# 故事库资源表与提示词通用规范（总纲）

> 本技能是资源表的**总纲**：尺寸规范、分段规则与 H3 语言规范对**所有**资源类型都适用，场景与视频类技能会引用它。各类型条目分散在技能 `stories-scene-video`、`stories-video-prompts`、`stories-audio-resources` 中。

## 画面术语定义（面/侧/边/视/词/缘）

六种术语全文档严格区分，严禁混用：

1. **面**：代表三维空间拍摄的具体画面（场景某一朝向的画面），共**九方位**：前面（正面）、前右、右面、右后、后面、后左、左面、左前、全图（四个正方向 + 四个斜方向 + 全景俯瞰）；场景类列名与提示词内容中的「面」一律指被描述的画面朝向
2. **侧**：代表摄像机在哪侧，**永远与面相对**：左侧相机拍摄的是右面，右侧相机拍摄的是左面，后侧相机拍摄的是前面，前侧相机拍摄的是后面；斜向同理——左前侧相机拍摄的是右后面，右后侧相机拍摄的是左前面，后左侧相机拍摄的是前右面，前右侧相机拍摄的是后左面；上下同理（上侧相机拍摄的是下面，下侧相机拍摄的是上面）
3. **边**：代表一个场景画面九宫格的哪一边（方位格），例如 左边在中间的左边，右上在中间的右边的上边
4. **视**：与场景无关，只与万物有关；万物类画面（**人物、生物、物品一律**）统一采用三视图（横向并排三个视角，**左边是正面、中间是侧面、右边是后面**）；不是九宫格
5. **词**：仅分 正词 与 负词；资源表提示词列后缀一律写 -正词 / -负词，词名中不得出现「面」字（避免与画面的面冲突）；提示词正文中出现的「面」指画面的面（如旋镜提示词「右面是…」）
6. **缘**：代表**画面边缘**，共八处——左缘、左上缘、上缘、右上缘、右缘、右下缘、下缘、左下缘（**四缘** = 左缘 / 上缘 / 右缘 / 下缘，四角缘 = 左上缘 / 右上缘 / 右下缘 / 左下缘）；**只与画面变化（运镜）有关，与场景方位无关**，专门用来描述视频画面里元素的**进出方向与进出快慢**（不是场景的边、不是九宫格方位格的「边」，也不与万物三视图的「视」混用）。判据（2026-10-08 定，方向口径与 `stories-scene-video` 的「12 秒八镜 360° 旋镜定式」一致）：
   - **一进一出定旋转**：画面内容从**右缘进入、左缘移出**（地平线保持水平）＝镜头**顺时针旋转**（pan right）；反向从**左缘进入、右缘移出**＝**逆时针旋转**（pan left）；从**上缘进入、下缘移出**＝镜头**上仰**（tilt up），从**下缘进入、上缘移出**＝**下俯**（tilt down）
   - **四缘同进 = 拉镜**：元素从四面边缘同时向画面中心进入（画面范围变大、视点后退）＝**拉镜头**；**四缘同出 = 推镜**：元素从画面中心向四面边缘移出（画面范围变小、视点前进）＝**推镜头**
   - **一侧快一侧慢 = 侧拉镜**：两侧缘进出速度不等（如左缘移出快、右缘进入慢）＝**侧拉镜**（拉镜叠加横移 / 斜向拉镜）；上下两缘速度不等则为上下斜拉
   - **有无视差是分水岭**：缘上内容有进出、透视关系不变（只是视线被扫过）＝角运动（pan / tilt）；四缘同进同出但**前后景无视差**＝光学变焦（zoom）；**有视差**＝物理推拉（dolly in / out）
   - 写入提示词时直接点名缘即可（如「右侧内容自画幅右缘进入、向画幅左缘移出」「四面内容同时向画幅中心汇聚进入」），**镜头术语仍取英文**（见「H3 提示词语言规范」）

### 图片提示词书写顺序规范

万物建模、万物变化、场景首帧、场景拉镜、场景推镜 的提示词，除遵循各自类型的专属要求外，还必须严格按照以下顺序书写：

1. **整体图片品质**：描述整图画质、清晰度、精细度、光影氛围、环境背景等整体视觉表现
2. **图片元素万物**：列出画面中出现的所有元素与万物（人物、器物、场景物体、生物、道具、自然景物等）
3. **图片风格要求**：写明整体艺术风格。**本故事库所有生图类资源（万物建模、万物变化、场景首帧/拉镜/推镜/旋镜）默认统一采用「写实三维CG风格」**：次世代三维渲染质感，立体体积感明确，真实材质与皮肤纹理（保留毛孔与细微纹理，不做平涂磨皮），影棚级立体布光与自然明暗过渡。⚠️ **2026-09-22 起整体改写实三维CG**（旧规范为「国漫CG风格」且严禁"写实"字样，已废止）：实测国漫CG 正词叠加负词里的 `写实摄影`/`实拍照片` 会把画面压成 2D 动漫平涂脸，故**负词里严禁再出现 `写实摄影`/`实拍照片`**，要压制的是 `二维动漫`/`二次元平涂`/`卡通渲染`/`赛璐璐上色`/`塑料感皮肤`/`过度磨皮`。注意「不向纯白背景投射阴影」≠「主体没有立体光影」，主体自身必须有体积与明暗过渡

三段顺序不可颠倒，缺失任一段视为不合格。

#### 提示词内容分段规则（通用，两类生图提示词共同遵守）

- **段分隔符统一**：提示词的所有分段点一律用 `<br>` 分隔（每个分段点一个 `<br>`，置于段末），段内属性用全角逗号 `，` 分隔，全文不使用句号；严禁使用换行符（真实回车 / 换行字符）或 `
`（反斜杠 n 两字符）作为分段符——md 表格单元格内的换行会被解析为新行从而断开表格，只有 `<br>` 能在单元格内安全分段；冒号仅用于点名词句（如万物类的 `主体：`），同一条目内要么全用要么全不用，保持一致。⚠️ **注意与 Qwen-Image 2.1 官方规范的冲突**：官方要求送进模型的提示词是**单段连续文本、禁任何换行**（[system_prompt_edit.txt](refs/Qwen-Image-2.1/prompt_rewrite/prompts/system_prompt_edit.txt) L186）。两者不矛盾但需两步走——**表内保留 `<br>` 以保表格结构，`<br>` 在送模型前合成单段**；现状是带着 `<br>` 直接送模型，属已知偏差。详见技能 `qwen-image-2-1-prompting`
- **一段一职责**：每段只写一类信息（整图品质 / 一个显示区域 / 一个方位格 / 风格），不跨段混写
- **段头点名词**：每段以点名词开头（如 `主体：`、`左上…`、`右面是`、`整体是…`、`写实三维CG风格`），点名词即段边界
- **一个元素只归一段**：不得在不同段重复堆叠同一元素
- **风格词只在最后一段**出现（`写实三维CG风格，…` 收尾），严禁散入品质段与区域段
- **`整体是…` 总结段全文仅一处**，紧跟区域段之后
- **段序固定**，不可颠倒，缺段视为不合格

两类提示词的分段维度不同，各自按以下规则执行：

#### 万物类分段规范（一律按三视图分段）

万物建模、万物变化 的画面**一律是三视图**（人物、生物、物品无例外，2026-10-07 改回）：横向并排正面/侧面/后面三个视角，**左正、中侧、右后**，**不使用九宫格**、不使用特写分区。段序：

1. **品质段**：画质描述 + 纯白背景硬句（#FFFFFF，无环境、无场景、**不向背景投射阴影**；「不投影到背景」不等于「主体没有立体光影」，主体自身必须写明体积与明暗过渡，见各自类型规范）
2. **布局声明段**：点明画面构成与取景（物品：`物品三视图并排展示，左边是正面、中间是侧面、右边是后面，三个视角为同一件物品、造型尺寸完全一致、均完整入画`；人物：`人物三视图并排展示，左边是正面、中间是侧面、右边是后面，三个视角为同一个人、体型与造型尺寸完全一致、均完整入画`；生物：`全身三视图并排展示，左边是正面、中间是侧面、右边是后面，三个视角为同一只生物、体型与造型尺寸完全一致、均完整入画`）
3. **主体段**：`主体：` 开头，**逐视角/逐区域分段**写各区域各自可见的形态特征（外形轮廓、结构组成、材质质感、颜色配色、纹样装饰、配件部件）；**与各区域无关的共同特征**（材质、配色、风格等）只写一次、不按区域重复
4. **总结段**：`整体是…`（全文仅一次）
5. **风格段**：`写实三维CG风格，…` 收尾

点名词体系：**主体**（画面各区域的共同主体）+ **视/区域**。`主体：` 只与万物有关，**严禁出现在场景类提示词中**；万物类物品/生物**必须写出三视字样**（`三视图`，生物写 `全身三视图`、物品写 `物品三视图`）与三个视的方位（`正面`/`侧面`/`后面`），但**严禁使用特写分区**（`左边特写`）与九宫格方位格（`左上`/`中间格`等）；`正面/侧面/后面` 三个视与场景类的九方位面（`前右`/`右面`/`后面`）是**不同体系**，万物类只用前者。万物类**三类对象（人物/生物/物品）都必须写出三视字样**（人物写 `人物三视图`、生物写 `全身三视图`、物品写 `物品三视图`），且都**必须按 左正 / 中侧 / 右后 的顺序逐视描述**（方位词只写在提示词里，**绝不出现在画面里**）。
万物变化段序：`以图1为底，保持原构图不变` 起头 → 主体修改段（`主体：` 开头，写改后的新外观）→ 风格段。

#### 场景类分段规范（按九宫格方位格分段）

场景首帧、场景拉镜、场景推镜、场景旋镜 的画面按**九宫格方位格**分段（见「场景图片生成 九宫格画面描述要求」）。段序：

1. **品质段**：画质 + 光影氛围描述（场景自带环境，无纯白背景要求）
2. **方位格段**：按固定顺序逐格一段——16:9 横版按 `左上…` → `左边…` → `左下…` → `上边…` → `中间…` → `下边…` → `右上…` → `右边…` → `右下…`；9:16 竖版按 `上左…` → `上边…` → `上右…` → `左边…` → `中间…` → `右边…` → `下左…` → `下边…` → `下右…`；每格段以该格方位词（边词）开头，无内容的格可略过
3. **风格段**：`写实三维CG风格，…` 收尾

点名词体系：**边词**（九宫格方位格），与万物类的 `主体：` 点名词互斥——场景类提示词中**严禁出现万物类的 `主体：` 点名词、三视图与特写分区**（`三视图`、`全身三视图`、`物品三视图`、`左边特写`）。⚠️ 场景类**允许**用 `正面`/`侧面`/`后面` 等方位词（它们属九方位面体系），但**不得**写成三视图并排结构。
- **场景推镜**：单帧非九宫格，不划分方位格段，仅用区域方位词描述画面内各区域的内容分布

### 生图类尺寸规范

| 用途 | 宽度×高度 | 说明 |
| :--- | :--- | :--- |
| 万物建模、万物变化（全部对象：人物、生物、物品，不分形态） | **832×480** | 固定横屏档；三视图要把三个视角并排放下，画面必须**横向**；三个视角各占约 1/3 宽（单个约 277 像素宽） |

- **不分档**：人物、生物、物品一律 **832×480**，不按对象固有形态另选比例
- 宽度/高度两列必须成对填写 **832** 与 **480**，不得自行拼凑比例
- ✅ 每轴均为 32 的倍数（832 = 26×32，480 = 15×32），满足 VAE 8×8 下采样对齐
- ⚠️ **代价说明**：832×480 下单个视角仅约 277 像素宽（26 个 token），**三视图的立绘分辨率偏低**，细节与人脸辨识度受限；这是为固定档位与速度付出的代价，若某一行确实需要更高细节，可临时上调到 **1664×960**（同 26:15 比例、约 4 倍面积，每轴仍为 32 倍数）——但**默认档仍是 832×480**
- **档位选择**（2026-10-02 定）：默认短边 1088 ≈2.09MP；要更高细节可升 Qwen-Image 2.1 官方 2K 档——竖屏 1536×2752 / 横屏 2752×1536 / 正方 2048×2048（≈4.2MP，**实测生成明显更慢**，8G 显卡另有 OOM 风险）；显存/速度再紧则降旧 768 档——竖屏 768×1344 / 横屏 1344×768 / 正方 768×768（≈1MP），或再降 480×832 / 832×480（0.4MP）；高清统一走 4x 外部放大 + 分块重绘
- 像素保持 32 的倍数（VAE 8×8 下采样对齐）；三档比例与 H3 视频桶（9:16 = 768×1344）相差不到 1%，进首帧视频/首帧场景时由模型自动重采样，无需人为改小

**场景首帧**（场景类，不属于万物）的宽度/高度统一填写 **16:9 = 1920×1088**（短边 1088 档，≈2.09MP；2026-10-02 由 1344×768 上调，同日因 2K 档生成太慢而由 2752×1536 下调）。进首帧视频/首帧场景时，模型会把首帧自动重采样到视频目标 canvas（如 832×480），无需人为改小。需要其他比例时，从本节 1088 档改比例、或从 Qwen-Image 2.1 官方 2K 档、H3 合法桶选取（见「视频类尺寸规范」）；追求细节可升 2K 档 2752×1536，显存不足降回 1344×768。

### 视频类尺寸规范（MiniMax H3）

视频类资源（文生场景、首帧场景、文生视频、首帧视频、首尾视频、关键帧视频、参考视频）的宽度/高度按 MiniMax H3 官方 canvas 规则填写：

- H3 固定 **24fps**（模型架构常量：表内**不设「视频帧率」列**，工作流的帧数换算一律写死 ×24，输出容器帧率亦恒为 24；要变速/补帧另用 `FallingTSFrameRateConvert` 节点）；视频秒数按需求填 5~15 秒（官方训练域）
- canvas 硬规则：**短边 ≤ 768**、**面积 ≤ 768×1344（≈1.03MP）**、每轴为 **32 的倍数**；宽度/高度直接决定生成尺寸，超限不会被自动纠正
- 默认统一 16:9 = **832×480**（480p 低显存档，0.4MP，官方原生工作流默认，适配 8G 显卡）
- 显存充足（16G+）可升档 16:9 = **1344×768**（768p 官方主推档，与 turbo 4 步 LoRA 训练域一致）
- 其余比例合法桶：21:9 = 1536×672、3:2 = 1152×768、4:3 = 1024×768、1:1 = 768×768、3:4 = 768×1024、2:3 = 768×1152、9:16 = 768×1344、9:21 = 672×1536
- 低显存/加速档 9:16 = **480×832**
- **严禁使用 1664×928 等生图桶值**：面积 1.54MP 超出 H3 上限约 50%，属分布外，易质量崩坏；2K 需另行二采放大（SeedVR2 / RTX VSR），不在宽度/高度列表达

### H3 提示词语言规范（视频类资源通用）

> **2026-09-25 用户决定：提示词正文改中文，H3 关键标识保持英文。** 下表是唯一语言口径。正文（画面、运镜、光影、动作、声音、剧情的描述句）写中文，便于作者读写与维护；凡是**模型要照抄的骨架**——字段名、`<Picture N>`/`<Subject N>` 一类标签、retention 枚举、方括号任务前缀、`[Shot N]` 与紧邻时间戳、官方对齐指令整句——一律保持英文。`stories\七纹刻印\` 下 9 个含提示词的资源表已按此口径改写完毕，对应 9 个工作流的 mdtable 快照同步刷新。

**写进资源表的提示词正文一律中文**，只有对白/歌词与画面内实际可见的文字保留原语言；**骨架与镜头语言术语保持英文**。

为什么上一版写的是英文（现降级为**已知代价**，不推翻）：H3 官方提示词技能（`h3-prompt-writing`）与官方模板（`templates\视频\api_minimax_h3_max_r2v.json` 等）的示例 prompt 全为英文；官方 HF 仓库讨论 #32 中经官方人员编辑的答复为「除需要生成的文字和对白内容，其他都要用英文描述」；官方模型卡载明 H3-Encoder 取 **Qwen3-VL-32B 第 50 层隐状态**送进 H3-Omni-Transformer，生成主干是在英文条件上训练的，故中文条件落在分布外。本机 `qwen3vl_32b_minimax_h3_nvfp4_awq` 是 **4-bit** 量化编码器，多语言基准实测长提示词的词义错乱率为**英文 1.8 / 100 词、中文 3.1 / 100 词**（中文额外损失约 1.7 倍）——长提示词用英文可同时规避「条件分布外」与「量化损失」两笔代价。这些代价**不因改用中文而消失**，只转为可接受成本；实测数字与唯一的有效回退杠杆见本节末「已知代价」。

**骨架必须逐字照抄（译错即失效）**：`<d>` 与 `</d>` 不是普通文字，而是 tokenizer 里的**扩展 special token**（本机 `ComfyUI\comfy\text_encoders\minimax.py` 中 id 为 **151669 / 151670**；同批还有 `<|cutoff|>`=151671、`<|lyrics_start|>`=151672、`<|lyrics_end|>`=151673、`<|caption_start|>`=151674、`<|caption_end|>`=151675，全部在基础词表 0..151668 之外）。译成 `<对话>` 只会被切成两个普通 token，指令直接失效；整枚标签**连同数字与空格一并照抄**（`<Picture 1>`，不是 `<Picture1>`、不是 `<图片 1>`）。字段名（`subject_definitions:` 等）、retention 枚举（`fully_preserved` 等）、任务前缀（`[reference generation]`）、`[Shot N]`、时间戳、`(S1)` 同理，全部属于骨架。

- **`<d>` 内只放两样东西**：英文语言名标签 + **用户原始说话内容**（官方 `base-en.txt`：`Inside <d>, include only the language tag and the actual user-provided spoken content`）。说话人身份、音色、语气、语速、动作一律写在 `<d>` **之外**；`<d>` 内的对白逐字保留、不翻译不改写。
- **`<d>` 内标点**：只用普通的 `,` `.` `?` `!`，且在 `</d>` 之前收尾；不写全角标点、不写省略号。
- **引用参考音频的原词**：保留原语言逐字；听不清的片段写 `[unclear]`，不得猜写。

**本文档各节的规范说明与示例用中文书写是为便于阅读；填进资源表的提示词正文一律中文，骨架与镜头语言术语仍英文。** 各类对齐指令是**官方固定句、属骨架**，一律逐字照抄英文（不翻译）：

- I2VA 首行：`For the target video, at 0.00 seconds into the target video, <Picture 1> (from [Shot 1]) is fully referenced.`
- FL2VA 首行：`Reference image alignment with the target video - Picture 1 (from [Shot 1]) aligns with the 0.00-second position of the target video; Picture 2 (from [Shot N]) aligns with the S.SS-second position of the target video.`
- 关键帧锚定：`[Shot N] At S.SS, anchored to the frame established by <Picture N>.`

**改写后的自检口径（2026-09-25 用 9 个表实测）**：中文正文字符数 ≈ 原英文字母数的 **0.23 ~ 0.33**（汉字本身约 0.21~0.27）。逐段（按 `<br>` 切）比长度比，**任一段低于 0.18 就要人工看**——那是漏译或压缩的信号；同时必须回验骨架 token 计数**逐项相等**（字段名 / `<Picture N>` / `<Subject N>` / `[Shot N]` / retention 枚举 / 任务前缀 / `At S.SS` / `<d>` / `(S1)`）与 `<br>` 数不变。这两条一起卡，才能既中文化又不破坏 H3 骨架。

### 万物建模

即文生图并优化图片，包含ID，主-正词(TEXT)，主-负词(TEXT)，宽度(INT)，高度(INT)，图2(IMAGE)，图3(IMAGE)，优化-正词(TEXT)，优化-负词(TEXT)

**画面一律采用三视图**（2026-10-07：**人物、生物、物品全部适用**，人物不另设版式）：横向并排三个视角，**左边是正面、中间是侧面、右边是后面**。三视图是**同一个主体**的三个方向——造型、体型、尺寸、比例、配色、材质必须**完全一致**，只是朝向不同；不是三个不同对象，也不是三张不同设计。**不划分特写分区、不使用九宫格。**

万物只在正文中**第一次出现**时才建立建模条目（记录其首次外观与设定），后续不重复建。

- **全部对象（人物、生物、物品，不分形态）** → **832×480**（固定横屏档，见「生图类尺寸规范」）

提示词中必须**按 左正 / 中侧 / 右后 的固定顺序逐视写出**各自要表现的外观特征（外形轮廓、结构组成、材质质感、颜色配色、纹样装饰、配件部件）；材质、配色等**跨视角共通的特征只写一次**。**必须写出三视字样**（人物写 `人物三视图`、生物写 `全身三视图`、物品写 `物品三视图`）与三个视的方位（`正面`/`侧面`/`后面`）；**严禁使用特写分区**（`左边特写`）与九宫格方位格（`左上`/`中间格`）。

**人物行的专门要求（2026-10-07 起，必须写足）**：既然回到三视图，人物行的**服装与体型就在 0011 里定死**，不再推给 0013。

- **取景**：三个视角都是**从头到脚的完整全身**，头顶到脚底全部入画、不裁切；与物品/生物不同，人物**必须写出这一身衣着**（款式、颜色、材质、纹样、配饰、鞋履）——三视图正是为了锁服装与体型在三个朝向下不漂移
- **姿态统一**：三个视角必须是**同一个中性站姿**——双脚并拢或与肩同宽、双手自然垂在身侧、身姿笔直；不得出现走动、跨步、手势、回头或任何动作，三个视角的姿态差异只能是朝向本身
- **侧面/背面的可读性**：侧面必须交代鼻梁、下颌线、后脑发型的真实轮廓；背面必须交代后脑发型、肩背、腰臀与双腿后侧的服装结构（如衣摆开衩、鞋跟、腰带扣等背面才可见的细节），**严禁背面与正面长得一样**（这是三视图最常见的失败）
- **三视一致**：三个视角是同一个人，身高、头身比、肩宽、腿长、肤色、发型、发色、服装款式与配色**必须逐项一致**；正面写了什么，侧面与背面要对应地写出来

**三视图内部规则**（三视并排的硬约束）：

**背景硬性要求：画面背景必须完全纯净的纯白色（#FFFFFF），无任何环境、地面、光影、纹理与装饰元素；主体独立悬浮在纯白背景上，不投射阴影、不带任何场景。**

- **三等分布局**：三个视角横向**大致三等分**排列、间距均匀、各自居中，不重叠、不切边
- **无标注**：**不要**在视角之间加箭头、标签、中文/英文标注或分隔线（`正面`/`侧面`/`后面` 等文字**不出现在画面里**），也不要把三视做成拼贴相框
- **宽度/高度**：832×480（固定横屏档）。⚠️ **不要把像素尺寸写进提示词**，比例与分辨率只走宽度/高度字段

**按对象类型的三视字样与取景**：

| 对象 | 三视字样 | 取景 |
| :--- | :--- | :--- |
| **人物** | `人物三视图` | 全身（头顶到脚底）+ **服装、鞋履、配饰一应写足**，中性站姿，侧面/背面结构必须交代 |
| **生物/怪物** | `全身三视图` | 全身完整入画，含尾部/翼/触须等附肢 |
| **物品** | `物品三视图` | 按固有形态完整入画，造型尺寸三视一致 |

**负词（人物行）**：

- 通用：低质量, 模糊, 变形, 解剖错误, 二维动漫, 二次元平涂, 卡通渲染, 赛璐璐上色, 平面插画, 塑料感皮肤, 过度磨皮, 蜡像感, 硅胶质感, 网红脸, 尖下巴, 大眼, 浓妆

**背景硬性要求：变化后画面背景必须保持完全纯净的纯白色（#FFFFFF），无任何环境、地面、光影、纹理与装饰元素；主体独立悬浮在纯白背景上，不投射阴影、不带任何场景。**

变化以原图为底，必须**保留画面构图**：

1. **构图不变**：保持原图的三视图构图（人物/生物/物品一律如此）——三个视角的**位置、大小、视角（**左边是正面、中间是侧面、右边是后面**的排布与朝向）与四周留白全部不动**，不新增显示区域、不增删视角、不改成单视角、不加特写
2. **主体外观修改**：按需求改变主体的材质、纹路、配色、氛围等外观表现，逐条描述改后的新外观
3. **整体统一**：主体各部分（各部件、各区域）修改后风格必须完全统一，不得出现相互矛盾或风格割裂

提示词中必须写明"保持原构图不变"；逐条描述主体改后的新外观并强调整体统一；**改后三个视角必须仍与原图三视图构图一致**（左正/中侧/右后、位置大小朝向不变），且**改后的外观在三个视角间保持统一**（正面改了什么，侧面与背面要对应地改，不能只改正面）。**必须写出 `三视图` 字样**（人物写 `人物三视图`、生物写 `全身三视图`、物品写 `物品三视图`）；**严禁使用特写分区**（`左边特写`）与九宫格方位格。

#### Qwen-Image-Edit 提示写法（图片修改通用）

万物变化走 Qwen-Image-Edit 多图参考编辑，提示词写作要点：

1. **图号引用**：提示词里用 `图1` / `图2` / `图3`（中文工作流通行）或 `Picture 1/2/3`（正规标签）指代各张输入图，三图顺序对应 图1/图2/图3，接错顺序等于指错图。⚠️ **Qwen-Image 2.1 官方规范强制要求多图用 `<image1>`/`<image2>`**，明文禁止 `图1` 这类自然语言引用（[官方 system_prompt_edit.txt](refs/Qwen-Image-2.1/prompt_rewrite/prompts/system_prompt_edit.txt) L59：*mandatory and non-negotiable*）。实测 `00120_万物变化_QI2.1` 的 mdtable 槽位严格一一对应（`图1`=槽3→`images.image_1`），**改成 `<imageN>` 是纯文本改动、无需重接工作流**。写法与诊断见技能 `qwen-image-2-1-prompting`
2. **surgical 指令**：指令只描述"改什么"（surgical instruction），别说长篇大论；文字编辑把目标文字用引号括起
3. **底图与参考**：以某张图为底、其余做参考时，目标图接在 图1（image1），参考图接 图2/图3（image2/image3）
4. **负提示词**：原生 Qwen-Image-Edit 负提示词支持有限，留空或单空格即可
5. **不要手写** `<|vision_start|><|image_pad|><|vision_end|>`：节点自动前缀，手写会破坏模板

### 场景图片生成 九宫格画面描述要求（场景首帧 / 场景拉镜 / 场景推镜 / 场景旋镜 通用）

场景类图片生成的提示词，必须把画面按**横向、纵向各三等分**划分为**九宫格**，并逐格点名每格内出现的元素与布局（场景方位、物件、灯光、细节），使画面各区域有明确交代、不随场。

描述顺序按画面宽高比分为 **16:9** 与 **9:16** 两种，按生图的宽度/高度选用对应顺序：

**16:9（横版）**：按 **左边 → 中间 → 右边** 描述。
- 左边：按 **左上 → 左边 → 左下** 描述；
- 中间：按 **上边 → 中间 → 下边** 描述；
- 右边：按 **右上 → 右边 → 右下** 描述。

**9:16（竖版）**：按 **上边 → 中间 → 下边** 描述。
- 上边：按 **上左 → 上边 → 上右** 描述；
- 中间：按 **左边 → 中间 → 右边** 描述；
- 下边：按 **下左 → 下边 → 下右** 描述。

每格用方位词开头点名（如"中间是…""左上…"），说明该处放的物件或留空；没有内容的格可略过，但任一元素只归入其所处的那一格，不得在不同格重复堆叠。

九宫格与场景本身的空间布局（前后左右、物件相互位置关系，见技能 `stories-scene-video` 的「场景类公共要求」）要互相印证统一：中间格通常为核心主体/主光区，四边交代墙面/地平/边缘，四角补足角部朝向的底景与照明。

## 表格 md 文件规范说明

所有表格 md 文件的第一列永远是 ID

后续字段完全按照 标题(类型) 定义

(类型) 不填写默认是 (STRING)

(类型) 包含如下内容和说明:

- (IMAGE)/(VIDEO)/(AUDIO)/(MASK)/(STRING)/(INT)/(FLOAT)/(BOOLEAN)：对应 ComfyUI 同名输出类型
- (TEXT)：对应 ComfyUI 的 STRING 输出类型，但自定义节点渲染为多行文本框

实际使用情况（扫描 `stories/` 下全部含表格 md 文件）：显式声明过的只有 `TEXT`、`IMAGE`、`INT`、`VIDEO`、`AUDIO`、`FLOAT`、`MASK` 七种；`STRING` 从未显式书写（各资源表的 ID 列等一律靠省略默认）；`BOOLEAN` 已登记但尚无一处使用。

各类型的字段定义（ID + 各字段(类型)）见对应类型的技能（`stories-resource-tables` 的图片类、`stories-scene-video` 的场景类、`stories-video-prompts` 的视频类、`stories-audio-resources` 的音频类）；ID 命名规则见 `stories/AGENTS.md` 的「资源 ID 规则」。

### 全图方位

**全图**是第九个方位，代表从场景**正上方垂直向下俯瞰**的全景画面（顶视/Bird's Eye），是八面水平方位之外的垂直维度补充。

- **含义**：全图不是某一朝向的画面，而是俯瞰整个场景的鸟瞰平面图——能看到场景中所有物件、地面、边界与空间关系的完整布局
- **用途**：场景类资源描述场景空间时，除八面水平方位外，还应提供全图方位的整体俯瞰描述，使模型从二维平面理解整个场景的空间结构与物件分布
- **描述要求**：全图方位的描述按俯视平面图的方位词逐区域点名（如「上方是…」「下方是…」「左侧是…」「右侧是…」「中央是…」），与八面水平方位描述交叉印证
- **与其他方位的关系**：全图方位是八面水平方位的上层概览——八面描述的是"站在某个方向往另一个方向看"，全图描述的是"从天上看下来"；两者互补而非替代

### 建模链（0013 首图建模 / 0014 参考建模 / 0015 建模截帧）

**为什么有这条链**：静态资产板只能锁住一两个景别。要让**跨全部景别**（特写 / 近景 / 中景 / 全景）的脸部一致，
唯一可靠办法是让脸在**同一段视频里逐帧同生** —— 视频内部天然同源同生，
因此「H3 视频 → 抽帧 → 反推人物资产」是唯一能覆盖全部景别的路线。
