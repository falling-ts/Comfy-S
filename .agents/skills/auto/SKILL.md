# auto — 正文区间 → 成片(全自动编排)

> **职责**: 用户只给「**哪个故事库**」+「**正文哪几行**」, 本技能负责把这段内容变成落盘的视频产物。
> **不负责**: 提示词写法本身(加载 `stories` 技能)、单个工作流的 JSON→API 机制
> (加载 `comfyui-workflow-runner` / `comfyui-headless-control`)。

## 1. 输入契约

调用形如:

```
auto 技能: 七纹刻印, 正文 1-120 行, 分辨率 960*544
```

| 参数 | 说明 | 缺省/推断 |
|---|---|---|
| **故事库** | `stories/<库名>/` 的目录名。产物落 `media/<库名>/` | 只有一个故事库时取之; 多个则**必须问** |
| **正文区间** | `stories/<库名>/0000_正文.md` 的**行号区间**, 闭区间 `起-止`, 也接受单行 | 无缺省, **必须给** |
| **分辨率** | 形如 `960*544` / `960×544` / `960 544` / `960x544`, 也可写档位名「544p」 | **可选**。不给则**完全不干预** md 宽高列, 沿用各表现值 |

**分辨率口径**: 解析出 `(宽, 高)` 后, **凡本库 md 文件里有「宽度」「高度」列的表, 其目标行一律写这个值**
(§S0 有完整写入口径与档位映射)。这不是「只影响视频」—— `0011`/`0020` 等资产表同样被覆盖。
硬约束见 §3 第 4 条; 越界值**拒绝执行并报错**, 不静默截断。

**行号口径**: `0000_正文.md` 是「**一段一行**、段间以空行分隔」的纯文本, 因此
**行号 = 段落序号(含空行)**。第 1 行是文件首行的提示语(`提示：「」是人物心理话…`),
**不是剧情**, 区间应避开它。实测该文件 3656 行 / 1893 非空行 / 平均段长 50 字。

**行号会漂移**(续写会让后续段落整体后移), 所以:

- 解析区间时**同时记下首段与末段的前 20 字**作为锚点文本;
- 每次作业在运行账本里写 `{库名, 起止行, 首段锚点, 末段锚点, 正文文件 sha256}`;
- 二次作业若行号对不上锚点, **停下来问用户**, 不得凭行号硬猜。

**硬要求(来自根 `AGENTS.md`, 全文见该文件)** —— 每次作业都适用:

1. **MiniMax H3 加速 LoRA ↔ shift 配对表**: 换 LoRA **必须同步改 shift**。
   Ref2VA 恒 `12/3`; FL2VA 仅 **768p 系**是 `6/3`。**改 H3 工作流前必查**。
2. **数据流约定**: 产物目录优先取 **md 表文件名**(无表节点退回工作流名);
   跨表引用写 `@{<表文件名>/<ID>}`; QI2.1 版与 1.x 版**共用表 ⇒ 产物互相覆盖**。
3. **提示词否定句式禁令**(`stories/AGENTS.md`): 一律肯定句式, 唯一例外 `non_diegetic_music` 的 `N/A`。
4. **工作流布局六规范**(仅当确需改工作流 JSON 时): 输出在左输入在右、不重叠、边距 (50,100)px。
   ⚠️ 本技能**默认不改** `workflows/` 下的 JSON(§8)。
5. **三条本机铁律**: 中文思考输出; 改文件只用 `edit`/`write`; 校验脚本经 stdin 内联执行。

## 3. 铁律(违反即整轮失败)

1. **改文件只能用 `edit` / `write`**; 命令与脚本**只做只读校验与工作流提交**。
   校验脚本一律经 stdin 内联执行, 不落盘临时文件。
2. **提示词一律肯定句式**, 严禁否定词(`不/没/无/别/非/未/禁止/避免…`)。
   唯一例外是 `non_diegetic_music` 一栏的固定值 `N/A`。写完逐字自查。
3. **骨架英文、正文中文**: 字段名 / `<Subject N>` / `<Picture N>` / `[Shot N]` / 时间戳 /
   `fully_preserved` / `<d>[Chinese] …</d>` 等**逐字照抄英文**; 画面与运镜描述写中文。
4. **尺寸受 §1 分辨率参数统一管辖**: 给了分辨率 ⇒ **所有含宽高列的 md 表目标行都写它**;
   没给 ⇒ 沿用各表现值。硬约束 **短边 ≤768、面积 ≤1 032 192、每轴 32 的倍数**,
   越界**直接报错拒跑**, 绝不静默截断。合法三档: 480p `832×480` / 544p `960×544` / 768p `1344×768`
   (竖版把两数对调; 非三档但满足硬约束的值**同样合法**)。`0011`/`0020` 等生图类**独立定档**
   —— `0011`/`0012` 固定 **1920×1088**(编辑链 ×1, 产物即此尺寸), `0020` 等场景图按 S0 分辨率走。
5. **`<Picture N>` 的 N 是「非空参考图的连续排位」, 不是槽位号**。空槽是唯一的「不锚定」开关。
6. **无头提交前必须刷新 mdtable 状态并回读校验** —— `md` 改动**不会**自动进工作流;
   引用解析失败会**静默变 `None`**, 没有任何报错。
7. **一切产物必须遵守统一落盘规则**(详见 §6): **用 ID 规则命名 → 存进 output 下
   「md 表文件名」或「工作流名」子目录 → 文件名以 `0000x` 开头**, 与 md 数据 ID 规则一致。
   这条对**所有资源**成立: 资源图 / 参考图 / 音频 / 视频 / 场景视频 / 3D 产物。
8. **`0050`/`0051`/`0070` 没有数据表**, 不要为它们建表、也不要用 `@{...}` 引用它们的产物。

## 4. 编排顺序(用户指定的标准制作流程)

**核心**: **`0044_参考视频` 是唯一出片工作流**, 其余工作流全部为它**生产参考图**。
参考图分两路 —— **万物路**(人物/器物)与**场景路** —— 最后汇总进 0044 出片, 再抽帧复核迭代。

```
S0 分辨率统一 (给了分辨率才做: 扫全部 md 的宽高列 → 逐表改写目标行 → 校验硬约束)
      ↓
S1 区间解析
      ↓
S2 万物路   ① 0011_万物建模 或 00110_万物建模_QI2.1  → 三块版式大图 (产物尺寸 = md 宽高, ×1 直通)
            ② 0016_建模拆图  2×2 出 4 张 / 3×3 出 9 张 → 每格由下游 resize
      ↓
S3 场景路   ③ 0020_场景首帧 或 00200_场景首帧_QI2.1
            ④ 0031_首帧场景 → 360° 旋镜视频
            ⑤ 0035_场景截帧 或 ffmpeg 抽帧 → 八方位单帧 + _四图 / _八图
      ↓
S3.5 参考图质检  (逐张看图; 内容混乱/不一致 ⇒ 重生成, 不带病汇总)     ← 硬闸门
      ↓
S4 汇总出片  ⑥ 0044_参考视频  (参考图模式固定 match; 唯一出片路线)
      ↓
S5 音频推导  0060/0061/0062/0063/0064 (对白走 0063/0064, 环境走 0061)
      ↓
S6 无头执行  (按拓扑序; 每步 refresh → reset → **分辨率/LoRA/shift 覆盖** → submit → 轮询)
      ↓
S7 验证落盘  (PyAV 探针 + 抽帧拼图 + 账本追加; 核对产物分辨率 == 目标分辨率)
      ↓
S8 成片复核  ⑦ ffmpeg 抽关键帧看效果 → 不好则回改提示词/参考图 → 重跑 0044  ← 可迭代多轮
```

**顺序不可颠倒的硬原因**:

- **0011 是人物身份唯一上游** —— 脸必须来自它的高分辨率独立生成, **绝不从全身小图裁脸**;
- **0016 的输入就是 0011 的产物**, 0011 没跑完(闸门未放行)则拆图拿到的是未放大旧图;
- **0035 的输入就是 0031 的产物**(实测其加载节点写着 `0031_首帧场景/00001_书房旋镜.mp4`);
- **0044 的参考图来自 0016/0035 的既有产物**, 资产没落盘时其 `@{...}` 会**静默解析成 `None`**;
- **S3.5 质检必须在 S4 之前** —— 带病参考图汇总后问题会被 0044 放大,
  事后还无法从成片反推是哪张参考图的错。

**备用路线**(仅在需要时启用, 不替代上面的主线):
`0023_场景旋镜`(静态八方位视角图, 跳过 ④⑤)、
`0013_首图建模 → 0015_建模截帧 → 0014_参考建模`(人物特写锁脸迭代)、
`0017_建模细节`(逐块精修)、`0034_世界模型`(复用 0031 视频做 3DGS)。

阶段细节 → `references/pipeline.md`; 单个工作流的接线 → `references/workflows.md`。

## 5. 各阶段做什么

### S0 分辨率统一(仅当给了分辨率参数)

**这是本技能唯一会批量改写既有表的步骤**, 执行前必须说清改了什么。

1. **枚举目标表**: 扫 `stories/<库名>/*.md`, 取**首行表头**里同时含「宽度」与「高度」的表。
   实测本库共 **13 张**: `0011` `0013` `0014` `0020` `0030` `0031` `0032` `0033`
   `0040` `0041` `0042` `0043` `0044`。(`0012`/`0021`/`0022`/`0023`/`0034`/`0060`~`0064` **没有**宽高列, 不动。)
2. **写入口径**: 对每张表, 逐行把「宽度」列写 `宽`、「高度」列写 `高`。
   **只改这两列**, 其它列一个字符都不碰; 表头与分隔行不动。
   - **已存在的行**: 原地覆盖这两个格子。
   - **本次新建的行**(S2/S4/S5 写的): 直接按分辨率填, 不写 0 也不留空。
   - ⚠️ 用 `edit` 逐格改, 或对**整行**重写; 绝不用脚本批量替换 —— 见 §6 纪律。
3. **校验硬约束**(§3 第 4 条): 短边 ≤768、面积 ≤1 032 192、两轴均为 32 的倍数。
   **任一条不满足 ⇒ 立即停下报错, 不得改任何文件。**
4. **档位解析**(S6 覆盖用):

   | 你给的分辨率 | 档位 | H3 LoRA 谱系 | shift (video/audio) |
   |---|---|---|---|
   | `832×480`(短边 480) | 480p | 544p 系 LoRA **可用**(同量级低分档) | 见 S6 映射表 |
   | `960×544`(短边 544) | **544p** | 必须用 **544p 系** LoRA | `12/3` |
   | `1344×768`(短边 768) | 768p | 必须用 **768p 系** LoRA | Ref2VA `12/3`; **FL2VA `6/3`** |
   | 其它合法值 | 按短边归入最近档 | 短边 ≥768 归 768p, 否则归 544p | 同该档 |

5. **通知用户**: 列出「改了哪几张表、各几行、从什么值改到什么值」。
   若某表**本来就是这个值**, 明确说「无变化」, 不要假称改过。

> ⚠️ **光写 md 不够 —— 见 S6 的 selector 覆盖**。`0013`/`0014`/`0030`/`0033`/`0040`/`0041`/`0042`/`0043`
> 的宽高 `FallingTSSelector` 当前停在「横480」档, 该档**完全忽略 md 宽高列**。
> 不覆盖它, S0 写进 md 的分辨率会**静默失效**。

### S1 区间解析

1. `read` 正文文件的目标区间(`offset` / `limit`), 不整份加载。
2. 产出**叙事清单**: 按「时间线 → 地点 → 在场人物 → 器物 → 事件 → 对白/心理」逐段抽取。
3. 判定**场景切换点**与**人物首次出现**, 这是 S2 建行的依据。
4. 记锚点与 sha256(§1)。

### S2 万物路(基准生成 → 拆图取参考图)

路线: `① 0011_万物建模 / 00110_万物建模_QI2.1` → `② 0016_建模拆图`。
(两步的全局位置见 §4; 提示词规范见 `stories` 技能。)

**拆图倍数的精确含义**(2026-10-17 起): `0011` 的编辑链放大已由 **×3 改为 ×1**,
所以**产物尺寸 = md 宽高**(md `960×544` → 磁盘 `960×544`; md `1920×1088` → 磁盘 `1920×1088`)。
于是拆图的几何关系变成:

| 拆图方式 | 块数 | 每格尺寸(源 = md 宽高) | 用途 |
|---|---|---|---|
| **2×2** | 4 块 | `md宽/2 × md高/2` | 每格只有视频分辨率的一半, 会被下游上采样 |
| **3×3** | **9 块** | `md宽/3 × md高/3` | 每格约为 md 的 1/3, 需下游上采样 |

⇒ **「4 倍 / 9 倍」指的是拆出的参考图张数**(2×2 = 4 张 / 3×3 = 9 张),
**不再**是分辨率放大倍数。要拿到「与视频同分辨率」的参考图, 现在应当:
**直接让 md 宽高 = 3 × 视频分辨率**(如视频 `960×544` → md 写 `2880×1632`, 3×3 每格正好 `960×544`),
或者按 `stories` 技能的固定档 **`1920×1088`** 生成、再用 0016 拆图后由下游 resize。

> ⚠️ **旧口径已废止**: 曾经 0011 的 `LatentUpscaleBy` 为 `['bicubic', 3]`,
> 「源图放大 3 倍 × 拆 3×3 = 1 倍」这条推导**不再成立**。现值为 `['bicubic', 1]`(直通)。
> 本库 `0011_万物建模.md` 的固定档是 **1920×1088**, 比视频 `960×544` 每轴大约 2 倍,
> 拆 3×3 后每格 `640×363`, 下游会重采样; 需要逐格精确等于视频分辨率时按上面的公式反推 md 值。

#### S2 步骤

1. **基准工作流**: `0011_万物建模`(默认)或 `00110_万物建模_QI2.1`(Qwen-Image 2.1 底座)。
   ⚠️ 二者**共用 `0011_万物建模.md` 与产物目录**, 同 ID 产物**互相覆盖**(见 `workflows.md` §9)
   —— 选定一个就整段跑完, 不要混用。
2. `0011_万物建模.md` 写行: 人物/生物/物品, 纯白 `#FFFFFF` 背景; 宽高列**用 S0 的分辨率**。
   **人物行**按 `stories` 技能的新版式写: **左边是脸部特写(含头发/脖子/脖颈/衣服)、右上是人物三视图、右下是手部特写**,

### S3.5 参考图质检(汇总进 0044 之前**必须做**)

**在把参考图交给 0044 之前, 逐张肉眼查看**, 不合格就**重生成**, 绝不带病汇总:

| 检查项 | 不合格表现 | 处置 |
|---|---|---|
| **内容混乱** | 同一格出现多个人/多个物体、肢体粘连、视角错位 | **重跑该资产行** |
| **多视图一致性** | 三视图里三个视角不是同一人/同一物(脸型/服装/尺寸不一致) | 重跑 0011 该行, 强化提示词一致性描述 |
| **版式缺失** | 人物行缺左脸部特写或缺右下手部特写, 三块合并成一块, 分割线变成粗黑框 | 重跑 0011 该行, 强调「左脸部特写 + 右上三视图 + 右下手部特写、三块间 1px 黑线」 |
| **拆图错位** | 3×3 某格切到了相邻视角的半个身子(源图三视未均匀三等分) | 重跑 0011, 强调「右上三视区沿横向平均三等分、间距均匀」 |

| **场景方向错误** | 八方位顺序与实际朝向对不上 | 重跑 0031/0035 |
| **场景内容漂移** | 八方位帧之间墙面/家具位置跳变 | 重跑 0031, 提示词强调固定布局 |

### S4.5 提示词写法(Ref2VA 六段)

**一个叙事段落 → 一行、一段 5~15 秒的 H3 视频**。
默认路线是 `0044_参考视频`(本库既有 10 行全部是它, 且引用全链产物, 是唯一能覆盖跨景别
一致性的路线); 下列四个是**备用线**, 仅在叙事形态明确匹配时换用:

| 叙事形态 | 备用表 | 依据 |
|---|---|---|
| 无任何参考、纯描述 | `0040_文生视频` | T2VA 三字段, 无对齐指令 |
| 有明确首帧图 | `0041_首帧视频` | I2VA |

| 中间还要钉若干关键帧 | `0043_关键帧视频` | 最多 9 图 + 秒数列 |

提示词按 **Ref2VA 六段**固定顺序(参考视频与参考场景同结构):

```
subject_definitions: → summary: → retention_analysis: → detailed_description: → overall_soundscape: → non_diegetic_music:
```

- ⚠️ **散文定不住镜头顺序**(Ref2VA 的参考图没有时间位置)。时间码照写(仍是有效引导),
  但**默认不要上硬锚点** —— 实测「不加锚点效果更好」; 必须钉死时才用 `FallingTSH3AddGuide`。
- 对白写 `<d>[Chinese] 原句</d>`, 说话人 `(S1)` 置于 `<d>` **之外**, `<d>` 内只用 `, . ? !`。

换 LoRA **必须同步改 shift**(见根 `AGENTS.md` 配对表): Ref2VA 一律 `12/3`;
只有 FL2VA 的 **768p** 系是 `6/3`。shift 与分辨率档位无关, 只跟 LoRA 谱系绑定。

### S6 无头执行

对 DAG 里每个待跑工作流, 按拓扑序:

```bash
# ① 转换 + 刷新 mdtable + 分辨率/LoRA/shift 覆盖 + 提交(脚本自动轮询 /history)
python .agents/skills/comfyui-workflow-runner/scripts/workflow-to-prompt.py "0044_参考视频.json" \
    --refresh-md --resolution 960*544 --submit
```

⚠️ **`--resolution` 何时加**: 只要本次给了分辨率参数就**每个工作流都要加**, 一个都不能漏 ——
它同时干三件事(见 `references/pipeline.md` §5.1、§6.1):

1. 把宽高 `FallingTSSelector` 的 `selection` 覆盖成 `默认`, **否则 md 宽高被静默忽略**;
2. 按 `UNETLoader` 谱系(fl2va/ref2va)+ 短边档位**替换两个 LoRA**;
3. 按**替换后**的步数**同步 shift**(漏了不会有任何报错, 只会画面/音频结构性崩坏)。

脚本会在 stdout 逐条打印改了什么(`*` 开头); **空列表 = 该工作流本来就对, 无需改动**。

**每一步都要**:

1. **Run 前 reset**: `POST /preview-image/reset`、`/preview-video/reset`、`/preview-audio/reset`、
   `/audio-trim/reset` —— 无头不做的话执行缓存会跳过节点。
2. **强校验**: 每个 `@{...}` 必须能解析; 工作流快照 id 必须还在 md 里。任一失败**拒绝提交**。
3. **提交后回读校验**, 不能只信 200(很多端点字段名错也返 200)。
4. **产物保存**: `PreviewVideo`/`PreviewImageSave`/`PreviewAudioSave` 只写 `temp/`,
   要落 `output/` 必须**显式打保存端点**(端点表见 `comfyui-headless-control` §2)。
   ⚠️ `AutoSaveImage` 例外 —— 执行到即落盘, **没有按钮**, 但提交时要**自带工作流名**,
   否则产物落回 output 根。
5. **闸门**: `0011`/`0020`/`0021`/`0063` 含 `FallingTSContinue`;
   放行前先 `POST /free {"unload_models":true,"free_memory":true}`, 再
   `POST /proceed/continue/{id}`(未跑到该节点会 400)。
6. **服务重启即失**: 所有按钮状态都在模块级内存里, **跑完立刻操作**, 中间不要重启。
7. ⚠️ **`--resolution` 只改提交载荷, 不改磁盘上的工作流 JSON**(与 `--refresh-md` 同理)。
   这是有意的: `workflows/` 拓扑受 §8 保护。所以**下一次跑还得再传一次**。

### S7 验证落盘

**绝不只信「success」**:

- **探针用 PyAV, 不要用 `ffprobe`** —— ⚠️ **本机 `ffmpeg`/`ffprobe` 都不在 PATH 里**

  - **查分辨率/时长/帧数/音轨 → PyAV**(实测 18.1.0, 首选):

    ```python

    with av.open(path) as c:
        v = c.streams.video[0]
        print(v.codec_context.width, v.codec_context.height,
              float(v.average_rate), v.frames, float(c.duration)/1e6,
              len(c.streams.audio) > 0)
    ```

    ```python
    import imageio_ffmpeg
    FF = imageio_ffmpeg.get_ffmpeg_exe()
    ```

  - **动作幅度 → 别指望 `motion-profile.py`**, 直接用 PyAV 抽帧 + 相邻帧绝对差
    (`np.abs(np.diff(frames, axis=0)).mean()`; 实测正常镜头均值 13~14,
    而只看 `pblack` 会在 H3 颗粒下饱和)。

- **必须核对产物分辨率 == S0 的目标分辨率**(H3 输出应精确相等; `0011` 产物等于 md 宽高, 放大倍数为 ×1);
- 产物真实路径 = `media/<库名>/<表名>/<ID>.<ext>`;
- **追加**运行账本(路径 + 内容 sha256), **不要覆盖清空**。

## 6. ID 与产物落盘规则(全部资源统一)

> **总纲**: 一切产物 —— **资源图、参考图、音频、视频、场景视频、3D 产物** ——
> 都由插件节点落盘, **统一遵守一套规则**:
> **① 用 ID 规则命名; ② 存进 output 下「md 表文件名」或「工作流名」子目录;
> ③ 文件名以 `0000x` 开头, 与 md 数据 ID 规则完全一致。**

### 6.1 目录: output/<子目录>/ —— 子目录名二选一

插件的 `output_subdir.resolve_subdir` 决定子目录名(**实测源码**):

| 优先级 | 条件 | 子目录名 | 例 |
|---|---|---|---|
| 1(优先) | 工作流的 API prompt 里有 `FallingTSMarkDownTable` 节点 | **该表的 `md_path` 文件名(去 `.md`)** | `0011_万物建模` |
| 2(兜底) | 无 md 表节点 | **工作流名** | `0016_建模拆图` |

⇒ 这正是 `@{表名/ID}` **严格命中**能生效的原因: **表文件名 = 产物目录名**。
产物的绝对路径 = `media/<库名>/<子目录名>/<文件名>`(`media/` 是 `ComfyUI/output/` 的软链目标)。

⚠️ **QI2.1 变体与 1.x 版共用表 ⇒ 落同一目录, 同 ID 产物互相覆盖**(`workflows.md` §9)。

### 6.2 文件名: 必须以 `0000x` 开头, 与 md ID 规则一致

md 表的行 ID 规则(权威定义见 `stories/AGENTS.md`「资源 ID 规则」):

> **`编号_简短名` 两段**: 编号为 **5 位十进制**, **每张表独立从 `00001` 起连续递增**
> (只在本文件内唯一, 不跨文件连号); **中间插入**时编号末尾追加一位,
> 由 5 位升 6 位(`00001` → `000011`), 逐字排序仍落在两者之间。

**产物文件名沿用同一编号** —— 由插件的 `output_subdir.sequence_prefix` 实现:

```python
sequence_prefix(sequence, name)   # → "00005_夜雨"
# 序列号按 5 位补零(%05d); 空值/0/负数都按起始编号 1 处理(→ "00001")
# 名称为空时只给序列号, 不补下划线
```

**两条编号来源(实测 85 个保存节点全部溯源)**:

| 来源 | 数量 | 机制 |
|---|---|---|
| **mdtable 的 `ID` 槽(槽 0)** → 保存节点 `filename_prefix` | **42**(其中 10 个经 `Reroute` 中转) | 前缀 = 表内该行的 ID 原文 |
| **`FallingTSLoad*` 的 `prefix` 输出**(槽 2) | **42**(LoadVideo 26 / LoadImage 13 / LoadAudio 3) | 前缀 = `<序列号>_<名称>` |
| ⚠️ 硬编码(未接线) | **1**(`0034_世界模型` 的 `#3`) | 见下方例外 |

**共同点**: 无论走哪条, **文件名都以 `0000x_` 开头**。
mdtable 路线直接给出表内 ID(天然 `00001_陈落`); `Load*` 路线由「序列号 + 名称」拼出同格式。

> ⚠️ **实测例外 `0034_世界模型`**: 其 `PreviewImageSave`(`#3`)的 `filename_prefix`
> 是**硬编码** `'0034_世界模型_360长图'`, **不以 `0000x` 开头**。
> 这是本机唯一不合规的保存节点(`stories/AGENTS.md` 里其产物路径也写作
> `0034_世界模型/0034_世界模型_世界3DGS.ply`)。
> ⇒ auto 若要跑 `0034`, **应在 API 载荷层面把该前缀覆盖成该行 ID**(不改磁盘 JSON),
> 或明确告知用户该例外。

| 拆图参考图 | `0016` | `0011_万物建模/`(取表名) | `00001_陈落_中间.png` |
| 场景资产图 | `0020`/`00200` | `0020_场景首帧/` | `00001_书房.png` |
| 场景旋镜视频 | `0031` | `0031_首帧场景/` | `00001_书房旋镜.mp4` |
| 场景八方位帧 | `0035` | `0035_场景截帧/` | `00001_书房_前面.png` |
| 成片视频 | `0044` | `0044_参考视频/` | `00007_第四夜醒着.mp4` |
| 音频 | `0060`~`0064` | `0060_背景音乐/` 等 | `00001_夜雨.mp3` |
| 3D 产物 | `0034` | `0034_世界模型/` | ⚠️ 例外, 见 §6.2 |

**跨表引用**一律写 `@{<表文件名>/<ID>}`, 斜杠前那段**永远是表文件名(= 产物目录名)**,
斜杠后那段是 5 位行 ID。

### 6.4 写表纪律

- 只用 `edit` / `write` 改 md; 表**第一列永远是 ID**, 字段严格照表头 `标题(类型)`。
- **不新增列、不改列序** —— 列序与工作流 mdtable 的**位置式槽位**(`0`=ID, `1..9`=`<Picture 1..9>`,
  `10..12`=`<Video 1..3>`, `13..15`=`<Audio 1..3>`, `16`=提示词, `17`=宽, `18`=高, `19`=秒数)耦合。
- **新增行取本表当前最大编号 +1**, 不参考其它表的编号; 跨表引用写 `@{<表文件名>/<ID>}`。
- 无真实换行: 多段内容一律 `<br>` 连接, 否则整表解析错位。
- ⚠️ **改 ID = 改产物文件名** —— 保存节点的 `filename_prefix` 常被 mdtable 的 ID 覆盖
  (磁盘里写的 `preview`/`scene_video` 只是未连线时的兜底值)。

## 7. 失败处理

| 现象 | 真因 | 处置 |
|---|---|---|
| `@{...}` 静默变 `None` | 引用文件不存在 / ID 写错 | **提交前**逐条 `GET /fallingts_mdtable/resolve` 校验, 全部命中才跑 |
| 提交后产物没变 | md 改了但快照没刷新 | 必须 `--refresh-md`; 且注意它**不改磁盘上的工作流 JSON** |
| **改了 md 宽高但产物尺寸没变** | 宽高 `FallingTSSelector` 停在「横480」档, **忽略 md** | 提交必须带 `--resolution W*H`(§S0 第 4 条、§S6) |
| **产物画面/音频结构性崩坏** | LoRA 与 shift 档位不配对(换 LoRA 没改 shift) | 别手改; 让 `--resolution` 自动配对, 或查根 `AGENTS.md` 配对表 |
| 几秒就「跑完」 | 执行缓存命中, 根本没跑 | 换 seed 或改提示词 |
| 节点被跳过 | 没做 Run 前 reset | 补 `POST /preview-*/reset` |
| `Required input is missing` | 控件按位置对齐错位 | 按**名字**对齐控件; 动态子控件进 prompt 用扁平点号 |
| 端点返 200 但没生效 | 字段名错(如 `frame-remove` 要 `frame_index`) | **回读 state 校验** |
| `ffprobe: command not found` | 本机没装 ffmpeg/ffprobe | 改用 PyAV + `imageio_ffmpeg.get_ffmpeg_exe()`(§S7) |

## 8. 边界声明(与 stories/AGENTS.md 的关系)

`stories/AGENTS.md` 定的是「**写作会话**」的边界: 只改 md、不跑工作流、不改工作流 JSON。
**本技能是被显式调用的「出片会话」, 职责不同**:

- 用户调用 `auto` 本身即构成对「写哪些行」的**明确指示** —— 因此 §5 各阶段可以写入
  那些平时需要用户逐项点名的表(`0021`/`0023`/`0031`/`0032`/`0040`~`0043`/`0060`~`0064`)。
- 给了分辨率参数时, 该指示**同样覆盖「改宽高列」**: 用户要求的就是「所有表统一用这个分辨率」,
  因此 §S0 批量改写 13 张表的宽高列**属于授权范围**, 不算越权。**仍须逐表报告改了什么**。
- 本技能**允许无头运行工作流**(这是它与 `stories` 技能的核心差异)。
- **仍不允许**改动 `workflows/` 下的 JSON 拓扑与节点参数 —— 只允许**读取**它们来构造 API 载荷。
  ⚠️ 但**在 API 载荷层面覆盖 LoRA 与 shift 是允许的**(`--resolution` 的做法): 它不改磁盘、
  不违反本条款, 且是分辨率参数能正确生效的必要条件(见 §S6)。
  确需改**磁盘上的**工作流(如加硬锚点)时, **先备份到 `backups/`** 并**明确告知用户**。
- 一切内容仍受 `stories/AGENTS.md` 的**绝对限制**与**否定句式禁令**约束。

## 9. 交付

一次 `auto` 作业的完成物:

1. 上述资源表的新增行(改完**落盘**);
2. 若给了分辨率: **13 张含宽高列的表**已按该分辨率统一改写(§S0), 并向用户报告改了哪些表、各几行;
3. `media/<库名>/<表名>/` 下**已保存**的视频/图片/音频产物 —— 且**逐个核对落盘规则(§6)**:
   - 目录 = md 表文件名(无表节点才是工作流名);
   - 文件名**以 `0000x_` 开头**, 与表内 ID 一致;
   - ⚠️ 凡不符(如 `0034` 的硬编码前缀)必须**明确指出**, 不得默认合规;
4. 运行账本条目(含 prompt 全文、参考图 sha256、实际提交的 prompt 哈希、**本次分辨率**);
5. 一份**给用户看的简报**: 区间、分辨率(或「沿用各表现值」)、建了哪些资产、跑了哪些工作流、
   **LoRA/shift 是否被切档**(脚本 `*` 行)、产物清单与实测分辨率、抽帧拼图与判断、
   以及**下一段区间**的建议起点。

细节 → `references/pipeline.md`(工作流档案、DAG、阶段清单、执行模板)。
**单个工作流的职责、表头列、产物命名与引用网络 → `references/workflows.md`**。
**标准制作流程的每步操作与命令 → `references/production-flow.md`**。
