## 1. 万物路:资产 → 三视图 → 拆图

### 1.1 基准生成(二选一, 不混用)

| 工作流 | 底座 | md 表 | 产物目录 |
|---|---|---|---|
| **`0011_万物建模`**(默认) | `qwen_image_2512_fp8_e4m3fn_scaled_comfyui` + Edit-2511 fp8mixed | `0011_万物建模.md` | `media/<库>/0011_万物建模/` |
| `00110_万物建模_QI2.1` | `qwen_image_2.1_bf16` + Edit-2511 bf16 | **同上(共用)** | **同上(互相覆盖)** |

⚠️ **两者共用同一张表与同一个产物目录**, 同 ID 产物**互相覆盖**。
⇒ **选定一个就整段跑完**, 不要在同一个 ID 上混用; 需要对比时用不同的 ID。

**输入要求**: `0011_万物建模.md` 一行一个人物/器物, 提示词要求**一张图内并排三视图**:

- 人物: 左正面 / 中侧面 / 右后面, 同一人、同一套衣着, **头顶到脚底完整入画**,
  三者视平线一致、尺寸一致、水平大致三等分且间距均匀;
- 物品: 左正面 / 中侧面 / 右后面, 同一件器物, 造型尺寸一致;
- **背景必须纯净纯白** `#FFFFFF` —— 无环境、无地面、无纹理、无投影;
- 明确写「**文字标注、箭头与分隔线一律省略**」, 否则模型会画上不存在的标注。

**宽高列**用统一分辨率(S0); 实测本库现值 `960×544`。

### 1.2 放大链与闸门(关键)

该工作流是**两段式**, 中间有 `FallingTSContinue` 闸门:

```
主生成(KSampler) → VAEDecode → PreviewImageSave(主结果) → ★ FallingTSContinue
                                                                ↓ 点「继续」放行
                                              ImageScaleBy(lanczos) → LatentUpscaleBy(bicubic, 3)
                                                                ↓
                                                       Edit-2511 提画质 → PreviewImageSave(成品)
```

- **实测放大倍率恒为 3**(`LatentUpscaleBy` 的 `scale_by = 3`), 0011 与 00110 都是。
- ⇒ **md 写 `960×544` 时, 磁盘产物是 `2880×1632`**(每轴 ×3, 面积 ×9)。
- **无头执行必须放行闸门**, 否则只有未放大的主结果:
  `POST /free` 卸显存 → `POST /proceed/continue/{id}`(未跑到该节点会 400)。

### 1.3 拆图(`0016_建模拆图`)

**它不读 md 表** —— 输入是加载节点直接指向 0011 的产物:

```
#1 FallingTSLoadImage  = ['建模拆图', '0011_万物建模/00001_陈落.png', ...]  → 2×2 流程
#2 FallingTSLoadImage  = ['陈落',     '0011_万物建模/00001_陈落.png', ...]  → 3×3 流程
```

**两条完全独立的流**, 各由一个 `FallingTSRunGroup` 收口:

| RunGroup | 拆法 | 张数 | 保存节点 | 后缀 |
|---|---|---|---|---|
| `#1300` | `easy imageSplitGrid [2,2]` | **4** | `#1011~#1014` | `_左上` `_右上` `_左下` `_右下` |
| `#1301` | `easy imageSplitGrid [3,3]` | **9** | `#1031~#1039` | `_左上` `_上边` `_右上` `_左边` `_中间` `_右边` `_左下` `_下边` `_右下` |

- **运行方式**: 用「**▶ 运行本组**」(`FallingTSRunGroup`), **不要用「继续」**。
  实测只提交四宫组时 `/history` 的 outputs 仅 `1011..1014`, 九个九宫节点一个都没跑。
- **保存节点是 `AutoSaveImage`** —— 执行到即落盘, 没有「保存」按钮。
- **`filename_prefix` 接的是 `FallingTSLoadImage` 的 `prefix` 输出**(槽 2),
  所以产物名 = `<序列号>_<名称><后缀>`, 例: `00001_陈落_中间.png`。

### 1.4 「4 倍 / 9 倍」到底是什么(实测澄清)

⚠️ **不是「把图放大 4 倍」** —— 放大倍率恒为 **3**。
「4 倍 / 9 倍」指**拆出的参考图张数**: 2×2 = **4 张**、3×3 = **9 张**。

| 拆法 | 张数 | 每格尺寸(源 2880×1632) | 与视频分辨率(960×544)的关系 |
|---|---|---|---|
| 2×2 | 4 | `1440×816` | 每轴大 1.5 倍 → 下游会 resize |
| **3×3** | **9** | **`960×544`** | **精确相等** ✓ 首选 |

⇒ **要拿到「与视频同分辨率」的参考图, 必须用 3×3 拆图**。
——这正是「用建模拆图获得视频同分辨率的参考图」的机制:**源图放大 3 倍 × 拆 3×3 = 1 倍**。

## 2. 场景路:场景 → 旋镜视频 → 八方位帧

### 2.1 基准生成(二选一, 不混用)

| 工作流 | md 表 | 产物目录 | 放大 |
|---|---|---|---|
| **`0020_场景首帧`**(默认) | `0020_场景首帧.md` | `media/<库>/0020_场景首帧/` | `LatentUpscaleBy(bicubic, 3)` / `ImageScaleBy(lanczos, 2)` |
| `00200_场景首帧_QI2.1` | **同上(共用)** | **同上(互相覆盖)** | `LatentUpscaleBy(bilinear, 1)` |

**输入要求**: 每个新场景一行, **九宫格逐格描述**(左上/上边/右上/左边/中间/右边/左下/下边/右下)
+ 全图俯瞰。实测产物分辨率**等于** md 值(`960×544`, 无放大)。

⚠️ **共用表共用目录**, 同 §1.1 —— 选定一个跑完再换。

### 2.2 旋镜视频(`0031_首帧场景`)

以场景图为首帧, 生成 **360° 旋镜视频**(I2VA):

- 实测产物: `media/<库>/0031_首帧场景/00001_书房旋镜.mp4` = **`960×544` / 24fps / 12.25s**;
- 该视频是 **`0035` 的输入**, 也是 `0034_世界模型` 的输入(复用同一段, 不另拍)。

### 2.3 取八方位视图(两条等价路线)

**路线 A — `0035_场景截帧` 工作流(推荐)**

输入源实测:

```
#18 FallingTSLoadVideo = ['书房', '00001', None, '0031_首帧场景/00001_书房旋镜.mp4', ...]
```

产出(全部落 `media/<库>/0035_场景截帧/`):

| 节点 | 后缀 | 内容 |
|---|---|---|
| `#118~#125` | `_前面` `_前右` `_右面` `_右后` `_后面` `_后左` `_左面` `_左前` | 8 张单方位帧 |
| `#117` | `_四图` | `FallingTSImageComposite(total=4)` → 2×2 合成 |
| `#127` | `_八图` | `FallingTSImageComposite(total=8)` → 3×3 合成(末格留空) |

- 保存节点是 `AutoSaveImage`, `filename_prefix` 接 `FallingTSLoadVideo` 的 `prefix`(槽 2);
- 名称形如 `00001_书房_前面.png`。

**路线 B — ffmpeg 直接抽帧**

只要单帧、不要合成图时用它。⚠️ **本机 `ffmpeg`/`ffprobe` 不在 PATH**,
必须走 `imageio_ffmpeg`:

```python

FF = imageio_ffmpeg.get_ffmpeg_exe()          # 实测 v7.0.2, -vf 可用
# 360° 分 8 份 ⇒ 每 45° 一帧; 12.25s 视频按时间点抽
subprocess.run([FF, "-ss", "0", "-i", src, "-frames:v", "1", "00001_书房_前面.png"])
```

## 3. 参考图质检(汇总进 0044 之前**必须做**)

**这是一道硬闸门, 不是建议。** 带病参考图一旦汇总, 问题会被 0044 放大,
且事后**无法从成片反推是哪张参考图的错**。

用 `read_image` 逐张查看(合成图 `_四图`/`_八图` 优先看, 一张覆盖多视角):

| 检查项 | 不合格表现 | 处置 |
|---|---|---|
| **内容混乱** | 同一格出现多个人/多件物、肢体粘连、视角错位 | 重跑该资产行 |
| **三视图一致性** | 三个视角不是同一人/同一物(脸型/服装/尺寸不一致) | 重跑 0011, 强化一致性描述 |
| **拆图错位** | 某格切到相邻视角的半个身子 | 重跑 0011, 强调「三等分、间距均匀」 |
| **参考图分辨率** | 3×3 每格 ≠ 视频分辨率 | 查闸门是否放行、拆图倍数是否选对 |
| **背景纯净度** | 出现地面/投影/环境元素 | 重跑 0011, 强调纯白 `#FFFFFF` |
| **场景方向错** | 八方位顺序与实际朝向对不上 | 重跑 0031 / 0035 |
| **场景内容漂移** | 八方位帧之间墙面/家具位置跳变 | 重跑 0031, 强调固定布局 |

**通过标准**: 每张参考图都有明确结论, **未通过的一律不进 §4**。
结论记进运行账本(`references/pipeline.md` 的账本 schema)。

## 4. 汇总出片:`0044_参考视频`

### 4.1 表结构

```
ID | 视频提示词 | <Picture 1..9> | <Video 1..3> | <Audio 1..3> | 宽度 | 高度 | 视频秒数
```

`<Picture N>` / `<Video N>` 填**上游产物引用**, 形如:

```
@{0016_建模拆图/00001_陈落_中间}      ← 万物路参考图
@{0035_场景截帧/00001_书房_前面}      ← 场景路参考图
@{0031_首帧场景/00001_书房旋镜}       ← 视频参考
```

⚠️ **`N` 是「非空参考图的连续排位」, 不是槽位号** —— 空槽是唯一的「不锚定」开关。
⇒ 中间留空会让后面的整体前移, 这通常正是想要的; 但要清楚它的语义。

### 4.2 参考图模式: 固定 `match`

实测 `MiniMaxH3ReferenceToVideo` 的控件值:

| 工作流 | `ref_image_size_mode` |
|---|---|
| **`0044_参考视频`** | **`match`** ✓ |
| `0032_参考场景` | `match` |
| `0014_参考建模` | `max` ← 特例, 人物建模用 max |

- `match` = 官方蒸馏训练时的策略, **官方明确推荐**, 保持一致;
- **不要在 md 里「改」它** —— 它是工作流控件, 不是表字段;
  只能经 `--resolution` 那类**API 载荷层面**的覆盖来动(§5)。

### 4.3 档位与 shift(Ref2VA 铁律)

`0044` 有步数 `FallingTSSelector`(`默认/8步/4步`)与宽高 `FallingTSSelector`,
以及**两个** `MiniMaxH3SigmaShift`, 实测当前都是 **`[12, 3]`**。

> **Ref2VA 恒 `12/3`, 与分辨率档位无关。**
> 实测: `0044` 传 `--resolution 1344*768` 时 shift **保持 12/3 不变**;
> `0031` 传 768p 时才从 `[12,3]` 切到 `[6,3]`(因它是 FL2VA)。
> **不要用「文件名带 768p ⇒ 6/3」这条通则去推 Ref2VA。**

## 5. 无头执行

```bash
python .agents/skills/comfyui-workflow-runner/scripts/workflow-to-prompt.py \
    "0044_参考视频.json" --refresh-md --resolution 960*544 --submit
```

脚本参数(实测定义在 `sys.argv` 扫描, 无 argparse):

| 参数 | 作用 |
|---|---|
| `--refresh-md` | 按 md 重读表, **不改磁盘工作流 JSON** |
| `--resolution W*H` | 三件事: ① 宽高 selector 覆盖成 `默认`; ② 按谱系换 LoRA; ③ **同步 shift** |
| `--submit` | 真正提交(不加则 dry-run) |
| `--dump PATH` | 导出 API 载荷 |

**每一步都要**:

1. **Run 前 reset**: `POST /preview-image/reset`、`/preview-video/reset`、
   `/preview-audio/reset`、`/audio-trim/reset` —— 不做会命中执行缓存跳过节点;
2. **引用强校验**: 每个 `@{...}` 都要能解析 ——
   `GET /fallingts_mdtable/resolve?path=@{表名/ID}`(**必须 GET**, POST 恒返 405);
3. **提交后回读校验**, 不能只信 200;
4. **闸门**: `0011`/`00110`/`0020`/`00200`/`0021`/`0063` 含 `FallingTSContinue`;
   `0016` 用 RunGroup(2 个); 放行前先 `POST /free`;
5. 所有按钮状态在**内存**里, 服务重启即失 —— 跑完立刻操作。

### 各工作流的执行要点速查

| 工作流 | 闸门 | 保存节点 | 注意 |
|---|---|---|---|
| `0011` / `00110` | ✅ Continue | `PreviewImageSave` | 必须放行, 否则无 3 倍放大 |
| `0016` | ❌ RunGroup ×2 | `AutoSaveImage` | 用「▶ 运行本组」选 4 张或 9 张 |
| `0020` / `00200` | ✅ Continue | `PreviewImageSave` | |
| `0031` | ❌ | `PreviewVideo` | 需显式打保存端点才落 output |
| `0035` | ❌ | `AutoSaveImage` | 执行即落盘 |
| `0044` | ❌ | `PreviewVideo` | 需显式保存; 出片主力 |
| `0063` | ✅ Continue | `SaveAudioAdvanced` | 本机缺模型, 默认跳过 |

## 6. 成片复核(生成视频之后**必须做**)

```python
import imageio_ffmpeg, subprocess
FF = imageio_ffmpeg.get_ffmpeg_exe()
# ① 按帧号抽单帧(时间 × 24fps: 0.5s → n=12)
subprocess.run([FF, "-i", src, "-vf", f"select='eq(n,{n})'",
                "-vsync", "0", "-frames:v", "1", out])
# ② 整片等距抽帧拼图看走向
subprocess.run([FF, "-i", src, "-vf", "fps=1,tile=4x2", "-frames:v", "1", sheet])
```

**抽帧时间点**: 至少覆盖**开头 / 中段 / 结尾**; 长片按秒等距多抽。

**看图判断** —— 是否符合**小说内容所描述的剧情与内容**:

| 维度 | 看什么 |
|---|---|
| 人物身份 | 脸/发型/服装是否与 `0016` 参考图一致(跨镜头不漂移) |
| 场景吻合 | 是否与正文描述的环境、时间、天气一致 |
| 动作/运镜 | 是否达到提示词要求的动作幅度与镜头运动 |
| 结构完整 | 肢体/手指/物体有无崩坏、闪烁、穿模 |
| 音频 | 声轨是否与画面匹配、有无爆音/静音 |

**不满意 ⇒ 回改再跑**, 两条路:

1. **调提示词** —— 改 `0044_参考视频.md` 该行的视频提示词(按 Ref2VA 六段);
2. **换 / 改参考图** —— 回 §1 / §2 重生成, **再过 §3 质检**;

然后**重新提交 0044**。**可迭代多轮**, 每轮都进账本(改动 + 结论)。

> 复核用抽帧图**只作判断依据**, 不要混进 `media/` 产物目录; 需留存时落 `.agents/tmp/`。

## 7. 落盘规则: 插件如何决定目录与文件名

> **一切产物** —— 资源图、参考图、音频、视频、场景视频、3D 产物 —— 都经插件节点落盘,
> 统一遵守: **① ID 规则命名; ② 存进 output 下「md 表文件名」或「工作流名」子目录;
> ③ 文件名以 `0000x` 开头, 与 md 数据 ID 规则一致。**

### 7.1 目录解析(`output_subdir.resolve_subdir`, 实测源码)

```python
resolve_subdir(workflow_name, prompt) -> str
    return md_table_name(prompt) or safe_dir_name(workflow_name)
```

| 优先级 | 条件 | 子目录名 |
|---|---|---|
| 1 | API prompt 里有 `FallingTSMarkDownTable` | 该节点 `data.md_path` 的**表文件名**(去 `.md`) |
| 2 | 无 md 表节点 | **工作流名** |

- 多张表同图时取 **节点 id 最小**的那个(保证结果确定);
- 目录名经 `safe_dir_name` 清洗(剥 `.json` 后缀、替换 Windows 非法字符、防 `../` 穿越);
- 绝对路径 = `folder_paths.get_output_directory()/<子目录>` = `media/<库名>/<子目录>/`。

⇒ **表文件名 = 产物目录名**, 这正是 `@{表名/ID}` **严格命中**的前提。

### 7.2 编号解析(`output_subdir.sequence_prefix`, 实测源码)

```python
sequence_prefix(sequence, name)   # → "00005_夜雨"
    seq = "%05d" % max(1, seq_num)   # 5 位补零; 空/0/负数 → 00001
    return seq + "_" + token if token else seq
```

- 序列号 **5 位补零**; 名称经 `safe_file_token` 清洗(空白折叠成 `-`, 最长 120);
- 名称为空时只给序列号(不补下划线, 免得出现 `00005_`);
- `next_sequence(directory)` = 目录里已有 `数字_` 命名**文件**的最大编号 + 1
  (只数文件 —— 目录名也以数字开头, 算进去会得到无意义的值)。

### 7.3 保存节点前缀来源(实测 85 个保存节点全部溯源)

| 来源 | 数量 | 前缀内容 |
|---|---|---|
| **mdtable `ID` 槽(槽 0)** | **42**(其中 10 个经 `Reroute` 中转, 均在 `0023_场景旋镜`) | 表内该行的 ID 原文, 如 `00001_陈落` |
| **`FallingTSLoad*` 的 `prefix` 输出**(槽 2) | **42** | `<序列号>_<名称>`, 如 `00001_书房` |
| — `FallingTSLoadVideo` | 26 | 用于 `0035`/`0050`/`0051`/`0070` |
| — `FallingTSLoadImage` | 13 | 用于 `0016` |
| — `FallingTSLoadAudio` | 3 | 用于 `0060`~`0064` 类 |
| ⚠️ **硬编码(未接线)** | **1** | `0034_世界模型` 的 `#3` = `'0034_世界模型_360长图'` |

**两条路线产出的文件名格式一致**: 都以 `0000x_` 开头。

> **保存节点的 `widgets_values[0]` 常写着 `preview` / `scene_video` / `model_video`
> —— 那是「未连线时的兜底默认值」**, 一旦 `filename_prefix` 接上就被覆盖。
> ⇒ **改 md 的 ID 就是改产物文件名**, 反之亦然。

### 7.4 产物命名实例(本机实测)
