## 3. mdtable 位置式槽位(改列序 = 静默错位)

`FallingTSMarkDownTable` 的输出槽 = **字段数组下标**, 与工作流连线一一绑定。
实测 `0044` 的 20 个字段与槽位:

```
slot 0  = ID            → 保存节点 filename_prefix（决定产物文件名！）
slot 1  = 视频提示词 / 场景提示词 / 建模提示词
slot 2..10 = <Picture 1..9>
slot 11..13 = <Video 1..3>
slot 14..16 = <Audio 1..3>
slot 17 = 宽度          → 宽高选择器 / EmptySD3LatentImage
slot 18 = 高度
slot 19 = 视频秒数      → 帧数换算 (max(5, round(a*24)) 对齐 17k+5)
```

**不同表的槽位不同**(列数不同), 但**同一条铁律**: 插入/删除/调换列 ⇒ 下游连线全部错位,
**且不会报错**。这就是 auto 技能「不新增列、不改列序」的根据。

### 3.1 ID → 产物文件名(实测接线)

**所有产物统一遵守**: ID 规则命名 → 存进 output 下「md 表文件名」或「工作流名」子目录
→ 文件名以 `0000x` 开头。前缀有**两条来源**(实测 85 个保存节点全部溯源):

```
① mdtable 槽0 (ID) ──→ 保存节点 filename_prefix         [42 个]
   例如 `00007_第四夜醒着` (其中 10 个经 Reroute 中转, 均在 0023)
     ↓
   media/七纹刻印/0044_参考视频/00007_第四夜醒着.mp4

② FallingTSLoad* 的 prefix 输出 (槽2) ──→ filename_prefix  [42 个]
   = `<序列号>_<名称>`  例 `00001_书房`
     ↓
   media/七纹刻印/0035_场景截帧/00001_书房_前面.png
   (LoadVideo 26 / LoadImage 13 / LoadAudio 3)
```

⚠️ 保存节点自己的 `widgets_values[0]` 常写着 `preview` / `model_video` / `scene_video`
—— 那是**未连线时的兜底默认值**, 一旦 `filename_prefix` 接上就被覆盖。
所以**产物名 = md 表里的 ID**(或加载节点的「序列号_名称」), **改 ID = 改产物文件名**。

⚠️ **唯一例外 `0034_世界模型`**: 其 `#3` 前缀**硬编码** `'0034_世界模型_360长图'`,
不以 `0000x` 开头。跑它时需在 API 载荷层面覆盖, 或明确告知用户。

> 目录解析与编号生成的源码机制(`resolve_subdir` / `sequence_prefix` / `next_sequence`)
> → `production-flow.md` §7。

## 5. 工作流的「档位」机制(实测, 与 Note 说法不同)

H3 与 Qwen-Image 工作流都有「加速档 / 标准档」切换, 但**实现方式分两种**:

| 实现 | 出现在 | 机制 |
|---|---|---|
| **`FallingTSSelector` 选档** | 全部 H3 视频类(0013/0030/0031/0032/0033/0040~0044) + 0023 | 下拉选 `默认/8步/4步`, 各组输出「模型/采样器/步数」 |
| **`FallingTSSwitch` 布尔开关** | 图片类(0011/0012/0017/0020/0021/0022) 与 0014/0032 | `total` 组开关, 同时切 模型/步数/CFG |

⚠️ **实测发现**: `0013`/`0030`/`0031`/`0033`/`0040`/`0041`/`0042`/`0043` 的 Note 都写
"`FallingTSSwitch` — True=4步", 但它们图里**根本没有 `FallingTSSwitch`**,
用的是 `FallingTSSelector`(如 `0013` 的 `#130` selection=`'4步'`)。
**Note 未随重构更新** —— 这也是本文件以实测为准的原因。

## 6. 实测校验结果(2026-10-15, 经运行中的 8188)

对 `stories/七纹刻印/*.md` 里全部 `@{表名/ID}` 逐条调 `GET /fallingts_mdtable/resolve`:

- **共 20 条去重引用 → 严格命中 18 / 兜底命中 1 / 真失败 1**
- ❌ 唯一真失败: `@{0010_灰度遮罩/00001_陈落换装}`(出现于 `0012_万物变化.md`)
  —— `media/七纹刻印/0010_灰度遮罩/` 下只有 `00001_参考视频第一条_手机.png`。
- ⚠️ 隐患: `@{0011_万物建模/00001_陈落_左上}`(出现于 `0044_参考视频.md`) 严格趟落空
  (`0011_万物建模/` 只有 `00001_陈落.png`), 靠**兜底趟**命中 `0016_建模拆图/00001_陈落_左上.png`。
  语义上目录写错了, 一旦源文件被清理就会**静默变 `None`**。

> ### ⚠️ 调用本端点的两个坑(都踩过)
>
> 1. **必须是 `GET`, 不能 `POST`。** 实测 `POST` 恒返回 **`405 Method Not Allowed`**。
>    踩坑经过: 用 `urllib` 发 POST 时异常未被识别成失败, 而 `405` 的响应被误读,
>    导致脚本报出「20/20 全部命中」的**假绿**。改成 `GET` + query string 后才是真实结果。
>    验证脚本务必**显式检查 `ok` 字段**、并把「异常」与「失败」分开统计。
> 2. **`path` 必须是完整引用串 `@{表名/ID}`。** 传裸路径 `0011_万物建模/00001_陈落`
>    会 **100% 返回 `{"ok": false, "path": null}`**。
>
> ```bash
> # 正确写法
> curl -s -G http://127.0.0.1:8188/fallingts_mdtable/resolve \
>      --data-urlencode "path=@{0011_万物建模/00001_陈落}"

## 7. Note 与实测不符清单(为什么不能只信 Note)

工作流自带的 Note 是**开发者当时的自述**, 多次重构后已部分失真。实测确认的偏差:

| 工作流 | Note 说 | 实测 |
|---|---|---|
| `0011` | 「尺寸 1088×1920 / 1920×1088 / 1088×1088」 | md 现值 **`960×544`**; 且产物再 **×3** = `2880×1632` |
| `0020` | 「全部场景统一 1344×768」 | md 现值 **`960×544`**; 产物 `960×544` |
| `0013` 等 8 个 | 「`FallingTSSwitch` True=4步」 | **无此节点**, 实为 `FallingTSSelector` |
| `0030`/`0040`/`0041`/`0042`/`0033` | 「turbo 4步 768p LoRA + shift 6/3」 | 磁盘上确是 768p 系(6/3)✓, 但**可被 `--resolution` 覆盖切档** |
| `0031` | 「True=4步 (shift 6/3)」 | 磁盘上已是 **544p 系 + shift 12/3 + selector 默认** |

**结论**: 引用 Note 的**意图描述**(这工作流是干什么的)是可靠的;
引用它的**具体参数/尺寸/节点名**必须**当场实测**。

## 9. 共用表覆盖风险(必须知道)

四对工作流**写同一张表、落同一目录**, 同一 ID 的产物**互相覆盖**:

| 配对 | 共用表 | 共用目录 |
|---|---|---|
| `0011` ↔ `00110` | `0011_万物建模.md` | `0011_万物建模/` |
| `0012` ↔ `00120` | `0012_万物变化.md` | `0012_万物变化/` |
| `0020` ↔ `00200` | `0020_场景首帧.md` | `0020_场景首帧/` |
| `0022` ↔ `00220` | `0022_场景推镜.md` | `0022_场景推镜/` |

⇒ auto 技能**默认只用不带 `0` 后缀的那一个**(`0011`/`0012`/`0020`/`0022`);
换用 QI2.1 版前必须确认用户意图, 否则会污染既有产物。
