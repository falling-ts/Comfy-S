## 画面术语定义（面/侧/边/视/词/缘）

六种术语全文档严格区分，严禁混用：

1. **面**：代表三维空间拍摄的具体画面（场景某一朝向的画面），共**九方位**：前面（正面）、前右、右面、右后、后面、后左、左面、左前、全图（四个正方向 + 四个斜方向 + 全景俯瞰）；场景类列名与提示词内容中的「面」一律指被描述的画面朝向
2. **侧**：代表摄像机在哪侧，**永远与面相对**：左侧相机拍摄的是右面，右侧相机拍摄的是左面，后侧相机拍摄的是前面，前侧相机拍摄的是后面；斜向同理——左前侧相机拍摄的是右后面，右后侧相机拍摄的是左前面，后左侧相机拍摄的是前右面，前右侧相机拍摄的是后左面；上下同理（上侧相机拍摄的是下面，下侧相机拍摄的是上面）
3. **边**：代表一个场景画面九宫格的哪一边（方位格），例如 左边在中间的左边，右上在中间的右边的上边
4. **视**：与场景无关，只与万物有关；万物类画面（**人物、生物、物品一律**）统一采用三视图（横向并排三个视角，**左边是正面、中间是侧面、右边是后面**）；不是九宫格
5. **词**：仅分 正词 与 负词；资源表提示词列后缀一律写 -正词 / -负词，词名中不得出现「面」字（避免与画面的面冲突）；提示词正文中出现的「面」指画面的面（如旋镜提示词「右面是…」）
6. **缘**：代表**画面边缘**，共八处——左缘、左上缘、上缘、右上缘、右缘、右下缘、下缘、左下缘（**四缘** = 左缘 / 上缘 / 右缘 / 下缘，四角缘 = 左上缘 / 右上缘 / 右下缘 / 左下缘）；**只与画面变化（运镜）有关，与场景方位无关**，专门用来描述视频画面里元素的**进出方向与进出快慢**（不是场景的边、不是九宫格方位格的「边」，也不与万物三视图的「视」混用）。判据（2026-10-08 定，方向口径与本文档「12 秒八镜 360° 旋镜定式」一致）：
   - **一进一出定旋转**：画面内容从**右缘进入、左缘移出**（地平线保持水平）＝镜头**顺时针旋转**（pan right）；反向从**左缘进入、右缘移出**＝**逆时针旋转**（pan left）；从**上缘进入、下缘移出**＝镜头**上仰**（tilt up），从**下缘进入、上缘移出**＝**下俯**（tilt down）
   - **四缘同进 = 拉镜**：元素从四面边缘同时向画面中心进入（画面范围变大、视点后退）＝**拉镜头**；**四缘同出 = 推镜**：元素从画面中心向四面边缘移出（画面范围变小、视点前进）＝**推镜头**
   - **一侧快一侧慢 = 侧拉镜**：两侧缘进出速度不等（如左缘移出快、右缘进入慢）＝**侧拉镜**（拉镜叠加横移 / 斜向拉镜）；上下两缘速度不等则为上下斜拉
   - **有无视差是分水岭**：缘上内容有进出、透视关系不变（只是视线被扫过）＝角运动（pan / tilt）；四缘同进同出但**前后景无视差**＝光学变焦（zoom）；**有视差**＝物理推拉（dolly in / out）
   - 写入提示词时直接点名缘即可（如「右侧内容自画幅右缘进入、向画幅左缘移出」「四面内容同时向画幅中心汇聚进入」），**镜头术语仍取英文**（见「H3 提示词语言规范」）

### 图片提示词书写顺序规范

万物建模、万物变化、场景首帧、场景拉镜、场景推镜 的提示词，除遵循各自类型的专属要求外，还必须严格按照以下顺序书写：

1. **整体图片品质**：描述整图画质、清晰度、精细度、光影氛围、环境背景等整体视觉表现
2. **图片元素万物**：列出画面中出现的所有元素与万物（人物、器物、场景物体、生物、道具、自然景物等）
3. **图片风格要求**：写明整体艺术风格。**本故事库所有生图类资源（万物建模、万物变化、场景首帧/拉镜/推镜/旋镜）默认统一采用「写实三维CG风格」**：次世代三维渲染质感，立体体积感明确，真实材质与皮肤纹理（保留毛孔与细微纹理，不做平涂磨皮），影棚级立体布光与自然明暗过渡。⚠️ **2026-09-22 起整体改写实三维CG**（旧规范为「国漫CG风格」且严禁"写实"字样，已废止）：实测国漫CG 正词叠加负词里的 `写实摄影`/`实拍照片` 会把画面压成 2D 动漫平涂脸，故**负词里严禁再出现 `写实摄影`/`实拍照片`**，要压制的是 `二维动漫`/`二次元平涂`/`卡通渲染`/`赛璐璐上色`/`塑料感皮肤`/`过度磨皮`。注意「不向纯白背景投射阴影」≠「主体没有立体光影」，主体自身必须有体积与明暗过渡

三段顺序不可颠倒，缺失任一段视为不合格。

#### 提示词内容分段规则（通用，两类生图提示词共同遵守）

- **段分隔符统一**：提示词的所有分段点一律用 `<br>` 分隔（每个分段点一个 `<br>`，置于段末），段内属性用全角逗号 `，` 分隔，全文不使用句号；严禁使用换行符（真实回车 / 换行字符）或 `\n`（反斜杠 n 两字符）作为分段符——md 表格单元格内的换行会被解析为新行从而断开表格，只有 `<br>` 能在单元格内安全分段；冒号仅用于点名词句（如万物类的 `主体：`），同一条目内要么全用要么全不用，保持一致。⚠️ **注意与 Qwen-Image 2.1 官方规范的冲突**：官方要求送进模型的提示词是**单段连续文本、禁任何换行**（[system_prompt_edit.txt](refs/Qwen-Image-2.1/prompt_rewrite/prompts/system_prompt_edit.txt) L186）。两者不矛盾但需两步走——**表内保留 `<br>` 以保表格结构，`<br>` 在送模型前合成单段**；现状是带着 `<br>` 直接送模型，属已知偏差。详见外部技能 `qwen-image-2-1-prompting`
- **一段一职责**：每段只写一类信息（整图品质 / 一个显示区域 / 一个方位格 / 风格），不跨段混写
- **段头点名词**：每段以点名词开头（如 `主体：`、`左上…`、`右面是`、`整体是…`、`写实三维CG风格`），点名词即段边界
- **一个元素只归一段**：不得在不同段重复堆叠同一元素
- **风格词只在最后一段**出现（`写实三维CG风格，…` 收尾），严禁散入品质段与区域段
- **`整体是…` 总结段全文仅一处**，紧跟区域段之后
- **段序固定**，不可颠倒，缺段视为不合格

两类提示词的分段维度不同，各自按以下规则执行：

#### 万物类分段规范（一律按三视图分段）

万物建模、万物变化 的画面**一律是三视图**（人物、生物、物品无例外，2026-10-07 改回）：横向并排正面/侧面/后面三个视角，**左正、中侧、右后**，**不使用九宫格**、不使用特写分区。段序：

1. **品质段**：画质描述 + 纯白背景硬句（#FFFFFF，无环境、无场景、**不向背景投射阴影**；「不投影到背景」不等于「主体没有立体光影」，主体自身必须写明体积与明暗过渡，见各自类型规范）
2. **布局声明段**：点明画面构成与取景（物品：`物品三视图并排展示，左边是正面、中间是侧面、右边是后面，三个视角为同一件物品、造型尺寸完全一致、均完整入画`；人物：`人物三视图并排展示，左边是正面、中间是侧面、右边是后面，三个视角为同一个人、体型与造型尺寸完全一致、均完整入画`；生物：`全身三视图并排展示，左边是正面、中间是侧面、右边是后面，三个视角为同一只生物、体型与造型尺寸完全一致、均完整入画`）
3. **主体段**：`主体：` 开头，**逐视角/逐区域分段**写各区域各自可见的形态特征（外形轮廓、结构组成、材质质感、颜色配色、纹样装饰、配件部件）；**与各区域无关的共同特征**（材质、配色、风格等）只写一次、不按区域重复
4. **总结段**：`整体是…`（全文仅一次）
5. **风格段**：`写实三维CG风格，…` 收尾

点名词体系：**主体**（画面各区域的共同主体）+ **视/区域**。`主体：` 只与万物有关，**严禁出现在场景类提示词中**；万物类物品/生物**必须写出三视字样**（`三视图`，生物写 `全身三视图`、物品写 `物品三视图`）与三个视的方位（`正面`/`侧面`/`后面`），但**严禁使用特写分区**（`左边特写`）与九宫格方位格（`左上`/`中间格`等）；`正面/侧面/后面` 三个视与场景类的九方位面（`前右`/`右面`/`后面`）是**不同体系**，万物类只用前者。万物类**三类对象（人物/生物/物品）都必须写出三视字样**（人物写 `人物三视图`、生物写 `全身三视图`、物品写 `物品三视图`），且都**必须按 左正 / 中侧 / 右后 的顺序逐视描述**（方位词只写在提示词里，**绝不出现在画面里**）。
万物变化段序：`以图1为底，保持原构图不变` 起头 → 主体修改段（`主体：` 开头，写改后的新外观）→ 风格段。

#### 场景类分段规范（按九宫格方位格分段）

场景首帧、场景拉镜、场景推镜、场景旋镜 的画面按**九宫格方位格**分段（见「场景图片生成 九宫格画面描述要求」）。段序：

1. **品质段**：画质 + 光影氛围描述（场景自带环境，无纯白背景要求）
2. **方位格段**：按固定顺序逐格一段——16:9 横版按 `左上…` → `左边…` → `左下…` → `上边…` → `中间…` → `下边…` → `右上…` → `右边…` → `右下…`；9:16 竖版按 `上左…` → `上边…` → `上右…` → `左边…` → `中间…` → `右边…` → `下左…` → `下边…` → `下右…`；每格段以该格方位词（边词）开头，无内容的格可略过
3. **风格段**：`写实三维CG风格，…` 收尾

点名词体系：**边词**（九宫格方位格），与万物类的 `主体：` 点名词互斥——场景类提示词中**严禁出现万物类的 `主体：` 点名词、三视图与特写分区**（`三视图`、`全身三视图`、`物品三视图`、`左边特写`）。⚠️ 场景类**允许**用 `正面`/`侧面`/`后面` 等方位词（它们属九方位面体系），但**不得**写成三视图并排结构。
- **场景推镜**：单帧非九宫格，不划分方位格段，仅用区域方位词描述画面内各区域的内容分布

### 生图类尺寸规范

| 用途 | 宽度×高度 | 说明 |
| :--- | :--- | :--- |
| 万物建模、万物变化（全部对象：人物、生物、物品，不分形态） | **832×480** | 固定横屏档；三视图要把三个视角并排放下，画面必须**横向**；三个视角各占约 1/3 宽（单个约 277 像素宽） |

- **不分档**：人物、生物、物品一律 **832×480**，不按对象固有形态另选比例
- 宽度/高度两列必须成对填写 **832** 与 **480**，不得自行拼凑比例
- ✅ 每轴均为 32 的倍数（832 = 26×32，480 = 15×32），满足 VAE 8×8 下采样对齐
- ⚠️ **代价说明**：832×480 下单个视角仅约 277 像素宽（26 个 token），**三视图的立绘分辨率偏低**，细节与人脸辨识度受限；这是为固定档位与速度付出的代价，若某一行确实需要更高细节，可临时上调到 **1664×960**（同 26:15 比例、约 4 倍面积，每轴仍为 32 倍数）——但**默认档仍是 832×480**
- **档位选择**（2026-10-11 修订，2026-10-14 补 544p 档）：默认 480 档——480×832 / 832×480（0.4MP，与万物建模固定档、H3 视频默认桶一致）；需要更高细节时升 **544 档——竖屏 544×960 / 横屏 960×544**（0.52MP，官方 T2VA/Ref2VA 示例画布），或升 768 档——竖屏 768×1344 / 横屏 1344×768 / 正方 768×768（≈1.03MP），或升 Qwen-Image 2.1 官方 2K 档——竖屏 1536×2752 / 横屏 2752×1536 / 正方 2048×2048（≈4.2MP，**实测生成明显更慢**，8G 显卡另有 OOM 风险）；高清统一走 4x 外部放大 + 分块重绘
- 像素保持 32 的倍数（VAE 8×8 下采样对齐）；各档比例与 H3 视频桶（9:16 = 768×1344）相差不到 1%，进首帧视频/首帧场景时由模型自动重采样，无需人为改小

**场景首帧**（场景类，不属于万物）的宽度/高度统一填写 **16:9 = 832×480**（480p 档，0.4MP，与 MiniMax H3 视频桶一致）；显存充足可升 **1344×768**（768p 档，≈1.03MP），或取中间档 **960×544**（544p 档，0.52MP）。⚠️ **H3 视频合法档位共三档：0.4MP（480p）、0.5MP（544p）、1.03MP（768p）**——统一受短边 ≤768、面积 ≤768×1344（≈1.03MP）约束，场景首帧的宽度/高度也只在这三档里取，与其他 H3 视频资源同口径。进首帧视频/首帧场景时，模型会把首帧自动重采样到视频目标 canvas，无需人为改小。需要其他比例时，从本节三档改比例、或从 H3 合法桶选取（见「视频类尺寸规范」）。

### 视频类尺寸规范（MiniMax H3）

视频类资源（文生场景、首帧场景、文生视频、首帧视频、首尾视频、关键帧视频、参考视频）的宽度/高度按 MiniMax H3 官方 canvas 规则填写：

- H3 固定 **24fps**（模型架构常量：表内**不设「视频帧率」列**，工作流的帧数换算一律写死 ×24，输出容器帧率亦恒为 24；要变速/补帧另用 `FallingTSFrameRateConvert` 节点）；视频秒数按需求填 5~15 秒（官方训练域）
- canvas 硬规则：**短边 ≤ 768**、**面积 ≤ 768×1344（= 1 032 192 ≈ 1.0322MP）**、每轴为 **32 的倍数**；宽度/高度直接决定生成尺寸，超限不会被自动纠正

**三档位速查**（档名来自官方 README `Model specs` 表的 `Training resolution` 列，是本机资源表的取值口径）：

| 档位 | 16:9 尺寸 | 面积 | 适用 |
| :--- | :--- | :--- | :--- |
| **480p 档**（0.4MP） | **832×480**（官方 I2VA 示例用 864×480） | 0.40MP | **默认档**；8G 显卡；低显存/加速 |
| **544p 档**（0.5MP） | **960×544** | 0.52MP | 官方 T2VA 与 Ref2VA 示例的默认画布；中等显存 |
| **768p 档**（1.03MP） | **1344×768** | 1.03MP | 16G+ 显存；768p 系 turbo LoRA 训练域 |

- 默认统一 16:9 = **832×480**（480p 低显存档，0.4MP，官方原生工作流默认，适配 8G 显卡）
- 显存充足（16G+）可升档 16:9 = **1344×768**（768p 官方主推档，与 turbo 4 步 LoRA 训练域一致）

### H3 提示词语言规范（视频类资源通用）

> **2026-09-25 用户决定：提示词正文改中文，H3 关键标识保持英文。** 下表是唯一语言口径。正文（画面、运镜、光影、动作、声音、剧情的描述句）写中文，便于作者读写与维护；凡是**模型要照抄的骨架**——字段名、`<Picture N>`/`<Subject N>` 一类标签、retention 枚举、方括号任务前缀、`[Shot N]` 与紧邻时间戳、官方对齐指令整句——一律保持英文。`stories\七纹刻印\` 下 9 个含提示词的资源表已按此口径改写完毕，对应 9 个工作流的 mdtable 快照同步刷新。

**写进资源表的提示词正文一律中文**，只有对白/歌词与画面内实际可见的文字保留原语言；**骨架与镜头语言术语保持英文**。

为什么上一版写的是英文（现降级为**已知代价**，不推翻）：H3 官方提示词技能（`h3-prompt-writing`）与官方模板（`templates\视频\api_minimax_h3_max_r2v.json` 等）的示例 prompt 全为英文；官方 HF 仓库讨论 #32 中经官方人员编辑的答复为「除需要生成的文字和对白内容，其他都要用英文描述」；官方模型卡载明 H3-Encoder 取 **Qwen3-VL-32B 第 50 层隐状态**送进 H3-Omni-Transformer，生成主干是在英文条件上训练的，故中文条件落在分布外。本机 `qwen3vl_32b_minimax_h3_nvfp4_awq` 是 **4-bit** 量化编码器，多语言基准实测长提示词的词义错乱率为**英文 1.8 / 100 词、中文 3.1 / 100 词**（中文额外损失约 1.7 倍）——长提示词用英文可同时规避「条件分布外」与「量化损失」两笔代价。这些代价**不因改用中文而消失**，只转为可接受成本；实测数字与唯一的有效回退杠杆见本节末「已知代价」。

| 内容 | 填写语言 |
| :--- | :--- |
| 六部分 / 三部分核心字段的正文（画面、运镜、光影、动作、声音描述） | **中文** |
| 固定字段名与标签 | **英文**：`subject_definitions`、`integrated_multimodal_description`、`<Subject N>`、`<Picture N>`、`<Video N>`、`<Audio N>`、`[Shot N]`、`At MM:SS.mmm`、`fully_preserved` 等；**严禁写成 `<图片 1>`、`[镜头 1]`、`[中文]`** |
| 对白语言标签 | **英文语言名**：`<d>[Chinese] 我们现在出发。</d>`；说话人 ID 写 `(S1)`、`(S2)` 并置于 `<d>` 之外 |
| `<d>` 内的对白 / 歌词 | **保留原语言**（中文对白直接写中文，不翻译、不改写） |
| 画面内实际可见的文字（招牌 / 字幕 / 标签） | **保留原语言**，用英文双引号逐字包住，如 `a sign reading "营业中"` |
| 镜头语言术语（见下文词汇表） | 写入提示词时取**英文术语**（push in / medium close-up / cross-dissolve），词汇表中的中文词仅供对照 |

**骨架必须逐字照抄（译错即失效）**：`<d>` 与 `</d>` 不是普通文字，而是 tokenizer 里的**扩展 special token**（本机 `ComfyUI\comfy\text_encoders\minimax.py` 中 id 为 **151669 / 151670**；同批还有 `<|cutoff|>`=151671、`<|lyrics_start|>`=151672、`<|lyrics_end|>`=151673、`<|caption_start|>`=151674、`<|caption_end|>`=151675，全部在基础词表 0..151668 之外）。译成 `<对话>` 只会被切成两个普通 token，指令直接失效；整枚标签**连同数字与空格一并照抄**（`<Picture 1>`，不是 `<Picture1>`、不是 `<图片 1>`）。字段名（`subject_definitions:` 等）、retention 枚举（`fully_preserved` 等）、任务前缀（`[reference generation]`）、`[Shot N]`、时间戳、`(S1)` 同理，全部属于骨架。

- **`<d>` 内只放两样东西**：英文语言名标签 + **用户原始说话内容**（官方 `base-en.txt`：`Inside <d>, include only the language tag and the actual user-provided spoken content`）。说话人身份、音色、语气、语速、动作一律写在 `<d>` **之外**；`<d>` 内的对白逐字保留、不翻译不改写。
- **`<d>` 内标点**：只用普通的 `,` `.` `?` `!`，且在 `</d>` 之前收尾；不写全角标点、不写省略号。
- **引用参考音频的原词**：保留原语言逐字；听不清的片段写 `[unclear]`，不得猜写。

**本文档各节的规范说明与示例用中文书写是为便于阅读；填进资源表的提示词正文一律中文，骨架与镜头语言术语仍英文。** 各类对齐指令是**官方固定句、属骨架**，一律逐字照抄英文（不翻译）：

- I2VA 首行：`For the target video, at 0.00 seconds into the target video, <Picture 1> (from [Shot 1]) is fully referenced.`
- FL2VA 首行：`Reference image alignment with the target video - Picture 1 (from [Shot 1]) aligns with the 0.00-second position of the target video; Picture 2 (from [Shot N]) aligns with the S.SS-second position of the target video.`
- 关键帧锚定：`[Shot N] At S.SS, anchored to the frame established by <Picture N>.`

**改写后的自检口径（2026-09-25 用 9 个表实测）**：中文正文字符数 ≈ 原英文字母数的 **0.23 ~ 0.33**（汉字本身约 0.21~0.27）。逐段（按 `<br>` 切）比长度比，**任一段低于 0.18 就要人工看**——那是漏译或压缩的信号；同时必须回验骨架 token 计数**逐项相等**（字段名 / `<Picture N>` / `<Subject N>` / `[Shot N]` / retention 枚举 / 任务前缀 / `At S.SS` / `<d>` / `(S1)`）与 `<br>` 数不变。这两条一起卡，才能既中文化又不破坏 H3 骨架。

#### 已知代价：中文正文的实测数据（2026-09-18 本机受控实验）

### 万物建模

即文生图并优化图片，包含ID，主-正词(TEXT)，主-负词(TEXT)，宽度(INT)，高度(INT)

**画面一律采用三视图**（2026-10-07：**人物、生物、物品全部适用**，人物不另设版式）：横向并排三个视角，**左边是正面、中间是侧面、右边是后面**。三视图是**同一个主体**的三个方向——造型、体型、尺寸、比例、配色、材质必须**完全一致**，只是朝向不同；不是三个不同对象，也不是三张不同设计。**不划分特写分区、不使用九宫格。**

万物只在正文中**第一次出现**时才建立建模条目（记录其首次外观与设定），后续不重复建。

- **全部对象（人物、生物、物品，不分形态）** → **832×480**（固定横屏档，见「生图类尺寸规范」）

提示词中必须**按 左正 / 中侧 / 右后 的固定顺序逐视写出**各自要表现的外观特征（外形轮廓、结构组成、材质质感、颜色配色、纹样装饰、配件部件）；材质、配色等**跨视角共通的特征只写一次**。**必须写出三视字样**（人物写 `人物三视图`、生物写 `全身三视图`、物品写 `物品三视图`）与三个视的方位（`正面`/`侧面`/`后面`）；**严禁使用特写分区**（`左边特写`）与九宫格方位格（`左上`/`中间格`）。

**人物行的专门要求（2026-10-07 起，必须写足）**：既然回到三视图，人物行的**服装与体型就在 0011 里定死**，不再推给 0013。

- **取景**：三个视角都是**从头到脚的完整全身**，头顶到脚底全部入画、不裁切；与物品/生物不同，人物**必须写出这一身衣着**（款式、颜色、材质、纹样、配饰、鞋履）——三视图正是为了锁服装与体型在三个朝向下不漂移
- **姿态统一**：三个视角必须是**同一个中性站姿**——双脚并拢或与肩同宽、双手自然垂在身侧、身姿笔直；不得出现走动、跨步、手势、回头或任何动作，三个视角的姿态差异只能是朝向本身
- **侧面/背面的可读性**：侧面必须交代鼻梁、下颌线、后脑发型的真实轮廓；背面必须交代后脑发型、肩背、腰臀与双腿后侧的服装结构（如衣摆开衩、鞋跟、腰带扣等背面才可见的细节），**严禁背面与正面长得一样**（这是三视图最常见的失败）
- **三视一致**：三个视角是同一个人，身高、头身比、肩宽、腿长、肤色、发型、发色、服装款式与配色**必须逐项一致**；正面写了什么，侧面与背面要对应地写出来

**三视图内部规则**（三视并排的硬约束）：

**背景硬性要求：画面背景必须完全纯净的纯白色（#FFFFFF），无任何环境、地面、光影、纹理与装饰元素；主体独立悬浮在纯白背景上，不投射阴影、不带任何场景。**

- **三等分布局**：三个视角横向**大致三等分**排列、间距均匀、各自居中，不重叠、不切边
- **无标注**：**不要**在视角之间加箭头、标签、中文/英文标注或分隔线（`正面`/`侧面`/`后面` 等文字**不出现在画面里**），也不要把三视做成拼贴相框
- **宽度/高度**：832×480（固定横屏档）。⚠️ **不要把像素尺寸写进提示词**，比例与分辨率只走宽度/高度字段

#### 万物变化 提示词提取规范

**背景硬性要求：变化后画面背景必须保持完全纯净的纯白色（#FFFFFF），无任何环境、地面、光影、纹理与装饰元素；主体独立悬浮在纯白背景上，不投射阴影、不带任何场景。**

变化以原图为底，必须**保留画面构图**：

1. **构图不变**：保持原图的三视图构图（人物/生物/物品一律如此）——三个视角的**位置、大小、视角（**左边是正面、中间是侧面、右边是后面**的排布与朝向）与四周留白全部不动**，不新增显示区域、不增删视角、不改成单视角、不加特写
2. **主体外观修改**：按需求改变主体的材质、纹路、配色、氛围等外观表现，逐条描述改后的新外观
3. **整体统一**：主体各部分（各部件、各区域）修改后风格必须完全统一，不得出现相互矛盾或风格割裂

提示词中必须写明"保持原构图不变"；逐条描述主体改后的新外观并强调整体统一；**改后三个视角必须仍与原图三视图构图一致**（左正/中侧/右后、位置大小朝向不变），且**改后的外观在三个视角间保持统一**（正面改了什么，侧面与背面要对应地改，不能只改正面）。**必须写出 `三视图` 字样**（人物写 `人物三视图`、生物写 `全身三视图`、物品写 `物品三视图`）；**严禁使用特写分区**（`左边特写`）与九宫格方位格。

### 场景图片生成 九宫格画面描述要求（场景首帧 / 场景拉镜 / 场景推镜 / 场景旋镜 通用）

场景类图片生成的提示词，必须把画面按**横向、纵向各三等分**划分为**九宫格**，并逐格点名每格内出现的元素与布局（场景方位、物件、灯光、细节），使画面各区域有明确交代、不随场。

描述顺序按画面宽高比分为 **16:9** 与 **9:16** 两种，按生图的宽度/高度选用对应顺序：

**16:9（横版）**：按 **左边 → 中间 → 右边** 描述。
- 左边：按 **左上 → 左边 → 左下** 描述；
- 中间：按 **上边 → 中间 → 下边** 描述；
- 右边：按 **右上 → 右边 → 右下** 描述。

**9:16（竖版）**：按 **上边 → 中间 → 下边** 描述。
- 上边：按 **上左 → 上边 → 上右** 描述；
- 中间：按 **左边 → 中间 → 右边** 描述；
- 下边：按 **下左 → 下边 → 下右** 描述。

每格用方位词开头点名（如"中间是…""左上…"），说明该处放的物件或留空；没有内容的格可略过，但任一元素只归入其所处的那一格，不得在不同格重复堆叠。

九宫格与场景本身的空间布局（前后左右、物件相互位置关系，见本文档「场景类公共要求」）要互相印证统一：中间格通常为核心主体/主光区，四边交代墙面/地平/边缘，四角补足角部朝向的底景与照明。

## 表格 md 文件规范说明

所有表格 md 文件的第一列永远是 ID

后续字段完全按照 标题(类型) 定义

(类型) 不填写默认是 (STRING)

(类型) 包含如下内容和说明:

- (IMAGE)/(VIDEO)/(AUDIO)/(MASK)/(STRING)/(INT)/(FLOAT)/(BOOLEAN)：对应 ComfyUI 同名输出类型
- (TEXT)：对应 ComfyUI 的 STRING 输出类型，但自定义节点渲染为多行文本框

实际使用情况（扫描 `stories/` 下全部含表格 md 文件）：显式声明过的只有 `TEXT`、`IMAGE`、`INT`、`VIDEO`、`AUDIO`、`FLOAT`、`MASK` 七种；`STRING` 从未显式书写（各资源表的 ID 列等一律靠省略默认）；`BOOLEAN` 已登记但尚无一处使用。

各类型的字段定义（ID + 各字段(类型)）见对应类型章节（图片类见本部分、场景类与视频类见第二/第三部分、音频类见第四部分）；ID 命名规则见 `stories/AGENTS.md` 的「资源 ID 规则」。

### 全图方位

**全图**是第九个方位，代表从场景**正上方垂直向下俯瞰**的全景画面（顶视/Bird's Eye），是八面水平方位之外的垂直维度补充。

- **含义**：全图不是某一朝向的画面，而是俯瞰整个场景的鸟瞰平面图——能看到场景中所有物件、地面、边界与空间关系的完整布局
- **用途**：场景类资源描述场景空间时，除八面水平方位外，还应提供全图方位的整体俯瞰描述，使模型从二维平面理解整个场景的空间结构与物件分布
- **描述要求**：全图方位的描述按俯视平面图的方位词逐区域点名（如「上方是…」「下方是…」「左侧是…」「右侧是…」「中央是…」），与八面水平方位描述交叉印证
- **与其他方位的关系**：全图方位是八面水平方位的上层概览——八面描述的是"站在某个方向往另一个方向看"，全图描述的是"从天上看下来"；两者互补而非替代

九张图为**固定语义槽位**：`<Picture 1> 首帧` 恒钉视频第 0 帧，`<Picture 9> 尾帧` 恒钉视频末帧，`<Picture 2>` ~ `<Picture 8>` 为 7 个中间帧槽位。**首帧、尾帧的位置是固定的，因此它们没有秒数列**：首帧在画布上由 `#40` 的 `frame_idx` 控件硬钉 `0`；尾帧由表达式 `max(0, a − 1)`（a = 吸附后总帧数 `length`）钉到第 `length − 1` 帧。**只有中间帧需要秒数**：第 2 ~ 8 槽每槽右侧跟一个「关键帧n所在秒数」列，工作流内每个中间帧配一个 `ComfyMathExpression`，把该秒数换算成帧索引 `frame_idx = max(0, min(round(关键帧n所在秒数 × 24), length − 1))`（24 为 H3 固定帧率），秒数留空按 0 处理。**槽位的先后与秒数大小无需单调**——中间帧按秒数各自独立定位，谁前谁后由秒数决定，不由槽位序决定。

**为什么是 9 个槽位**：官方核心没有「关键帧汇总节点」，逐帧锚定靠**链式串联 `MiniMaxH3AddGuide`**（每个节点吃 1 张图 + 1 个 `frame_idx`，数量本身无上限）。真正的上限在**文本编码器可见性**上——`MiniMaxH3ReferenceToVideo.ref_images` 是 `Autogrow.TemplatePrefix(prefix="ref_image_", min=0, max=9)`，槽位名硬生成 `ref_image_0` ~ `ref_image_8`，**第 10 个槽位名不存在**。故 **9 个图片槽位正好用满官方上限**，每个填入的槽位都能同时「被锚定」且「被提示词引用」。

**`锚点数` 列只作填写计数**：定位已改由「首帧/尾帧固定 + 中间帧逐列秒数」驱动，该列**不参与任何帧索引计算**，仅供提示词书写与自查参考；它应等于实际填图的槽位数（3 个锚点 = 首帧 + 1 个中间帧 + 尾帧）。因此**「槽位留空」就是唯一的「不锚定」开关**——空槽在数据表里输出 `None`，由 `FallingTSH3AddGuide` 原样透传，等价于该槽无锚点；**两个中间帧秒数相同（或换算后落在同一帧）时后到的那槽会被撤掉并告警**（同一时刻钉上两个互相矛盾的画面正是物件漂移的成因，该槽图片仍作为参考图参与条件）。

#### 关键帧视频 提示词提取规范

视频提示词按 H3 **关键帧锚定**规范书写（由引导节点在任意像素帧锚定画面）。**依锚点构成择一模式**：

- 只锚首帧 → 按 **I2VA** 写（同首帧视频）
- 只锚首尾帧 → 按 **FL2VA** 写（同首尾视频）
- **锚点 ≥ 3（含中间关键帧）或有多个镜头 → 按 Ref2VA 全参考模式写**（六部分结构同参考视频），与官方 `video_minimax_h3_multiframe_reference` 模板一致

写法：

1. **FL2VA 模式**首行写对齐指令：`参考图片与目标视频的对齐方式 — <Picture 1>（来自 [Shot 1]）对齐目标视频的 0.00 秒位置；<Picture N> 对齐目标视频的 S.SS 秒位置。`，空一行后写三个核心字段
2. **Ref2VA 模式**在 detailed_description 的每个镜头首句点名锚点：`[Shot N] At S.SS 锚定在 <Picture N> 所确立的…`

对齐指令**逐条点名每一个已填槽位**，时间格式 `S.SS`（两位小数）：**首帧固定写 `0.00`**；**中间帧直接取该列「关键帧n所在秒数」的值**（提示词里的时点与工作流的锚定帧由同一个数字驱动，无需按帧号反推）；**尾帧固定写末帧时刻 `(length − 1) / 24`**（15 秒档 = `15.04`，由 `视频秒数` 吸附后的 `length` 决定，表里不填秒数）；**未填槽位不写入对齐指令**。integrated_multimodal_description / detailed_description 在对应时点插入 `<Picture N>` 引用：首次出现写「标签 + 完整画面特征描述」落地，后续镜头继续使用同一标签。

**`<Picture N>` 编号规则（最易错的一条）**：`<Picture N>` 的 N 是**该图在非空参考图里的连续排位**，**不是表里的槽位号**——官方 ref2va 对非空参考图逐张累加编号（`comfy/text_encoders/minimax.py` 中 `counters["image"] += 1` 后写出 `<Picture %d>`），空槽在 `comfy_extras/nodes_minimax_h3.py` 里被 `if img is None: continue` 跳过。故：首帧 = `<Picture 1>`；第 i 个中间帧 = `<Picture i+1>`（**中间帧必须从第 2 槽起连续填写**，这样槽位号与排位号才恰好相同）；**尾帧 = `<Picture 锚点数>`**——尾帧虽然固定在第 9 槽，提示词里写的是它的排位号（3 个锚点时为 `<Picture 3>`，**不是** `<Picture 9>`；写 `<Picture 9>` 会指向一张不存在的参考图）。

#### 关键帧视频 硬性约束（违反即失败或画面崩坏）

1. **首帧填第 1 槽、尾帧填第 9 槽（两端槽位固定，都应填写），中间帧从第 2 槽起连续填写、中间严禁留空**。留空的槽位输出 `None`（不锚点、不生成引导块，也不影响其余槽位的定位），但**中间留空会使提示词里的 `<Picture N>` 排位号与实际参考错位**（同「场景参考图与 H3 运镜实测经验」第六条）
2. **相邻锚点间隔 ≥ 1.5 秒**（官方 multiframe 演示锚点为 0.00 / 1.5 / 3.0 / 5.0 秒，1.5 秒为工程红线）；推荐间隔 **2.5 秒**（多镜头节奏），故 `视频秒数 ≈ (锚点数 − 1) × 1.5 ~ (锚点数 − 1) × 2.5`
3. **9 个槽位用满要求视频 ≥ 12 秒**（8 段间隔 × 1.5 秒），按推荐密度则应配 **13.5 ~ 15 秒**；单段合法上限为 **15.08 秒（362 帧）**，故 9 锚点的实用区间是 **12 ~ 15 秒**（15 秒 = 362 帧，间隔 1.875 秒）
4. **锚点必须落在已生成时长内**：中间帧的帧索引算式以吸附后 `length − 1` 为上限钳制（填负数则夹到 0），不会越界；首帧恒钉第 0 帧、尾帧恒钉第 `length − 1` 帧，天然不越界；秒数为空的槽位在引导节点里直接透传、不校验帧索引
5. **引导图对文本编码器不可见**：官方 `MiniMaxH3AddGuide` 只固定帧构图，提示词无法以 `<Picture N>` 引用它（官方 multiframe 模板里 `<Picture 2/3/4>` 就是这样悬空引用——那 3 张只接了引导、只有首帧进了 `ref_images`）。要让提示词引用某张关键帧，该图**必须同时进入 `ref_images` 通道**；0043 工作流因此把每个槽位**同时**接入 `MiniMaxH3ReferenceToVideo.ref_image_0` ~ `ref_image_8` 与对应引导节点
6. **空槽必须走 None 安全的引导节点**：官方 `MiniMaxH3AddGuide` 在 image 与 audio 同为 `None` 时直接抛 `ValueError`（不像 `MiniMaxH3ReferenceToVideo` 有 `if img is None: continue` 兜底），而数据表空槽按「可选输入惯例」输出 `None`、引擎又把它原样传给下游——所以 0043 的 9 路引导一律用自研 **`FallingTSH3AddGuide`**（空则原样透传 `positive`，等价于该槽无锚点），**官方引导节点不能直接串联成链**
7. **锚点图必须来自同一场景的一致性画面**：互相矛盾的关键帧是互相冲突的条件，会使模型在矛盾间摇摆（家具漂移、凭空增减物件），参见「场景参考图与 H3 运镜实测经验」第一条

**帧数换算**：总帧数 `length` 由 `视频秒数` 按 17k+5 网格向上吸附，单段合法 **124 ~ 362 帧**（5.17 ~ 15.08 秒），15 秒 = 362 帧。帧索引落点：**首帧 = 第 0 帧**（固定）；**第 n 个中间帧 = `max(0, min(round(关键帧n所在秒数 × 24), length − 1))`**；**尾帧 = 第 `length − 1` 帧**（固定）。以 `视频秒数 = 15` 为例：`length = 362`（实际时长 15.083 秒），尾帧落在第 361 帧 = `15.04` 秒——**提示词里的尾帧时点要写 `15.04`，写 `15` 会指向第 360 帧**（末帧时刻恒为 `(length − 1) / 24`，改 `视频秒数` 时必须同步改提示词里的尾帧时点）。

#### ⚠️ 参考视频的镜头顺序：散文定不住；硬锚点能钉死，但**非必要不加**（实测）

参考视频走 Ref2VA，`ref_images` 里的图**没有时间位置** —— 官方只对非空参考图逐张编号成 `<Picture N>`，
从不说它该出现在第几秒。所以在 `detailed_description` 里写时间码、在 `summary` 里写死镜头先后，
都只是**建议**：哪张参考图对应的动作写得越活，它就越容易被提到视频开头。

本机实测（`0044_参考视频` 第 1 行，**当时**的行 ID 为 `00001_书房开场四镜`、现为 `00001_书房开场`；4 轮只改提示词 + 2 轮加硬锚点）：
「让 `[Shot 2]` 的手部敲击灵动」这件事本身成立，但**只要把敲击写活，`<Picture 5>` 的手部特写
就会被搬到 `[Shot 1]` 的时段里**（4/4 复现）；把 `[Shot 1]` 逐字还原、只改 `[Shot 2]` 也一样跑偏；
在 `[Shot 1]` 里用否定句禁止切特写同样无效（H3 不遵守否定式）。

**结论与做法**：

- **⚠️ 经验（2026-10-01）：不加硬锚点，效果更好。** 硬锚点虽能把顺序／时长钉死，但观感不如纯软参考；
  **默认不要上锚点**，只在「顺序／时长必须钉死、散文反复定不住」时才用（`0044_参考视频` 已据此改回无锚点通用版）；
- 写参考视频表时时间码照写（它对模型仍是有效引导），但**不要指望它把镜头顺序钉住**；
- 确实要钉死时，才在**工作流**里给关键帧上硬锚点（`FallingTSH3AddGuide` 的 `frame_idx`），
  且每张锚点图必须**同时**进 `ref_images` 通道（否则提示词引用不到它，见上文「硬性约束」第 5 条）；
- **同一张图钉两次 = 定义区间**（例：手部特写钉在 7.0s 与 10.5s，中间就不会被别的镜头插回来）；
- 接线、帧号换算、「`vae` 必需 / `audio_vae` 仅在锚定音频时需要」、该节点无法满足的一条布局例外，
  以及验证方法（抽锚点帧与参考图逐格比对），见外部技能 `comfyui-workflow-runner` 的
  `references/h3-shot-order-anchoring.md`。

**反面提示**：把主体的动作写活本身是对的，但要预期它会把对应参考图提前用掉。若该参考图的镜头
本该在后面，**先权衡**：能接受位置漂移就别上锚点（不加锚点效果更好）；确实必须钉死时才补锚点再写动作，
否则会白跑一轮。

### 建模视频（人物一致性链 0013 / 0014 / 0015）

1. **必须显式否定参考图的版面元素**：`0011` 人物资产图是**三视图**（2026-10-07 起人物回归三视图，左正 / 中侧 / 右后并排），

   提示词里必须写
   「参考图自身绝不会出现在画面里，目标视频中完全不得出现它的白边、边框、拼贴接缝、水印、字幕、字母、标注、数字与任何界面元素……全程画面完全无字」，

1b. **服装与体型以 0011 为准**：`0011` 人物三视图已把这一身衣着与体型写全，`0013_首图建模.md` 的提示词只需**照抄同一套服装与体型设定并要求全程不变**，不要在 0013 另起一套（两处打架会造成视频里的衣服与三视图对不上）。
2. **禁把分辨率数字写进提示词**；比例只走 `宽度` / `高度` 两列。
3. **参考图永不上采样**（`ref_image_size` 短边上限 2048、never upscaled）⇒ 脸必须来自 `0011` 的
   高分辨率独立生成，**绝不能**从全身小图裁脸。`0014` 的 `ref_image_size` 固定 `max`。
4. `0014` 的参考图**最多 9 张**（端口前缀 `ref_image_0`–`ref_image_8`），视频最多 3 条（内部经
   `FallingTSVideoComponents` 拆帧）。H3 **无 mask / 区域 / box / 坐标 / 深度 / 姿态端口** ⇒ 参考只是
   全局身份与风格条件，**不存在区域级拼接**。
5. 负向约束写在提示词的正文中（`no background music` / `无背景音乐`），H3 视频侧没有独立的负词列。

## 第三部分 场景视频

> 尺寸与语言规范见本文档第一部分（H3 canvas 桶与「提示词正文一律中文」）。场景方位词（面/侧/边）与画面边缘词（缘）的定义见第一部分的「画面术语定义」。镜头运动术语见第五部分。本部分与第二部分的视频类同属 H3 视频，只是对象是场景而非人物/主体。

### 场景类公共要求（文生场景 / 首帧场景 / 参考场景 通用）

**旋转与视角硬性要求**：场景视频以**平视视角**（镜头高度与视线齐平）完成 **360 度顺时针完整旋转**，画面以场景中央为轴从起始正面开始顺时针旋转一周，旋转过程连贯匀速一气呵成，**角速度全程恒定、一次连续转完**；镜头转到 **90°、180°、270°** 三个方位时把该方向看到的场景内容交代清楚，随后继续匀速转向，最终回旋至起始正面方向，起点终点画面完整衔接成**闭合环绕**。各方位视角之外另补一份 **全图** 俯瞰整体描述（按「全图方位」要求，用俯视平面图方位词逐区域点名整体布局），使场景还能从平面视角一并还原。

**为什么不停顿（2026-09-13 本机实测）**：在 90°/180°/270° 各停顿 0.5 秒会让模型在停顿点卸力、停顿结束后再猛冲追赶，表现为物件在画面里凭空出现与位移。同一场景、同一随机种子的 A/B 实测：运动逐帧变化量（pblack）标准差 **15.9 → 8.5**（去停顿后匀速性提升 46.5%），最小值从 **15**（猛冲段）回到 **30**；拼图核对显示带停顿版会在旋转中段长出首帧里根本不存在的落地灯、成堆纸箱与墙面搁架。**提示词里用正面陈述表达不停顿**（如「角速度自始至终保持不变」「整圈一次连续转完」），不要写「不停顿」「不加速」这类否定式——H3 对否定式指令不可靠。

**镜头旋转时，必须保持物体位置与空间关系全程一致，画面单镜连贯**，使 360° 环绕稳定还原整个场景。

**场景空间描述要求**：必须完整交代场景空间的大小（面积或尺度）与**整体布局**，并按**各方位视角逐一描写该方向看到的场景内容**——起始正面（0°）、转到 90° 时正对的正右方、转到 180° 时正对的正后方、转到 270° 时正对的正左方、回旋回归正面，五个节点逐一交代当前方向上的场景内容（物件、墙面、灯光、空间细节及其相互位置关系），用方位词（前/前右/右/右后/后/后左/左/左前）点名每件物件的空间位置，使 360° 环绕镜头能稳定、无遗漏地还原整个场景；保持角色、物体与空间关系一致。

**各方位视角画面描述要求（场景类通用）**：镜头转到的每个方位均须把该方向看到的画面内容交代清楚（该方位下的物件、墙面、灯光与空间细节），让模型据此逐方位还原画面。各方位之间的**过渡界面衔接一致**为硬性要求（顺时针 前→前右→右→右后→后→后左→左→左前，每个视角画面的右缘与下一视角画面的左缘是同一物理区域的延续）：
- **前面**右边 与 **前右**左边 重叠
- **前右**右边 与 **右面**左边 重叠
- **右面**右边 与 **右后**左边 重叠
- **右后**右边 与 **后面**左边 重叠
- **后面**右边 与 **后左**左边 重叠
- **后左**右边 与 **左面**左边 重叠
- **左面**右边 与 **左前**左边 重叠
- **左前**右边 与 **前面**左边 重叠

重叠区域内的内容（物件、灯光、空间元素）在相邻方位视角画面中互相衔接一致——同一物理区域是前后视角画面边缘处的同一延续（90° 处的正右面衔接前方正面的右缘，180° 处的正后面衔接右面的右缘，270° 处的正左面衔接后面的左缘，回旋正面衔接左前右缘与起始正面左缘）；描述与生成均按此关系交叉印证，360° 环绕每一面稳定、无遗漏地还原。

**参考视角顺序（八方位八视图）硬性要求**：给 H3 提供八方位视角参考图时，必须按**旋转顺序**提供并逐张点名方位，顺序固定为俯视视角下的**顺时针「前→前右→右→右后→后→后左→左→左前」**（与 0033 OrbitSheets 参考板视角顺序一致），其中 **90°、180°、270° 三张主格对应正右、正后、正左三个方位视角**，其余斜向视角为旋转过渡帧。参考段须逐张点明相邻视角为绕主体旋转 45° 的机位（如「图1=正前方视角；图2=顺时针转 45° 的前右视角；图3=再转 45° 的右侧视角；图4=再转 45° 的右后视角；图5=再转 45° 的后方视角；图6=再转 45° 的后左视角；图7=再转 45° 的左侧视角；图8=再转 45° 的左前视角」），并声明「目标镜头沿同一方向顺时针旋转，过渡角度取相邻两图之间的中间视角」。图序是给模型的旋转轨道暗示，必须与目标镜头旋转方向一致，方向相悖会干扰空间连贯（尤其 360° 环绕）；静止/无旋转镜头固定沿用默认顺时针顺序，故事内全局保持一致。

#### 参考场景 提示词提取规范

场景提示词按 **Ref2VA 全参考模式** 规范书写，包含六部分，顺序固定：

1. **subject_definitions**：定义被参考内容及其参考标签，使用 `<Subject N>`、`<Picture N>`、`<Video N>`、`<Audio N>` 四类标签。`<Subject N>` 用于可复用内容（场景、地形、环境、建筑、道具、风格），`<Picture N>` 用于充当帧锚点的图片，`<Video N>` 用于剪辑、续写或参考节奏的源视频，`<Audio N>` 用于被复制或引用的音频
2. **summary**：以 `[任务类型]` 前缀开头（如 `[reference generation]`、`[video continuation]`、`[audio reuse]`），概括目标场景与主要参考关系
3. **retention_analysis**：逐项描述被参考内容如何保留、转移或复用。可见内容用 `fully_preserved` / `partially_preserved` / `attribute_transfer` / `weak_reference`，音频用 `fully_copy` / `partially_copy` / `reference` / `weak_reference`
4. **detailed_description**：按播放顺序逐镜头描述场景画面、运镜、空间布局与声音，在首帧、尾帧、分镜等作用位置插入参考标签
5. **overall_soundscape**：概括环境氛围声与物理音效
6. **non_diegetic_music**：描述仅观众可闻的背景音乐

参考标签一旦赋予某段内容，在全部六部分中始终表示同一含义，不得换义或遗漏。**detailed_description 中必须持续使用参考标签，不得换成纯文字指代**：首次出现时写「标签 + 完整特征描述」落地到具体画面，后续镜头继续使用同一标签（无需重复定义），可配简略文字。标签是模型将画面内容与具体参考素材绑定的锚点，纯文字无法确定对应关系，尤其在多参考（≤9 图 + 3 视频 + 3 音频）时易串。

**Subject 三层绑定机制**：

1. **subject_definitions 登记**：文字描述内容并编号，建立「`<Subject N>` = 某内容」的映射关系
2. **detailed_description 首次出现落地**：写「标签 + 完整特征描述」，把编号真正绑定到具体画面特征。这一步是模型建立编号与画面对应关系的关键，只写编号不写特征会导致绑定变弱
3. **后续镜头纯引用**：直接使用同一标签引用即可，无需重复描述，可配简略文字

**图片编号按输入顺序、内容定位靠文字**：`<Picture N>` 按参考图输入顺序编号（images → videos → audio 各类型独立编号），与画面内位置无关；一张图内多个元素归属哪个 Subject 必须用文字点名（必要时用方位词辅助），模型不会自动按画面左右分配。**多视图参考（八方位视角图）必须按旋转顺序输入并在参考段逐张点名方位，顺序遵循「场景类公共要求 → 参考视角顺序」硬性规定**（默认俯视顺时针「前→前右→右→右后→后→后左→左→左前」，方向随目标镜头旋转方向对齐）。

### 场景参考图与 H3 运镜实测经验（2026-09-11 本机实测）

以下结论均来自本机实测（RTX 4060 8GB / ComfyUI 0.35.0 / 4 步 turbo LoRA），写入规范以免重复踩坑。

**一、参考图的跨图一致性是硬前提，优先级高于视角精确度**

- 逐格独立生成的参考图（如 Qwen-Image-Edit 多视角）**必然出现结构性漂移**：实测同一套四图中，同一只斗柜一处 3 抽屉、一处 4 抽屉；衣帽架一处 2 个、一处 1 个；琴叶榕 2 盆对 1 盆；音箱一处并排、一处叠放
- Ref2VA 把所有参考图一并作为条件，**互相矛盾的图 = 互相冲突的条件**；模型没有裁决能力，只能在矛盾间摇摆，表现为家具漂移、凭空多出或减少物件
- **唯一可靠来源**：参考图必须取自**同一段视频的选帧**（如同一镜头运镜视频），天然满足时间一致性
- **禁止**把逐格独立生成的多视角图直接当作多视图参考

**二、绝不在提示词里描述参考图自身的版式与标注**

- 实测：提示词写入「一张 2×2 拼合的图片」「每格左上角印有一行白色粗体带黑描边的中文方位标注」之后，模型**把分格线与方位文字直接画进了画面**（reference leakage），须两轮修正才清除
- **正确写法**：只说明参考图「提供了哪几个方向的视图、用于确定什么」；并补一句正面保护句——「参考图只是布局依据，它本身不会出现在画面中，其中的任何分格、边框、拼贴痕迹或注记文字也都不会出现在画面里」
- 参考图若已烧录文字标注，除提示词排除外，更根本的是在生成端就不烧字（OrbitSheets 的 `label_prefix` 应清空）

**三、离散参考视角会导致「吸附」，且提示词改不动**

- 实测（4 个正交参考视角、12 秒 360°）：镜头位于参考方位时的帧间运动量 pblack 均值 **71.6**，偏离 30° 处仅 **44.0** —— 靠近参考视角时**慢 63%**，即模型在参考姿态上停住、在中间猛冲
- 机理：模型把离散参考姿态当成「要对齐的目标」。**锚点越稀吸附越强**；把锚点加密只是把「大锯齿」变成「密锯齿」，并未消除
- 该现象**无法用提示词修正**（冲突在条件层，语言层盖不住）
- **治本**：把参考从 cross-attention 软条件升级为**首帧硬锚点**——分段生成，每段约 90°、用对应方向的图作为首帧，再拼接

**四、否定式指令在 H3 上不可靠**

- 实测：「不会停住、不会吸附、不要加速、不要翻滚」这类否定式惩罚**全部无效**
- 应按 H3 官方指南改为**正面陈述**：与其写「镜头保持水平不要倾斜」，不如写「地平线保持水平，墙与立柱的垂直线保持垂直，地板沿画面底部、天花板沿画面顶部」

**五、H3 连续环绕有速率上限**

- H3 官方示例写法：360° 环绕用 **15 秒**（= 24°/s），措辞为「one single continuous 360 degree orbital move, clockwise, at a slow constant rate, completing exactly one full rotation across fifteen seconds」
- 实测安全上限约 **40°/s**，超过即**翻滚**（画面倾斜、卷向天花板、地板格铺满画面）
- 完整 360° 至少需要 **9 秒 / 220+ 帧**；124 帧（5.17 秒）只容得下约 180°
- 结论：**短镜头不要要求完整 360°**——要么给足时长，要么改用多镜头硬切

**六、多视图参考的编号按「有效参考」重新计数**

- `<Picture N>` 的序号按**非空参考**从 1 连续计数，不是按 md 表的列号
- 因此参考必须**从第 1 列起连续填写**，中间留空会造成提示词编号与实际参考不符
- 关键帧视频的尾帧虽然固定填在第 9 槽，它的排位号仍是**锚点数**（非空图总数），提示词里要写 `<Picture 锚点数>` 而非 `<Picture 9>`（见第二部分的「关键帧视频 → 编号规则」）

**七、场景类视频的两种取法（实测取舍）**

| 方式 | 优点 | 代价 |
| :--- | :--- | :--- |
| **多镜头硬切**（OrbitSheets 默认） | 每个视角都是静止机位，**结构上不可能翻滚**；视角必然落位 | 背面/侧面是模型「编」的，可能与锚点图布局不符 |
| **单镜连续旋转** | 每帧只延续上一帧，空间关系连续 | 超过速率上限必翻滚；参考视角处吸附；长片一致性差 |

选法：**要参考板、要视角齐全 → 硬切**；**要一段连续的空间感 → 连续旋转，但必须控速在 40°/s 内、时长足够、且参考图来源一致**

**八、首帧只拍到一面墙时，背面必须有独立锚点（2026-09-27 实测）**

- **病灶**：首帧场景（I2VA）的首帧只拍得到前面墙时，若提示词把转到的 180° 反写成「后墙只由同色墙面、浅色木地板与深色天花板构成」，模型会把那一面拍成**空房**——实测 0031 旧提示词 10 秒 360°（832×480 / 243 帧）的 t=5.0s 帧是纯空墙+空地板，t=6.25s 凭空长出一张不存在的小桌与一只白色箱体，整间房在旋转中段一度变空
- **修法**：给**每面墙各钉一个独有锚点**，模型靠锚点认方位（本例 前=大窗+窗帘+书桌椅 / 右=深红棕抽屉柜+柜顶白盆绿植 / 后=一扇关着的深色木门+门框+门把手+门边开关面板 / 左=浅木框黑板+深木矮几+两盆盆栽），再写明四角以直角相接、踢脚线绕墙一圈、每件物件只经画幅左缘或右缘进出、四组锚点按前→右→后→左依次移到画幅中央
- **补的物件只挂在首帧拍不到的那面墙上**：首帧（硬锚点）已拍到的墙面一律照旧，否则与锚点图冲突（首帧里右墙后段本来就是空墙，就让它保持空）
- **复算结果**（同工作流、同首帧、仅换新提示词）：t=5.0s 得到门扇+门框+金属把手+门边白色开关面板，旋转中不再变空、不再出现新杂物，t=9.8s 构图回到 0.0s 的首帧；前后两版视频存 `backups\backup-00001_书房旋镜视频-20260927-后墙补门{前,后}.mp4`
- **边界**：门写「关着」并全程保持关着（开门会把走廊带进画面）；像素级闭环做不到，能保证的是**同一构图与同一组锚点**回到起点

**九、拍不到的墙面：房门 + 少量简单物件就够，别写成长清单（2026-09-27 实测定稿）**

- **只补门不够**：门解决了「180° 是空房」，但两侧墙后段仍是大片空白 → 四面墙都要点名，每面墙写明「拍得到的照首帧原样 / 拍不到的那一段放什么」
- **但补陈设要克制**：把整面后墙铺满（高书架+收纳盒+伞架雨伞+挂钟+矮边柜+书+茶盘茶杯+落地灯+扶手椅一组阅读角）虽然每面都有锚点、闭环也成立，但描述过长，且件数越多 H3 越容易翻倍（实测把「一张扶手椅」画成两张、挂钟被复制两处）。**定稿口径 = 每块空白墙面 1 件简单家具 + 后墙一扇门**
- **本例（书房）定稿分配**（提示词 1723 字符，比只写门的旧版 2285 还短）：右墙后段=一只木质矮书架（层板上十几本书）；左墙后段=一盆白盆绿植；后墙=中部偏右一扇关着的深色木门（门框/金属把手/木门槛/门边白色开关面板）+门左侧一只木质矮边柜（柜面一小摞书）+门右侧墙面一只圆形白色挂钟；其余墙面只写「深蓝灰墙面与深棕色踢脚线」
- **复算结果**：90°/180°/270° 每面都有实体锚点、无空墙，t=5.0s 的后墙是「矮边柜—木门—开关—挂钟」的简洁组合，t=9.9s 构图回到 0.0s 首帧；四版视频存 `backups\backup-00001_书房旋镜视频-20260927-{后墙补门后,补书房后段陈设后,座位清点后,精简陈设后}.mp4`
- **数量靠正面清单压**：需要保证"只有一件/一只"时，用正面清点句（「墙面上的挂钟只有后墙门右侧那一只」），不用否定句
- **硬约束不变**：首帧（硬锚点）里看得见的前面墙与两侧墙**前段**一律照原样，新物件只落在首帧拍不到的墙面（后墙与两侧墙后段）

### 静态镜头类别（依据景别）

影视专业教材（如《电影摄影画面创作》）与拍摄脚本中，依据**景别**（被摄主体在画面中所占比例）划分，静态镜头语言存在完整的**九级光谱**，从最宏观到最微观：

**第一层级：环境与空间（侧重「环境」）**

1. **大远景（Extreme Long Shot）**：人物在画面中仅占极小比例（通常小于画框高度的 1/4），甚至几乎看不清。极力弱化人物，强调环境的广袤、历史的厚重或自然的压迫感；固定机位如同一幅静态油画，让观众凝视人类在宏大空间中的渺小
2. **远景（Long Shot）**：人物约占画框高度的 1/2，能看到全身，但环境依然是绝对主体。固定机位下常做「交代性镜头」，展示故事发生的具体大环境（城市、战场），环境内的风吹草动都会被放大，起定场作用
3. **全景（Full Shot）**：人物从头到脚完整纳入画面，同时保留一定的环境背景。人物与环境「平分秋色」，可完整审视全身形体动作（走路姿态、衣着服饰），人物在固定框架内运动产生清晰的舞台感

**第二层级：人物与动作（侧重「肢体」）**

4. **中全景（Medium Full Shot，或称「七分景」「牛仔景」）**：画面下边框卡在人物**膝盖稍上方**。看不到脚，固定镜头强制放大上半身肢体语言；经典西部片用此景别拍拔枪，静态机位聚焦腰腹核心力量的发力瞬间
5. **中景（Medium Shot）**：画面下边框卡在人物**腰部**上下。叙事中最中性的镜头，兼顾手势动作（手部信息）和面部表情，常用于双人对话或摆弄道具（写字、倒水）；固定机位保证演员调度（走位）的准确呈现
6. **中近景（Medium Close-Up，或称「胸景」）**：画面下边框卡在人物**胸部**（约第三颗纽扣处）。静态镜头中最常用、最考验演员的景别——裁掉手部动作，完全靠**眼神和微表情**传递信息，面部的每一丝肌肉抽动都会被捕捉，适合传递暧昧、犹豫或隐忍的情绪

**第三层级：表情与细节（侧重「心理」）**

7. **近景（Close-up）**：画面下边框卡在人物**肩部**，头部占据画面主体。压缩空间感，增强观众与角色间的心理亲密度；静态拍摄制造「凝视」感，让观众觉得在直视角色灵魂
8. **特写（Close Up，狭义特写）**：人物整个**头部**，或某件物品充满大半个画面。固定不动产生强烈的「静止注视」效应，带有「审视」和「强调」的权力感，常用于揭示重要物件（如打开的信封）
9. **大特写（Extreme Close-Up）**：只表现对象的**局部**（一只眼睛、半张嘴唇、扣动扳机的手指、瞳孔的倒影）。画面内几乎没有空间纵深且机位完全静止，视觉张力全部来源于构图和纹理细节；常用于极致的高潮情绪（惊恐到凝固的瞳孔）或关键悬念（炸药倒计时的秒表跳动）

**景别构图变体（画内人物数量微调，仍属上述 9 级框架内）**：

- **单人静态镜头**：聚焦一个人，孤寂感或专注感
- **双人静态镜头**：固定画框内呈现两人互动，通常取「中景」或「中近景」，显示人物间的物理距离（亲疏关系）
- **过肩静态镜头（Over-the-Shoulder Static Shot）**：「中近景」的特殊构图，前景含模糊的后脑和肩膀。固定不动时极强地建立正反打对话中的「对峙空间感」，让观众感觉坐在现场旁观对话

**逻辑澄清**：景别决定「画面里装什么」，静态（固定不动）决定「画面怎么被观看」。9 种景别全部静态时，「时间」成为最核心的变量——同一中景静态停留 2 秒是「客观交代」，停留 10 秒就变成「压抑或审视」。

### 静态机位角度（拍摄高度与方向，机位不动）

景别之外，静态镜头的机位角度决定「从什么位置看」。机位不动时，角度即全部空间关系：

1. **平视（Eye Level）**：镜头高度与视线齐平，最客观中立，观众与人物平起平坐
2. **俯视（High Angle）**：机位高于被摄主体向下拍。人物显得弱小、被动、被掌控；环境压过人物
3. **仰视（Low Angle）**：机位低于被摄主体向上拍。人物显得高大、威严、有压迫感；天花板/天空入画
4. **顶视（Overhead / Top-Down）**：机位在被摄主体正上方垂直向下拍。纯平面构图，凸显布局与几何（如桌面物品排列、人物在地面的位置关系）
5. **鸟瞰（Bird's Eye）**：极高处的俯瞰，接近地图视角，展现宏大地理与整体空间结构
6. **底视（Worm's Eye）**：贴近地面极低处仰拍，几乎以地面生物视角看世界，强化渺小与仰望

### 静态构图形式（取景布局，机位不动）

构图画框内的元素如何摆放，决定静态画面的平衡感与视线引导：

1. **对称构图**：画面左右或上下镜像对称，稳定、庄重、仪式感（如宫殿、走廊、正对门框）
2. **中心构图**：主体置于画面正中央，视觉焦点最直接，常配合对称产生压迫或凝视感
3. **三分法构图（Rule of Thirds）**：画面横竖各分三等份，主体或地平线落在交点上，自然、耐看、经典
4. **框架构图（Foreground Framing）**：前景的门框、窗框、拱门、树枝等形成画中画，框住主体，产生偷窥感与空间纵深
5. **引导线构图**：画面中的线条（道路、栏杆、桌沿、光线）把视线引向主体，强化纵深与方向
6. **对角线构图**：主体或线条沿画面对角线排布，产生动感、张力与不稳定感
7. **前景遮挡/层次**：前景虚化或遮挡物体叠在主体之前，制造空间层次与窥视感
8. **留白/负空间**：主体周围大片空白（墙面、天空、水面），孤独感、呼吸感、极简
9. **满框构图**：主体几乎充满整个画面，没有环境余量，压迫、专注、窒息感

### 静态光学特性（焦点/焦距/景深，机位与镜头不动）

不移动机位、不变化焦距时的光学状态，同样影响画面观感：

1. **浅景深/大光圈虚化**：焦点清晰、前后景虚化（焦外 Bokeh），突出主体，隔离环境（特写、人像常用）
2. **深景深**：从前景到远景全部清晰，适合交代环境全貌与群体关系
3. **长焦压缩（Telephoto Compression）**：长焦镜头下远近物体空间距离被压缩，背景被拉近放大，层次扁平
4. **广角夸张（Wide-Angle Distortion）**：广角镜头边缘畸变、空间纵深夸大，靠近镜头的主体被放大变形
5. **微距（Macro）**：极近距离拍摄微小细节（纹理、水滴、瞳孔、织物），呈现肉眼难见的微观世界
6. **焦点锁定/泛焦（Pan Focus）**：全画面均匀清晰，无主次虚化，纪实、客观、冷淡

### 静态镜头功能（叙事职能，机位不动）

按镜头在叙事中的任务划分，静态机位同样承担特定职能：

1. **定场镜头（Establishing Shot）**：开场用全景/远景交代地点、时间、环境氛围，建立故事发生地（常为全景级别）
2. **插入镜头（Insert Shot）**：切入画面中某细节的放大（如桌上的纸条、手里的钥匙），强调信息或情绪
3. **切出镜头（Cutaway）**：切离主场景到相关次要画面（如旁观者的反应、窗外的雨），缓冲节奏或补充信息
4. **反应镜头（Reaction Shot）**：静态拍某人的表情/身体反应（多为近景/特写），传递对前情的情绪回应
5. **空镜/静物镜头（Static Object Shot）**：无人物的静物或环境空镜，抒情、留白、象征（对应动态板块的「空镜头」，此处为机位不动版）

### 动态镜头类别（依据镜头运动）

动态镜头的本质是**打破「摄影机三不动」（机位、光轴、焦距固定）**。

**四类基础运动（一切动态镜头都是这四类的单独使用或自由组合）**：

| 基础类别 | 什么在动 | 画面里变的是什么 | 术语（写入提示词用英文） | 所在板块 |
| :--- | :--- | :--- | :--- | :--- |
| **① 角运动（自身球形旋转）** | 机位不动，镜头绕自身节点做球形转动（Pan / Tilt / Roll 三轴） | 视线方向被「扫过」，透视关系不变 | pan / tilt / roll / whip pan | 板块二 |
| **② 面运动（三维整体位移）** | 机位在三维空间整体移动（X 横 / Y 竖 / Z 纵深，含曲线轨迹） | 视点位置改变，前后景出现视差，透视关系改变 | dolly in / out、truck、pedestal、track、orbit | 板块一 |
| **③ 概念级尺度运动** | 由数字或后期整体缩放，跨越现实尺度 | 从量子到星系的连续尺度跨越，不受物理镜头限制 | cosmic zoom / quantum zoom / digital zoom | 板块三 |
| **④ 焦点与焦距运动** | 机位与角运动均不动，只改镜头内部光学（焦点平面、焦距） | 变的是「哪一层清晰」或「整体放大率」，透视关系不变 | follow focus / rack focus / focus pull / zoom | **板块四** |

**四类的分界只需一句话**：① 只转视线、② 只挪视点、③ 跨越尺度、④ 只动光学。**四者可自由组合**，组合规则四条：

1. **组合 = 叠加，不是替换**：写复合镜头时必须能拆回基础分量（「推镜头 + 反向变焦」= ②面运动 + ④焦距运动 = 滑动变焦）；
2. **同类叠加是加强，异类叠加是对撞**：同类如推 + 升（斜向推进）、Pan + Tilt（综合摇）；异类如 ②向前 + ④向外（空间扭曲）、①摇 + ④变焦（扫视中拉近）；
3. **异类组合必须写明主从与同步关系**（谁先动、谁跟谁、同速还是反向）；只写「推进并变焦」会被模型随机分配方向与速度；
4. **①与②在同一瞬间互斥**：同一颗镜头要么机身位移、要么原地转动；两者同时出现即属组合运动，必须两个分量都写清。

**画面边缘（缘）判定法（判断四类基础运动的最快口径，2026-10-08 定）**：不看机位，只看画面内容从哪条边缘进出、进出快慢，即可反推运动类别。八缘 = 左缘 / 左上缘 / 上缘 / 右上缘 / 右缘 / 右下缘 / 下缘 / 左下缘（四缘 = 左 / 上 / 右 / 下，四角缘为斜向进出）。

| 画面现象（缘的进出） | 判定 | 术语 |
| :--- | :--- | :--- |
| 内容从**右缘进入、左缘移出**（地平线水平） | 镜头顺时针旋转 | ① pan right |
| 内容从**左缘进入、右缘移出** | 镜头逆时针旋转 | ① pan left |
| 内容从**上缘进入、下缘移出** | 镜头上仰 | ① tilt up |
| 内容从**下缘进入、上缘移出** | 镜头下俯 | ① tilt down |
| 内容从**四缘同时向画面中心进入**（画面范围变大） | 视点后退 | ② dolly out（拉镜） |
| 内容从**画面中心向四缘移出**（画面范围变小） | 视点前进 | ② dolly in（推镜） |
| 左右两缘进出**速度不等**（如左缘移出快、右缘进入慢） | 拉镜叠加横移 | ② 侧拉镜 / 斜向 dolly |
| 四缘同进同出、**前后景无视差** | 只动光学 | ④ optical zoom |

> 方向口径与第三部分的「12 秒八镜 360° 旋镜定式」一致（俯视顺时针；顺时针时画面内容向左缘移出、从右缘进入）。**进还是出**定推拉、**快慢是否对称**定侧拉、**有无视差**区分物理推拉与光学变焦。
按物理与逻辑层级，下文细分**十一板块**——板块一~四即上述四类基础运动，板块五~十一是按速率、设备、后期、叙事、参考系与组合划分的扩展类别：

**板块一：三维空间中的宏观位移运动（②面运动，机位整体移动）**

1. **推镜头**：摄影机沿 Z 轴（纵深）向前移动靠近被摄主体。产生逐渐深入、聚焦、紧张或揭示真相的心理效果
2. **拉镜头**：摄影机沿 Z 轴（纵深）向后移动远离被摄主体。产生疏离、释放、展现环境或结局感
3. **移镜头**：摄影机沿 X 轴（左右）或 Y 轴（垂直）平移。产生强烈的动态感和节奏感
4. **跟镜头**：摄影机跟随运动主体同步移动（前后左右跟随），保持主体在画面中的相对位置基本不变，连贯展示其动作与环境的关系
5. **升降镜头**：摄影机在 Y 轴（垂直）方向整体上升或下降。改变视点高度，展现空间纵深感或营造戏剧性（如从上帝视角降至凡人视角）
6. **环绕镜头**：摄影机沿弧形或圆形轨迹围绕被摄主体运动。产生 360 度的环绕审视感，全方位展示主体与环境的关系
7. **穿梭镜头**：摄影机穿越狭窄空间或障碍物（窗户、栏杆、缝隙、人群）拍摄。产生强烈的空间穿透感和速度感，引导视线深入场景
8. **螺旋环绕**：环绕运动叠加升降位移（围绕主体的圆形轨迹 + 持续上升或下降），形成螺旋线运动。产生「天旋地转」般的沉浸纵深，从低处螺旋升至高处可自然揭示全景（如从庭院螺旋升到屋顶）

**板块二：镜头自身的球形转动运动（光轴与角度变化）**

1. **摇镜头（Pan）**：镜头在水平方向（左右）摆动，扫视环境或连接两个物体
2. **俯仰镜头（Tilt）**：镜头在垂直方向（上下）摆动。Tilt Up（仰视）产生崇高、压迫感；Tilt Down（俯视）产生渺小、压抑感
3. **旋转镜头（Roll / Spin）**：镜头围绕光轴（Z 轴）旋转，画面地平线倾斜或翻转。产生眩晕、失重、混乱或不稳定的视觉效果
4. **荷兰角（Dutch Angle / Canted Angle）**：镜头刻意倾斜（Roll 的一种变体），画面水平线不平行于画框。产生不安、紧张、迷幻或世界颠倒感
5. **甩镜头（Whip Pan / Snap Pan）**：极快速的摇镜头（水平甩动），画面产生强烈动态模糊。用于快速转场、制造紧张感或视觉冲击
6. **综合摇镜**：同时进行 Pan 和 Tilt 的复合转动，实现任意方向的镜头弧线扫视
7. **桶滚（Barrel Roll）**：镜头绕光轴连续翻滚一整圈及以上（区别于小幅倾斜的 Roll 与荷兰角）。持续整圈翻转制造失重、坠落与失控感，FPV 穿越机与太空失重场景常用

**板块三：概念级尺度运动（③，由数字与后期实现的尺度跨越）**

1. **数字变焦/后期缩放**：数字后期中通过裁剪和放大实现，可自由控制尺度但会损失画质
2. **宇宙缩放（Cosmic Zoom）**：从微观粒子级别连续放大到星系乃至整个宇宙的尺度
3. **量子缩放（Quantum Zoom）**：进入量子领域的微观尺度，从宏观急剧缩小到亚原子级
4. **宏观缩放（Macro Zoom）**：从宏观物体连续拉到星系乃至宇宙尺度（与宇宙缩放互为反向）

> **边界（勿混写）**：真实镜头的**光学变焦**与**急推/急拉**靠镜头内部光学完成、机位不动，属 ④ 焦点与焦距运动（见板块四）；本板块只收「现实镜头拍不出、必须由数字或后期跨越尺度」的运动。

**板块四：焦点与焦距运动（④，机位与角运动均不动，只改镜头内部光学）**

**与 ②面运动的分水岭（写提示词必须先择一）**：**变焦**前后景比例不变（画面整体「平面放大」，**无视差**）；**推/拉镜头**前后景相对位置改变（**有视差**）。混写会让模型在两种运动之间摇摆。

1. **跟焦（Follow Focus）**：焦点平面持续跟随运动中的主体（走进走出、起身落座、来回踱步），主体始终清晰、其余层次随距离自然虚实变化——机位不动而焦点在纵深上追着主体跑
2. **变焦/移焦（Rack Focus / Focus Pull / Pull Focus）**：焦点在同一画面内的前后两个层次之间主动转移（从前景的茶杯转到后景的人脸），一次干净的转移就是一次叙事强调的交接；两个层次须预先在同一画面内叠置，转移前后各稳定停留
3. **多平面焦点接力（Multi-Plane Focus Rack）**：焦点依次经过三层以上纵深平面（前景遮挡物 → 中景人物 → 远景环境），像拉开抽屉逐层揭示信息
4. **泛焦↔浅焦切换（Deep Focus ↔ Shallow Focus Rack）**：同一镜头内改变**景深**而非只挪焦点——从全画面皆清的泛焦段落收到只剩一张脸清晰的浅焦段落，用「清晰范围」本身完成从客观交代到主观聚焦的收束
5. **失焦/脱焦（Defocus / Rack to Blur）**：主动把焦点拉离主体使画面溶成光斑（昏迷、耳鸣、闪回、主观恍惚）；反向即「由虚转实」的苏醒与揭示
6. **光学变焦推/拉（Zoom In / Zoom Out）**：改变焦距放大或缩小画面，**透视关系不变**（与推拉镜头的本质分界）；产生空间被压缩或拉伸的独特感受
7. **急推/急拉（Snap Zoom / Crash Zoom）**：快速变焦推拉，戏剧性强调或揭示（香港动作片、昆汀）
8. **变焦跟焦同步（Zoom Tracking / Focus Compensation）**：真实镜头变焦时焦点平面会随之漂移，须同步微调焦点维持主体清晰；画面表现为变焦全程主体「始终咬住」，不松不糊
9. **微距跟焦（Macro Focus Rack）**：在极高放大倍率下移焦（露珠 → 花瓣脉络 → 花蕊），毫米级焦点位移即产生跨越峡谷般的空间切换
10. **移轴焦平面（Scheimpflug / Tilt-Shift Focus）**：不改焦点距离而**转动焦平面倾角**，使斜向排布的两个物体同时清晰；反向使用可只留一条斜带清晰，制造微缩景观感
11. **焦点漂移（Focus Drift）**：焦点缓慢失守的过程本身作为情绪曲线（清晰到模糊的 3 秒），可配合变速镜头做「焦点追赶」
12. **焦点呼吸（Passive Focus Breathing）**：跟焦时镜片组位移带来的极小视觉缩放，属被动光学伪影（见板块七）

**提示词写法**：焦点运动一律**正面陈述**（「焦点落在后景的人物脸上」「清晰范围收窄到只剩一张脸」），不写「不要虚化」「别把脸拍糊」——否定式指令在 H3 上不可靠（见第三部分的「场景参考图与 H3 运镜实测经验」第四条）。

**板块五：按拍摄速率与时间轴划分的运动（时间维度的扩展类别，可叠加在①②④任一之上）**

1. **升格镜头**：以高于正常速率拍摄（如 48fps/96fps），放映时呈现慢动作。强调瞬间、抒发情感、营造梦幻感（含子弹时间的前置拍摄）
2. **降格镜头**：以低于正常速率拍摄（如 12fps），放映时呈现快动作。制造喜剧效果、压缩无聊时间或表现时光流逝
3. **倒放反向运动**：前期正常拍摄、后期时间轴逆向播放，产生违反物理定律的反向动态效果
4. **长镜头/一镜到底（Long Take / Sequence Shot）**：单个镜头长时间连续拍摄（可达数分钟），中间不剪切，完整承载时间流逝与空间连续。产生强烈的沉浸感、纪实感与仪式感，是时间维度的核心镜头（如开场长镜、走廊枪战长镜）
5. **定格镜头（Freeze Frame）**：画面时间在某一瞬间完全凝固（人物/物体静止不动，仅声效或旁白继续）。常用于强调关键瞬间、制造悬念或作为结尾句号
6. **变速镜头（Time Remap / Ramp）**：同一镜头内播放速度主动变化（先慢后快、先快后慢或中间急停），时间重映射。产生节奏操控感（如起跳瞬间变慢、落地后恢复正常速度）
7. **抽帧/步进（Step Printing）**：按间隔抽取中间帧（如每 3 帧取 1 帧），画面呈现不连贯的卡顿动画感。常用于梦境、记忆闪回或粗粝风格化

**板块六：按物理实现手段与支撑设备划分的运动（实现方式，不新增自由度）**

1. **手持/肩扛镜头**：画面带不规则的随机晃动，增强真实感、纪录片感或表现角色的紧张不安
2. **斯坦尼康镜头**：穿戴稳定器行走拍摄，平滑流畅地实现推、拉、摇、移、跟、升降的任意组合，不受地形限制
3. **航拍镜头**：搭载于直升机、无人机等飞行器上，建立宏大的地理环境或壮观场面
4. **遥控头/机械臂镜头（Robo Arm）**：按预设程序做高精度、微米级往复运动，常用于特效合成或高精度绿幕拍摄
5. **索道/飞猫镜头（Cable Cam）**：悬挂在双钢缆上由电机驱动超长距离高速滑行（体育赛事全场俯冲），可叠加电动云台旋转
6. **水下遥控运动（ROV）**：搭载于遥控潜水器，深水中慢速悬浮漂移或微距推拉，运动节奏受水流阻力影响
7. **FPV 穿越机运动**：第一人称竞速无人机高速飞行，同时做剧烈的 Roll 轴横滚与翻转，实现「高速穿梭+旋转+位移」的极限复合运动
8. **滑轨微距移动**：机位沿 Z 轴移动仅几毫米，因放大倍率极高，视觉上产生如跨越峡谷般的剧烈空间穿越感
9. **轨道车镜头（Dolly）**：摄影机安装在轨道车上沿直线/曲线滑动（区别于手持推拉），运动平滑、可精确控制速度与距离，是经典的平稳推拉/横移实现方式（如沿轨道从走廊一端匀速滑到另一端）
10. **摇臂镜头（Jib / Crane Arm）**：摄影机挂在可伸缩大臂上做大幅升降 + 弧线摆动，实现「从地面直冲天际」的宏观垂直运动，或大范围弧形环绕（常配合电动云台旋转）
11. **车载镜头（Car Rig / 车拍）**：摄影机固定在行驶的车辆/交通工具上跟拍（吸盘架、前杠架、侧挂架），与被摄主体同速同向运动，产生高速追车戏的贴地速度感（也可反装拍车内对谈）

**板块七：基于光学物理特性变化的被动/隐性光学现象（第 1、2 条为被动伪影，非主动运动）**

1. **变宽畸变动态（Anamorphic Breathing）**：变形宽银幕镜头跟焦时，镜片组内部移动导致画面水平拉伸比产生微小瞬时波动，「画面在呼吸」的被动光学动态
2. **焦点呼吸动态（Focus Breathing）**：跟焦过程中镜片组前后位移，画面产生极其细微的「视觉缩放感」（区别于变焦，范围极小，老式镜头尤其明显）
3. **偏振/滤镜动态旋转**：拍摄中电机旋转镜头前的偏振镜或渐变滤镜，动态改变天空颜色、水面反光或画面饱和度

> 第 1、2 条是跟焦的**副产物**（被动），主动的焦点变化见板块四；第 3 条是主动控制的滤镜/偏振，靠板块六的设备实现。

**板块八：虚拟制作与后期特效产生的运动（现场物理机位可能不动）**

1. **虚拟制片联动运动（LED Volume Sync）**：摄影机物理位移时，实时渲染引擎反向移动 LED 背景墙上的虚拟场景贴图，实现物理位移与概念缩放的实时无缝组合
2. **时间切片/子弹时间阵列运动**：一圈环绕的静态相机按顺序逐帧触发，剪辑成连续的环绕动态（摄影机本身未动，靠多静止机位时序接力创造动态）
3. **动态遮罩移位/2.5D 视差运动**：后期将前后景分离，数字缩放分别移动不同图层，制造伪推拉或伪摇移的视差动态

**板块九：按特殊叙事视角与功能划分的运动**

1. **主观镜头（POV）**：模拟故事中角色的视角进行运动（行走、奔跑或倒下的视线）
2. **客观镜头**：以旁观者视角拍摄，摄影机不参与叙事，是绝大多数镜头的默认叙述方式
3. **空镜头**：画面中不出现人物，只拍摄景物或环境，常用于抒情或转场
4. **悬空/顶拍镜头**：摄影机从高空垂直向下拍摄，营造超脱、审视或宿命感
5. **主观环绕（POV Orbit）**：以角色第一人称视角做环绕/转身运动（如角色原地转圈张望、回头扫视身后），把 POV 的代入感与环绕的空间揭示结合，观众直接看到角色「看到的世界」

**板块十：画面内参考系的隐性运动（机位静/动相对论）**

1. **主动摇拍**：摄影机摇动，目标静止
2. **被动摇拍**：摄影机静止，依靠目标极速入画或出画（如火车高速驶过镜头前）产生画面视觉冲刷感，机位不动但视觉上属于动态构图剧变

**板块十一：综合经典组合运动镜头（④ 与 ①②③ 的自由组合实例）**

1. **推拉摇移跟升降的任意复合**：如先摇镜扫视环境，再跟主体，最后推至面部特写，一个镜头完成复杂叙事
2. **滑动变焦（希区柯克变焦）**：**②面运动（物理推/拉）+ ④焦距运动（反向变焦）**，背景压缩或拉伸，产生空间扭曲的眩晕感。是「异类对撞」的标准范例：两个分量必须反向且同步变化
3. **摇-升降-变焦组合**：水平摇动（①）+ 垂直俯仰（①）+ 变焦（④），锁定在三维空间中做复杂曲线运动的主体
4. **斯坦尼康长镜头**：穿戴设备行走，同时实现推、拉、摇、移、跟、升降的无缝平滑衔接（② + ① 的平滑接续）
5. **跟拍-揭示镜头**：先跟拍主体（②跟），当其移开后，通过摇/移（①摇）揭示出之前被遮挡的关键信息
6. **推+摇组合**：沿 Z 轴推进（②）的同时水平摇动（①），保持主体在画面中心，产生极强的包围感
7. **移+升降组合**：水平横移（②）的同时垂直升降（②），营造复杂的空间穿梭纵深感
8. **环绕+变焦组合**：环绕主体旋转（②环绕）的同时进行光学缩放（④变焦），视觉冲击力极强
9. **跟焦+推移组合**：机位向主体推进（②）的同时焦点从前景切到主体（④移焦），「空间靠近」与「注意力交接」叠加，是正反打与登场镜头的常用写法
10. **宇宙缩放组合**：物理拉镜头（②）+ 光学 Zoom Out（④）+ 后期特效缩放（③），实现从人物拉到星系的全程尺度跨越
11. **量子穿梭组合**：物理推镜头（②）+ 光学 Zoom In（④）+ 后期特效穿越（③），实现进入微观世界的沉浸感

### 剪辑衔接类别（镜头与镜头的连接）

镜头之间的衔接方式本身也构成视觉语言，提示词中可用以描述转场与节奏：

1. **跳切（Jump Cut）**：同一机位、同一主体间直接硬切，画面主体位置/姿态突变，产生时间跳跃感或急促不安的节奏（新浪潮标志手法）
2. **匹配剪辑（Match Cut）**：前后镜头在构图、形状、动作或声音上相似/呼应的衔接（如从圆形钟表切到圆形月亮），产生隐喻与视觉流动
3. **叠化（Cross-Dissolve）**：前一镜头逐渐淡出与后一镜头叠加过渡，柔和的时空流逝感，常用于时间跳跃或回忆
4. **淡入淡出（Fade In / Fade Out）**：画面从黑场淡入或淡出至黑场，段落的开始与结束，强烈的叙事分隔
5. **划变（Wipe）**：一条分界线扫过画面完成切换（横向/纵向/圆形），风格化、年代感或空间并置
6. **甩切（Whip Cut）**：快速甩镜产生的动态模糊直接衔接下一镜头，动势连贯，节奏凌厉
