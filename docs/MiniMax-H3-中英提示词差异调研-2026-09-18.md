# MiniMax H3 中英提示词差异调研(FL2VA/I2VA 与 Ref2VA)

调查日期: 2026-09-18 · 本机环境: RTX 4080 SUPER 32GB / ComfyUI 本地 H3(int8 主干 + nvfp4 TE + sol-attn + int8 VAE, 4 步)
证据分级: **[官方]** 官方文档/代码 · **[实测]** 本机受控实验 · **[社区]** 社区报告 · **[推断]** 未验证推理

## 0. 结论速览

| 问题 | 结论 |
|---|---|
| 必须用英文吗? | **不是"必须",但英文是唯一有官方文档、官方示例与官方指南背书的形式**。正文散文用中文能跑通、能吃格式、能吃镜头时间轴;中文唯一可复现的视觉代价是**人脸年龄感偏大约 2~3 岁**(见 §3.2,11 次运行按语言零重叠) |
| 哪些内容**必须**英文/原样? | 字段名(`subject_definitions:` 等 6 个)、引用标签(`<Subject N>`/`<Picture N>`/`<Video N>`/`<Audio N>`)、镜头标记 `[Shot N]`、时间戳 `00:08.000`、`retention_analysis` 的固定枚举值(`fully_preserved` 等)、`summary` 的方括号任务类型、对白/歌词/画面文字的 `<d>[Language] …</d>` 包裹符 — 这些是**格式契约**,改成中文即脱离官方 token 与训练分布 [官方+实测] |
| 中文的主要代价 | ① 人脸年龄感偏大 2~3 岁(英文 4 次运行 25.2~26.1,中文 7 次运行 27.1~29.4,**零重叠**),且**用"严格要求"补不回来**(见 §3.4);② 细节描述类内容 token 反而**多约 8%**;③ 官方对中文正文无指南、无示例、无承诺 [实测+官方] |
| 中文的优势 | ① 提示词字符数只有英文约 1/3,可读性与维护性好得多;② 短提示词(以指令/氛围为主)token 反而**省 17%**;③ 镜头结构、时间轴、音轨、手部细腻度等"结构性"要求与英文**无可见差异** [实测] |
| 官方到底承诺了什么语言? | 只承诺**对白语言**:稳定支持 11 种(含中文/英文) [官方]。**没有任何一处承诺"提示词正文语言"** |

## 1. 官方立场(证据链)

1. **[官方] 官方只发布英文指南。** HF 仓库 `docs/` 仅两份:`VIDEO_PROMPT_WRITING_GUIDE_base_en.md`、`VIDEO_PROMPT_WRITING_GUIDE_ref_en.md`;官方 skill `skills/h3-prompt-writing/references/` 也只有 `base-en.txt` / `ref-en.txt`。官方仓库**没有** h3-prompt-writing 的中文版(其它 skill 如 `3d-animation-short-generator` 有 `SKILL.cn.md`,但提示词指南没有)。
   - 注: 本机 `.agents/skills/h3-prompt-writing/references/` 下的 `base-cn.md` / `ref-cn.md` 是**与英文版逐节对应的中文翻译(非官方发布)**,时间戳 2026-08-19,早于英文版最新修订 2026-08-22。
2. **[官方] 指南明确要求正文英文。** `ref-en.txt`: "Write all six rewrite sections in English. Preserve the original language only for dialogue and lyrics inside `<d>` and for text visibly present in the scene." 中文译本 `ref-cn.md` 首段同样写「六个改写部分全部用英文撰写」。
3. **[官方] 官方能力表只承诺对白语言。** README: `Supported dialogue languages | Stable support for 11 languages: Arabic, Chinese, English, …` — 这是**对白**,不是提示词。
4. **[官方] 8 个扩展 special token 全是英文符号,且 id 固定。** `comfy/text_encoders/minimax.py`:

   | token | id |
   |---|---|
   | `<d>` | 151669 |
   | `</d>` | 151670 |
   | `<|cutoff|>` | 151671 |
   | `<|lyrics_start|>` / `<|lyrics_end|>` | 151672 / 151673 |
   | `<|caption_start|>` / `<|caption_end|>` | 151674 / 151675 |

   基础词表只有 id 0..151668,**这 8 个 id 全在词表之外**,由 ComfyUI 加载时注入。实测:直接拿官方 `tokenizer.json` 编码,`<d>` 会被切成 2 个普通 token `[90707, 29]`,只有注入后才是单个 151669 ⇒ **把 `<d>` 写成 `<对话>` 之类,对白通道直接失效**。
5. **[官方] H3-Context-IR 是质量关键,但开源版不含。** 官方称 "H3-Context-IR 对最终输出质量至关重要…本次开源版本不包含该模块",建议自建预处理。这意味着**提示词写法在本地开源路径下的权重比官方 API 路径更高**,语言差异也更容易显形。

## 2. 本机受控实测设计

原则: **同一工作流、同一结构、同一 seed、同一分辨率/帧数,唯一变量是提示词正文语言。**

- 手段: 不动工作流、不动 md。用 `scripts/build-cn-prompt.py` 直接改写 API prompt 里 MD 表节点的 `视频提示词` 字段,并固定 `RandomNoise.noise_seed`。

## 3. 实测结果

### 3.1 没有差异的维度(结构性要求 — 中文一样吃得住)

| 维度 | 英文版 | 中文版 | 判定 |
|---|---|---|---|
| 输出帧数/时长(0041) | 192 帧 / 8.000s | 192 帧 / 8.000s | 一致 |
| 输出帧数/时长(0044) | 345 帧 / 14.375s | 345 帧 / 14.375s | 一致 |
| 分辨率/帧率/音轨 | 1344×768 / 24fps / 32kHz stereo | 同 | 一致 |
| 镜头切点(8.000s / 11.000s) | 准点切成三镜 | 准点切成三镜 | 一致 |
| 拉镜+焦点转移(0041) | 玻璃特写 → 出焦窗外 → 后拉进室内 → 书房中景 | 同路径 | 一致 |
| 手部细腻度(0044 Shot 2) | 手背平滑无条索 | 手背平滑无条索 | 一致 |
| 音轨内容 | 雨声宽带噪声 + 键盘瞬态,无音乐段 | 同 | 一致 |
| 音频响度/谱质心(0044) | LUFS −31.12 / 2511 Hz | LUFS −30.51 / 2624 Hz | 无实质差异 |
| 音频响度/谱质心(0041) | LUFS −27.79 / 970 Hz | LUFS −28.45 / 730 Hz | 中文略暗略轻,能量峰 5.54s → 6.43s |

### 3.2 有差异的维度

**(1) 人脸 — 中文版年龄感偏大 2~3 岁(不是"身份失真")** ⚠️ 最重要

> **更正**: 本调研第一版把这里写成"中文身份 likeness 明显变弱、像换了个人",那是**基于单帧目视的过度解读,已撤回**。补上客观指标后(见 §3.4 与 §3.4 的 11 组数据)结论相反:中文版的**几何相似度并不低**(ArcFace 余弦 0.62~0.68 vs 英文 0.52~0.71,区间重叠),真正稳定分层的是**估计年龄**。

0044 尾镜(11.0~14.375s,每段取 4~5 帧)对照参考图 `<Picture 1>`(陈落):

| 语言 | 运行次数 | ArcFace 余弦(vs 参考图) | 估计年龄 | 脸高/画面 |
|---|---|---|---|---|
| 英文 | 4(A_en / B_en / C3 / C5) | 0.518 ~ 0.713 | **25.2 / 26.1 / 25.8 / 25.6** | 0.29 ~ 0.75 |
| 中文 | 7(A_cn / B_cn / C1 / C2 / C4 / C6 / C7) | 0.556 ~ 0.677 | **27.8 / 27.4 / 28.7 / 29.4 / 29.4 / 27.4 / 27.1** | 0.39 ~ 0.84 |

- **年龄按语言完全分层、零重叠**(英文全在 25.2~26.1,中文全在 27.1~29.4),方向在两个 seed 上一致 ⇒ 这是真实且可复现的语言效应,不是噪声 [实测]。
- 相似度上中文并不吃亏(A_cn 0.677 > A_en 0.609),**所以"中文生成的是另一个人"不成立**;等脸高拼图(`scripts/H3身份补足-等脸高对照.png`)也显示 11 个版本都是同一个角色,差异在眉眼重量与皮肤质感上。
- 尺度不是伪影:把中文版画面缩到与英文版同脸高,相似度 0.6901→0.6879、年龄 27.9→27.7,基本不变;把英文版放大 2.5× 也基本不变 ⇒ 差异在脸本身,不在像素尺度 [实测,尺度控制]。
- 机理推测 [推断]: 中文正文里"真实男人的皮肤/毛孔绒毛/胡青/略不均匀肤色"这类质感词与同段的"少年脸"之间的张力,中文下更容易被偏"熟"的方向解掉。但 §3.4 显示直接删掉这些"催老"描述**并没有**把年龄拉回来,所以机理尚未确认。

**(2) 英文版更"敢"补细节,也更容易幻觉** [实测,单样本]

0041 的参考首帧只是一扇雨窗(画面里没有人)。英文版在 t≈3.0s 自行插入了一个**戴眼镜男子的近景** —— 而提示词从未提到眼镜或人物特写;中文版没有这段,老老实实留在窗外,到 5.2s 才进室内。就此例看,英文版的时间表推进更"主动",但**引入了提示词外的错误元素**。

**(3) 字符数 vs token 数(同样内容)** [实测,官方 H3 tokenizer]

| 提示词 | 字符 | tokens | 字符/token |
|---|---|---|---|
| 0041 英文 | 3182 | 685 | 4.65 |
| 0041 中文 | 850 | 566 | 1.50 |
| 0044 英文 | 13218 | 3004 | 4.40 |
| 0044 中文 | 4871 | 3256 | 1.50 |

- 中文**字符数**只有英文约 1/3(写作/维护成本低得多);
- 短提示词(指令、氛围为主):中文 **省 17% token**;
- 长提示词(细节密集):中文反而**多约 8% token**(英文字符/token 4.4,中文 1.5)。

结论:中文不是"token 更省的写法",长细节提示词尤其如此;省的是人读的成本,不是模型的成本。

### 3.4 针对人脸"显熟"的补足实验(7 个变体,同 seed 424242424242)

问题: **在中文提示词里"严格要求人物按参考图生成",能不能把年龄感补回来?**

| 变体 | 改动 | ArcFace | 估计年龄 | 脸高/画面 | 判定 |
|---|---|---|---|---|---|
| A_en(基线) | 英文原文 | 0.609 | **25.2** | 0.351 | 英文基准 |
| A_cn(基线) | 中文逐字翻译 | 0.677 | 27.8 | 0.794 | 中文基准 |
| C1 | 中文 +【身份第一原则】+ 五官比例锚点(眼距/鼻翼/三等分/下颌角等逐项写死)+ 尾镜重复钉脸 | 0.642 | 28.7 | 0.824 | ❌ 完全无效 |
| C2 | C1 + 皮肤年轻化(删鱼尾纹/胡青/T 区油光,改"年轻干净的少年脸") | 0.620 | 29.4 | 0.835 | ❌ 反而更老 |
| C3 | **英文** + 同样皮肤年轻化(对照) | 0.574 | 25.8 | 0.348 | 持平基线 ⇒ 该因子与语言无关 |
| C4 | 中文 + 量化景别("头部约占画面高度三分之一" + "不要变成大特写") | 0.676 | 29.4 | 0.747 | ⚠️ 景别略收,年龄无效 |
| C5 | **英文** + 同样量化景别 | **0.713** | 25.6 | 0.747 | 相似度全场最高 |
| C6 | **混合**: 中文正文,但 `<Subject 1>` 段 + `retention_analysis` 该条 + `[Shot 3]` 段整段用英文原文 | 0.589 | 27.4 | **0.415** | ⚠️ 景别明显回归英文层,年龄仍在中文层 |
| C7 | 中文 + 纯正面量化景别(去掉所有否定句与"特写"字样) | 0.585 | 27.1 | 0.544 | ⚠️ 优于 C4,但仍未到英文层 |

结论:
1. **在中文里追加"严格身份要求"补不了年龄感**:无论是"身份第一原则 + 五官比例锚点"(C1)、还是把"催老"的皮肤描述删干净(C2),估计年龄都没回到英文层(27.4~29.4 全在中文层内)。英文做同样删改(C3)也没变化 ⇒ **"皮肤质感描述催老"这个假设不成立**。
2. **能补的只有景别**:C6(身份段回英文)把脸高从 0.79 压到 0.42(接近英文层 0.29~0.35),C7(纯正面量化)压到 0.54。这是本次唯一被"补足"的指标。
3. **否定式会反噬**:C4 里写了"不推近、不变焦、不放大脸部…不要变成占满画面的脸部大特写",结果脸高 0.747;C7 把否定句全部换成正面表述(只留"头部约占画面高度三分之一")后降到 0.544 ⇒ 在 H3 里**描述"不要什么"会把"什么"引出来**,与语言无关。
4. 相似度本身在 0.52~0.71 波动,没有稳定语言效应 ⇒ **"中文人脸失真"这个提法本身就该收回**;中文的真实代价是"年龄感 +2 岁"这种细腻偏差,不是换人。

⚠️ **统计口径提醒**:以上每组只有 1 次生成(5 帧取均值),组间差异在 0.02~0.05(相似度)与 1~3 岁(年龄)量级。年龄的语言分层做到了零重叠,可信度较高;其余指标的单组差异**不可当结论**。同语言不同 seed 的景别差异可以很大(中文 seedA 0.794 vs seedB 0.388)⇒ **景别不是语言效应**。

## 4. 具体差距清单(实操口径)

**必须英文/原样(格式契约,改了就是错的)**
1. 六个字段名与冒号: `subject_definitions:` / `summary:` / `retention_analysis:` / `detailed_description:` / `overall_soundscape:` / `non_diegetic_music:`(FL2VA/I2VA 用 `integrated_multimodal_description:`)。
2. 引用标签 `<Subject N>`、`<Picture N>`、`<Video N>`、`<Audio N>`(Video/Audio 官方写作 `<Video N>`,ComfyUI 端口写作 `ref_video_N` 属工作流侧,不进提示词)。
3. `[Shot N]` 与切点时间戳 `At 00:08.000,`(数字与格式原样)。
4. `retention_analysis` 的枚举值:视觉 `fully_preserved` / `partially_preserved` / `attribute_transfer` / `weak_reference`;音频 `fully_copy` / `partially_copy` / `reference` / `weak_reference`。
5. `summary` 开头方括号任务类型(如 `[keyframe completion + reference generation]`)。
6. 对白/歌词/旁白包装:`(S1) says <d>[Chinese] 原话。</d>` — **中括号内语言标签写 `[Chinese]`/`[Mandarin]`,`<d>` 本体必须原样英文符号**;语内文字保持原语言、逐字不改。
7. 画面可见文字(招牌/字幕/霓虹)用英文双引号原样引用。

**中文完全可以(结构性、氛围性、动作性要求)**
- 镜头运动类型/幅度/速度、构图、光线方向、镜头切换时间点、场景物件、动作路径、环境声与配乐描述 —— 实测无可见损失。

**建议直接用英文(风险最高区)**
- `<Subject N>` 的**逐项 likeness 锁定**与皮肤细节段: 不是为了相似度(中文并不低),而是为了**年龄感**(中文稳定偏大 2~3 岁)与**景别**(中文把中近景拍成大特写的概率更高;C6 实测把这几段换回英文后脸高从 0.79 回到 0.42);
- 需要"像参考图/参考视频"的任何细粒度属性迁移;
- 复杂否定/排除意图(注意: H3 对否定式本身就不牢靠,应改写为**正面描述**,这一点与语言无关;实测中文写"不要大特写"反而更容易拍成大特写)。

## 5. 推荐写法(混合策略)

```text
subject_definitions:
<Subject 1> is the young man whose face, hair and body are taken exactly from <Picture 1>: ...
（这一段以及所有逐项 likeness / 皮肤细节 / 身份锁定 → 英文）

summary:
[keyframe completion + reference generation] 目标视频……（散文可中文）

retention_analysis:
<Subject 1> (appears in [Shot 1], [Shot 2] and [Shot 3]): fully_preserved - ...（枚举值与标签英文,说明可中文）

detailed_description:
[Shot 1] 画面从……（镜头、光线、动作、物件 → 中文可用）
[Shot 2] At 00:08.000, ……（时间戳原样）

overall_soundscape: ……（中文可用）
non_diegetic_music: N/A
```

一句话: **骨架英文,血肉随意**。标签、字段、枚举、时间戳、`<d>` 是骨架,不能动;身份锁定段建议跟随骨架用英文(实测它同时管住"年龄感"和"景别"),其余叙述用中文实测没有代价,且能省掉约 2/3 字符。

**如果坚持全中文正文**,能做的只有 (a) 景别用数字写死(如"头部约占画面高度三分之一"),且**只写正面表述、不要写"不要大特写"**;(b) 接受人脸年龄感约 +2 岁。若这两点都不能接受,再考虑上后期人脸对齐(ReActor / GPEN / CodeFormer)而不是继续加提示词。

## 6. 未验证 / 待确认

- 每个条件仍只有 1 次生成(取 4~5 帧均值)。**年龄的语言分层(英 25.2~26.1 / 中 27.1~29.4)做到了零重叠,可信度较高**;相似度与景别的单组差异(0.02~0.05 / 0.05~0.4)波动与效应同量级,**不可当结论**。要定论需 5+ seed 或人工打分。
- 年龄与相似度用的是 buffalo_l 的 `w600k_r50`(ArcFace)与 `genderage`,均非官方 H3 评估口径,且参考图是 CG 渲染(年龄模型把它读成 24 岁女性)——绝对数值不可直接采信,**只看同一模型下的相对差异**。
- 中文对照版由本会话逐字翻译,翻译措辞本身可能引入偏差(例如中文更紧凑、语序不同)。要做纯净实验,应让英文原文由另一个独立译者回译校验。
- 中文正文"为什么"会显熟:**未查明**。"皮肤质感词催老"假设已被 C2/C3 否掉;剩余嫌疑是中文语汇对"少年/男子"的年龄先验、或中文描述在 H3 条件编码里的权重分布,均无证据。
- 未测:中文提示词下的**中文对白**质量(本轮 0044 无对白)。官方已承诺 11 种对白语言稳定支持,但"中文对白 + 中文正文"与"中文对白 + 英文正文"的差异未测。
- 未测:L2VA(仅尾帧)、FL2VA(首尾帧,即 0042 工作流)的中英差异;T2VA(0030 工作流)。
- 未测:中文标签(`<图片 1>` / `[镜头 1]`)的实际效果。token 层面 `<图片 1>` 与 `<Picture 1>` 都是 5 个 token,无明显惩罚;但 `<Picture N>` 是训练分布内的固定写法,`<图片 N>` 不在其中 — 此为 **[推断]**,未做对照生成。
- 未测:**加一张脸部大特写作为额外参考图**(官方允许 ≤9 图)对身份/年龄的补足效果 —— 从本轮结果看,这比继续调中文措辞更可能是有效杠杆,但需改工作流与 md,未获授权。
- 本机**无 SenseVoiceSmall 权重**(`models/TTS/SenseVoiceSmall` 不存在,AGENTS.md 该行已过期),本轮音频判断依据是频谱图 + LUFS/谱质心/低频占比,**未做人声转写**;0044 提示词只要求雨声与键盘声,频谱也未见乐音或语音共振峰结构。
