# MiniMax H3 参考保真度调研：如何把画面与参考图的相似度做到 0.95+

- 日期：2026-09-18
- 对象：故事库 `七纹刻印` 的 H3 视频生成（0044 参考视频 / 0043 关键帧视频）
- 度量口径：`w600k_r50` ArcFace 512 维余弦（`scripts/face-sim.py`）+ SIFT 结构匹配 + 目视
- 全部数字均由本机实测产生，脚本见 `scripts/calib-*.py`，可复现
- ⚠️ 根 `scripts\` 临时目录已于 2026-10-11 移除，下列脚本名仅作历史记录；本报告结论不依赖脚本存在

---

## 0. 结论摘要

**0.95 在当前口径下不等于「很像」，而等于「就是那张图」。** 因此这不是一个靠提示词、模型精度或后期修复能解决的调优问题，而是**指标语义问题**。

| 目标 | 可达性 | 依据 |
| :--- | :--- | :--- |
| **关键帧 0.95+（走生成端）** | ❌ **不可达** | `AddGuide` 锚定帧实测 SSIM 0.83~0.92、SIFT 0.19~0.38（§7） |
| 关键帧 0.95+（走后期像素替换） | ✅ 可达 | 硬贴 0.978（ArcFace）；但观感崩坏（§6） |
| 整段视频每一帧都 0.95+ | ❌ 不可达 | 参考图自己跨视角只有 0.41（§2、§3） |
| 画面自然 + 全时段 0.95+ | ❌ 二者互斥 | 硬贴才能到 0.978，但姿态崩坏（§6） |
| 0.55~0.70（人物现状） | ✅ 已是同角色正常水平 | 与参考图内部 0.5923 持平（§4） |

**最有价值的一条**：现有 H3 输出与参考图的相似度 **0.599**，**高于参考图自己「正视 vs 侧视」的 0.4071**。也就是说模型并没有额外丢失身份，它已经处在「同一角色的两张不同画面」的正常区间内。

## 1. 先钉死口径：0.95 到底意味着什么

对同一张参考图（`media/万物建模-人物-陈落.png`，脸 315×441px）施加可控退化，重新检测+对齐+嵌入后与原始嵌入比余弦：

| 退化方式 | ArcFace 余弦 | 判定 |
| :--- | ---: | :--- |
| 原图重解码（理论上限） | 1.0000 | — |
| JPEG q95 / q50 | 0.9983 / 0.9916 | 几乎无损 |
| JPEG q15 | 0.9386 | 仍很高 |
| 整图缩放到脸高 269px（= H3 768p 实际脸高） | 0.9966 | 几乎无损 |
| 整图缩放到脸高 120px | 0.9770 | 几乎无损 |
| 高斯模糊 k=9 / σ=4.0 | 0.9675 / 0.9347 | 仍很高 |
| 高斯噪声 σ=15 / σ=25 | 0.9039 / 0.8644 | 开始下滑 |
| 增益 1.3 / 偏暖 +30 | 0.9746 / 0.9924 | 几乎无损 |
| 平面旋转 35° | 0.9559 | 仍 ≥0.95 |
| **水平翻转** | **0.9559** | 镜像仍 ≥0.95 |

**读法**：压缩、缩放、模糊、噪声、光照、旋转、镜像——**同一张脸的任何退化都在 0.93 以上**。

所以「0.95 相似度」的真实含义是：**画面里的脸必须就是参考图那张脸的复制，允许有画质损失，但不允许是"另一张脸"**。一旦输入的是同一角色的另一张画面，分数立刻掉到 0.3~0.6。

> 可复现：`python scripts/calib-arcface-tolerance.py`

## 2. 人物：同一角色内部的真实上限

`万物建模-人物-陈落.png` 内有 3 张脸：左侧大特写正脸（315×441px）、右侧三视图的正视（54×70px）与侧视（48×63px）。**同一角色、同一张图、同一套渲染**，两两比对：

| 对比 | ArcFace 余弦 |
| :--- | ---: |
| 特写正脸 vs 三视图·正视（**都是正面**） | 0.5923 |
| 三视图·正视 vs 侧视 | **0.4071** |
| 特写正脸 vs 三视图·侧视 | 0.3098 |

**结论**：连参考图自己内部「正视 vs 侧视」都只有 **0.41**。因此「视频里角色转头之后还要 0.95」在同一角色范围内**不存在这个数值**——不是模型做不到，是这个数在语义上不成立。

> 可复现：`python scripts/calib-refview-consistency.py`

## 3. 物品 / 场景：完全平行的结论

物品建模图（电子钟/旧书/手机/笔记本电脑）尚未生成，改用 `media/首帧场景-书房旋镜八图.png`（2520×1464，切 9 格，每格 840×488）。用 SIFT + RANSAC 单应内点测「结构可复用性」：

| 指标 | 同一场景 8 视角的 36 对 |
| :--- | :--- |
| 关键点覆盖率 | 中位 **0.067**、最大 0.147、最小 0.015 |
| 色调直方图相关 | 0.64 ~ 0.98（**很高**） |
| 同图自比（对照） | 1.000 |

同一场景、不同镜别：

| 镜别对 | 内点 | 覆盖率 | 色调相关 |
| :--- | ---: | ---: | ---: |
| 场景首帧-书房 vs 场景拉镜-书房（扩图关系） | 86 | 0.379 | 0.209 |
| 场景首帧-书房 vs 场景推镜-书房玻璃窗 | 8 | 0.066 | 0.413 |
| 场景拉镜-书房 vs 场景推镜-书房玻璃窗 | 6 | 0.050 | 0.057 |

**结论**：同一场景**色调能保持、结构换视角就基本不可复用**。物品侧和人物侧是同一个答案——**0.95 只在"同一视角、同一画面"下成立**。

这条也解释了 `h3-scene-generation.md` 里那个已知现象：同一场景两次独立生成，斗柜抽屉 3 vs 4 个、衣帽架 2 vs 1 个。**逐格独立生成的图不能当多视角参考**。

> 可复现：`python scripts/calib-item-consistency.py`

## 4. 现状定位：H3 并没有额外丢身份

| 对象 | 相似度 |
| :--- | ---: |
| 0044 生成尾镜 vs 参考图（t=13.0 / 14.0s） | 0.599 / 0.594 |
| **参考图内部 特写 vs 正视** | **0.5923** |
| 参考图内部 正视 vs 侧视 | 0.4071 |
| 11 组受控变体（英文/中文/各类强化） | 0.518 ~ 0.713 |

生成值 0.599 **追平了参考图自己"特写 vs 正视"的 0.5923**，并**远高于**"正视 vs 侧视"的 0.4071。

同时，0044 现有提示词**已经用满官方最强措辞**：官方 `ref-en.txt` 的 `retention_analysis` 只有 4 个固定枚举（`fully_preserved` / `partially_preserved` / `attribute_transfer` / `weak_reference`），而 0044 已经用了 `fully_preserved`（6 处），并额外写了 “taken exactly from `<Picture 1>`”“His likeness matches that portrait exactly in every frame, at every distance and from every angle”。

**即：措辞维度已无提升空间，官方也没有更强的枚举可用。**

### 4.1 跨源参考一致性：模型收到的是「两个陈落」

测 0044 实际喂进去的两路人物参考（`scripts/calib-crossref-consistency.py`）：

| 对比 | ArcFace 余弦 |
| :--- | ---: |
| 万物建模-人物-陈落 **vs** 万物变化-出门装（大特写/正视/侧视） | **0.9983 / 0.9729 / 0.9724** |
| 万物建模-人物-陈落 **vs** 灰度遮罩-换衣服（三张脸） | **1.0000 / 1.0000 / 1.0000** |
| 建模图大特写 **vs** 参考视频 t=14.0s | 0.6438 |
| 建模图大特写 **vs** 参考视频 t=9.0s | 0.1983 |
| **参考视频自己内部：t=9.0s vs t=14.0s** | **0.2012** |
| **0044 产物尾帧 vs 参考视频 t=14.0s** | **0.7708** |
| 0044 产物尾帧 vs 建模图大特写 | 0.5106 |

**三条结论**：

1. **三张「建模类」参考图其实是一张脸，不是三个视角**：`灰度遮罩-换衣服` 与 `万物建模` **逐像素完全相同（平均像素差 0.00）**；`出门装` 与 `万物建模` 的脸区平均像素差仅 **0.76**（同一底图换了衣服）。所以它们之间的 0.97~1.00 是**自比自**，不构成参考多样性。
2. **跨源（建模图 vs 参考视频）低到 0.20~0.64，但这不是"参考图做坏了"**：参考视频**自己两帧之间**也只有 0.2012——这是 ArcFace 对任何非同一画面的常态（§1）。
3. **⚠️ 真正值得注意的：模型在跟参考视频走，而不是跟建模图。** 产物尾帧 vs 参考视频 **0.7708**，远高于 vs 建模图的 **0.5106**。而提示词写的是 "His likeness matches that portrait **exactly** in every frame"（要求跟 `<Picture 1>`）——**参考视频对角色外观是一个反向拉力**。

> 这条给"想让角色严格像建模图"的目标提供了明确改进方向：**让参考视频与建模图同源**（用同一角色板生成参考视频），或干脆去掉冲突的人物视频参考。
> 但它**不改变 §7 的结论**：0043 已证明即使把参考图直接钉进 latent，锚定帧也只有 SSIM 0.92 —— 参考图一致性不是 0.95 的瓶颈，**口径才是**。

## 5. 为什么"堆措辞 / 提画质"无效（均已实测）

| 手段 | 实测结果 | 判定 |
| :--- | :--- | :--- |
| C1 中文 + 身份第一原则 + 五官比例逐项锚点 | 0.6424，年龄 28.7 | ❌ 无效，相似度反降 |
| C2 C1 + 皮肤年轻化 | 年龄 29.4 | ❌ 反而更老 |
| C3 英文 + 同样皮肤年轻化 | 25.8，与英文基线持平 | ⇒ 催老与语言无关 |
| C4 中文 + 否定式量化景别 | 脸高 0.747 | ❌ 否定句反噬 |
| C7 中文 + 正面量化景别（去否定句） | 脸高 0.544 | ⚠️ 只改景别，不改身份 |
| C6 混合（身份段回英文） | 0.415 景别、年龄仍在中文层 | ⚠️ 只把景别拉回 |
| JPEG / 缩放 / 模糊 / 噪声 | 余弦 ≥0.93 | ❌ 与身份无关 |
| 8 步 LoRA、bf16 主干、int8 VAE | — | ❌ 与身份无关 |

**一句话**：当前失败的不是画质也不是措辞，是**模型每次都在"画一张新脸"**，而新脸与新脸之间天然只有 0.3~0.6。

## 6. 后期路径实测：像素级替换能到多少

对 0044 尾镜帧（原 sim 0.5938）把参考图的脸仿射 warp 过去并融合：

| 替换范围 | 相似度 |
| :--- | ---: |
| 0 原始生成帧 | 0.5938 |
| 椭圆 0.56/0.60 + 羽化 5% | 0.9320 |
| 椭圆 0.62/0.68 + 羽化 2% | 0.9432 |
| **椭圆 0.70/0.78 硬边** | **0.9784** |
| 椭圆 0.85/0.95 硬边 | 0.9738 |
| 椭圆 1.15/1.25 硬边（含颈肩） | 0.9749 |

**三条硬结论**：

1. **羽化过渡本身就把分数从 0.978 拉低到 0.93** —— 过渡区残留的原脸特征仍被算进去。要 0.95+，必须**硬边整脸替换**。
2. **但硬贴的观感是崩的**：参考图是正脸，目标帧是三四侧，warp 后出现**头身朝向矛盾**（脸转正了、脖子和身体没转）加椭圆接缝（见 `scripts/calib-posthoc/compare.png` 中间格）。
3. **换脸（inswapper_128）不适用于本库的国漫CG风格**：实测输出是**模糊的写实人脸**（`scripts/calib-posthoc/inswapper_glintr100_faces.png`），因为它是在真实人脸照片上训练的。此外还踩到两个坑：
   - `inswapper_128` 配套的是 **`glintr100`（antelopev2）**，传 `w600k_r50`（buffalo_l）的嵌入是**分布外**（两者嵌入空间余弦仅 **+0.0041**，近乎正交）；
   - 小脸（54×70px）被强行放大到 128×128 会直接崩坏。

## 7. 生成端唯一的强杠杆：AddGuide 关键帧锚定

官方 `ref-en.txt` 里 `<Picture N>` 有**两种互斥用法**：

| 用法 | 任务类型 | 约束强度 |
| :--- | :--- | :--- |
| 只在 `<Subject N>` 里引用（定义角色/场景/风格来源） | `reference generation` | **弱**（语义参考，模型自由发挥）→ 实测 0.6 |
| 独立 `<Picture N>` 条目，作为某镜首帧/关键帧/尾帧 | `keyframe completion` | **强**（像素级锚定） |

**0044 属于前者**（`<Picture 1>` 在 `subject_definitions` 里定义 `<Subject 1>`），所以它拿到的是"语义参考"级别的 0.6，这与实测完全吻合。

**0043 工作流是后者**：`MiniMaxH3ReferenceToVideo`（Ref2VA）+ **9 个 `FallingTSH3AddGuide`**，每个锚点把图**直接写进 latent**（`ComfyMathExpression` 做秒→帧并对齐 `n%17==5`），且 md 里同一张图**同时**进入 Ref2VA 的 `ref_images.ref_image_N` 和对应 AddGuide 的 `image`。

| 实验 | 配置 | 结果 |
| :--- | :--- | :--- |
| 0043 锚定实验 | 3 锚点（书房首帧 / 玻璃窗推镜 @7.5s / 拉镜尾帧），15s / 1344×768 / 4 步 turbo | 见下方补记 |

**实测**（产物 `scripts/calib-anchor/0043.mp4`，1344×768 / 24fps / 362 帧 / 15.08s，耗时 **750s**；脚本 `scripts/calib-anchor-eval.py`）：

| 锚定帧 | 该帧的锚定参考图 | SIFT 覆盖 | SSIM | 色调相关 |
| :--- | :--- | ---: | ---: | ---: |
| 0.0s | 场景首帧-书房 | 0.228 | 0.829 | 0.682 |
| 7.5s | 场景推镜-书房玻璃窗 | 0.189 | 0.891 | 0.592 |
| 15.0s | 场景拉镜-书房 | 0.381 | 0.920 | 0.598 |
| 对照：参考图内部同场景跨视角 | — | 0.067~0.147 | — | 0.64~0.98 |

**结论（与预期相反，是本轮最重要的否定结果）**：

1. **`AddGuide` 是「内容/构图引导」，不是「像素级锚定」**。联络表目视证实三个锚点的**内容确实都出现了**（t=0 书房内景 → t=4.5~7.5 窗户雨夜特写 → t=12~13.5 宽景拉镜），锚定**真的在起作用**；
2. **但锚定帧并未被复现成参考图**：SIFT 覆盖只有 0.19~0.38、SSIM 0.83~0.92，**离"复制"差得很远**；
3. 即便如此锚定仍有实测价值：SIFT 覆盖 0.19~0.38 约为**同场景跨视角自然水平（0.067~0.147）的 2.6 倍**；
4. 色调相关反而低于参考图内部跨视角（0.59~0.68 vs 0.64~0.98）：生成把画面推向雨夜冷调，与参考图暖调氛围不同；
5. 非锚定帧相对首帧的 SIFT 覆盖从 0.228 掉到 0.009~0.151 —— **锚点之间仍会漂移**。

**场景/物品侧的 0.95 标定**（`scripts/calib-scene-ssim.py`，用于判断锚定帧离"复制"有多远）：

| 退化方式 | SSIM | SIFT 覆盖 |
| :--- | ---: | ---: |
| 原图自身（复制） | 1.0000 | 1.0000 |
| JPEG q90 / q50 / q30 | 0.9899 / 0.9655 / 0.9424 | 0.8334 / 0.5898 / 0.4836 |
| 缩到 50% / 25% 再放大 | 0.9606 / 0.8708 | 0.4731 / 0.2880 |
| 高斯模糊 σ=3 | 0.8232 | 0.3713 |
| 高斯噪声 σ=15 | 0.5501 | 0.3749 |
| 亮度 ×0.8 | 0.9699 | 0.9333 |
| 平移 2%（27,15）px | 0.4741 | 0.9623 |

两个指标**互补**：SIFT 覆盖高 = **结构/物件一致**（对平移、光照鲁棒）；SSIM 高 = **像素级对齐且结构一致**。

**据此定位锚定帧：SSIM 0.83~0.92 相当于「JPEG q30 ~ 缩到 25%」水平，SIFT 0.19~0.38 相当于「高斯模糊」水平。** 也就是说锚定帧与参考图的关系是"**同场景、结构相近、但像素与细节并未对齐**"，而不是"复制"。

**能力边界小结：生成端（含最强的 latent 锚定手段）实测上限 ≈ SSIM 0.92 / SIFT 0.38，到 0.95 仍有确定距离。要跨过 0.95，只能靠 §6 的像素级替换。**

**建议的下一步验证**（未执行，需你确认）：把锚点密度提高——在每一镜的关键时间点（如每 1.5~2s）插入一张**与目标构图一致**的参考帧，观察非锚定帧是否被锚点"拉住"。

## 9. 验收口径建议（最重要的一条）

**"整段视频每一帧与参考图 0.95+" 是一个物理上不成立的目标**，因为它要求每一帧都是参考图那张图的复制。建议改成可验证、且真正反映"像不像同一个人/同一个物品"的口径：

1. **分帧分级**：锚定帧 ≥0.95；非锚定帧 ≥ 0.40（= 参考图自身跨视角水平）
2. **同角色自然区间**：把"≥ 参考图内部正视 vs 侧视（0.4071）"作为"仍是同一角色"的判据
3. **等脸高对照**：比较身份必须先把两帧的人脸缩放到同高再看（历史教训：中文版"换脸"错觉其实是景别混淆造成的）
4. **人工复核**：客观指标只用于筛异常，最终以人眼判定"是否同一角色"
5. **物品/场景侧**：用 **SIFT 覆盖 + SSIM 组合**判读——SIFT 高而 SSIM 低 = 物件对但像素/细节没对齐；两者都高才是"复制"（参照 §7 标定表：JPEG q90 ≈ SSIM 0.99 / SIFT 0.83）

## 11. 边界与未验证

- **样本量**：相似度标定为单张参考图上的确定性退化（无随机性）；现状值来自 11 组变体各 1 次生成、取尾镜 4~5 帧均值。
- **口径局限**：`w600k_r50` 非官方评估口径，且参考图是 CG 渲染（年龄模型把它读成 24 岁女性）→ **只看相对差异，绝对数值不可采信**。
- **未做**：加密锚定（每 1.5~2s 一个锚点）能否抬升非锚定帧——鉴于锚定帧本身只有 SSIM 0.92、且锚点之间仍有漂移，**预期收益有限**；物品建模图（电子钟/旧书/手机/笔记本电脑）生成后的物品侧实测，本轮用场景素材替代（§3）。
- **一次锚定实验耗时 750s**（0043，15s / 1344×768 / 4 步 turbo / 单卡），迭代时按此估算。
- `ComfyUI/temp/` **会被清理**：本轮 11 个变体视频与 `workflow-to-prompt.py` 都已消失，实验产物必须及时转存到 `scripts/`。

- 场景侧的 SSIM/SIFT 与人物侧的 ArcFace 余弦**是不同口径，数值不可互相换算**，引用时须带上口径。
