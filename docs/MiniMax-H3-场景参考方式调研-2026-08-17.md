# MiniMax H3 场景参考方式调研(多图直传 · 合并参考板 · 场景旋转视频)

> 调研日期:2026-08-17
> 范围:ComfyUI-OrbitSheets 官方 README 全文(社区场景参考板插件,2026-08-17 经代理抓取)、Skythread 项目短文(Krea 2 + H3 R2V 实测)、官方 `h3-prompt-writing` skill 的 `ref-en.txt`(Ref2VA 六段式改写规范)、官方 `MiniMaxH3ReferenceToVideo` 节点源码
> 问题:当前主流生视频对「场景参考」如何做——是传入参考 4 图、还是 4 图合并成一张图、还是直接传入一段场景旋转视频?
> 结论(先行):**官方多图直传(≤9 图)> 合并成一张「场景参考板」(contact sheet)> 直接传场景旋转视频**。0031→0032 管线推荐「从环绕视频拆帧选 4 张正交清晰帧分传」或「拼 2×2 参考板合并传」,不推荐整段环绕视频直传。

---

## 一、三种方式的总体对比

| 方式 | 官方支持? | 社区实践 | 优点 | 缺点 |
|------|-----------|----------|------|------|
| **A. 参考 4 图直传** | ✅ Ref2VA ≤9 图 | 官方默认用法,最省事 | 每张图独立、分辨率无损、标签语义清晰;一个 Subject 可由多图共同定义 | 图间细节不一致时模型取折中或混乱 |
| **B. 4 图合并成一张参考板** | ✅(合并后按 1 图传) | OrbitSheets Location Sheet、Skythread 环境网格图 | 模型把网格图当「场景全集」一次读懂,跨角度一致性最强 | 网格压缩单帧分辨率;模型可能把网格当画面主体;>16 格可读性下降 |
| **C. 场景旋转视频直传** | ✅ Ref2VA ≤3 视频 | 少见,社区明确不推荐用于静态场景参考 | 含连续空间关系(若视频本身生成质量高) | 视频参考语义是编辑/延续/结构;旋转运镜生成本身高危易翻滚;连续运镜难抽象静态场景 |

## 二、方式 A:参考图多图直传(官方默认)

### 2.1 官方能力边界

`MiniMaxH3ReferenceToVideo`(`comfy_extras/nodes_minimax_h3.py`)输入:

| 输入 | 上限 |
|------|------|
| `ref_images` | ≤9 张(短边超 2048 下采样) |
| `ref_videos` | ≤3 段(24fps,2–15 秒,≥5 帧) |
| `ref_video_audios` | ≤3(与 ref_video 同编号配对音轨) |
| `ref_audios` | ≤3(独立参考音频) |

参考呈现顺序固定:**images → videos(每段 soundtrack 的 `<Audio j>` 标签紧贴其 `<Video k>` 前)→ standalone audio**;序号按类型各自 1-based,prompt 需用同一标签引用。**4 张图分开传完全在官方能力内,**无需合并。

### 2.2 官方规范中对「多图定义同一场景」的写法

Ref2VA 六段式(`subject_definitions` → `summary` → `retention_analysis` → `detailed_description` → `overall_soundscape` → `non_diegetic_music`)中:

- 每张参考图分配 `<Picture N>` 标签;场景/人物/道具等可复用内容用 `<Subject N>` 抽象定义;
- **一个 `<Subject N>` 可以由多个参考资源共同定义**,一个参考资源也可提供多个 Subject——官方原生支持「4 张图共同支撑一个场景定义」的写法:

```text
<Subject 1> is the study room in <Picture 1> and <Picture 2>, with the bookshelves along the walls, the desk facing the window, and the warm desk lamp.
```

- 当某张图仅作为场景细节补充(不单独分析)时,可直接在该 Subject 定义行内引用,不另立 `<Picture N>` 条目。

### 2.3 与 0031→0032 管线的衔接

0032 参考场景(Ref2VA)直接把 0031 环绕结果拆出的 4 张正交清晰帧分传,并在 `subject_definitions` 里统一标为同一个 `<Subject N>` 即可。**这是官方语义的最直接用法,不需要任何合并技巧。**

## 三、方式 B:合并成一张「场景参考板」(社区进阶)

### 3.1 OrbitSheets —— Location Sheet(本插件核心实践)

**流程**:锚点静帧 → H3 生成长镜头 → 视觉模型选帧 → 拼成一张编号网格图(sheet)。

- **覆盖模式二选一**:
  - `coverage = cut views`(**默认**):前 → 右 → 后 → 左(+ 可选全景/细节);室内 = 远墙 → 两面侧墙 → 高俯视。写法为 H3 多镜头格式 `[Shot N] At 00:MM.mmm, the shot cuts to...`,每视角 1 秒左右**静止锁机位**;
  - `coverage = continuous move`:一段不切割的连续运镜(室内原地摇镜 / 室外环绕弧形),用于**无法从单视角外推背面**的独特场景。
- **为什么硬切默认胜出**:静止机位「没有运镜可出错」,翻滚/倾斜在结构上不可能;在教堂室内等测试中,所有连续运镜(原地摇镜、平移滑动)都输了——摇镜会向上倾斜螺旋,平移只朝一个方向走、6 帧全是同一面墙滑过。
- **为什么旋转(连续运镜)仍被保留**:「场景不是角色」——角色换背面可从任何角度重建(模型知道背面长什么样),但**一个只见过一次的独特建筑,让它「切到背面」要么重摆正面、要么凭空发明**;旋转则每帧与上一帧重叠,只需**延续**不必**猜**,所以 Location Sheet 用旋转抽 6 个方向、Character Turnaround 用硬切。
- **选帧不能用等间隔**:运镜不均速,等间隔样本会落在模糊中段帧、或两帧同一面墙。改为**内容聚类**(k-means 按帧色彩签名分组,最远点播种可复现):H3 每次给各镜头的时长差异很大,按时间分会把两槽分给同一角度、丢一个视角。
- **选帧判定模型优先级**:图内 CLIP(与编码锚点同一 Qwen3-VL,不请求外网)> OpenAI 兼容 HTTP > Laplacian 锐度 + 最远点散布兜底。`boards=4` 可把时间轴分 4 扇区各自成板,视觉模型看到 4 倍帧数。
- **其他要点**:`shots=5` + `shot_split=views` 可保证每个视角必落一张;`length = 17k + 5`(124 帧 ≈ 5.2s 恰好五镜头);网格卡号**不烧录进图**(标签会跟随参考进入下游)。

### 3.2 Skythread —— 环境参考网格图(单图代表整个场景)

Krea 2 + H3 R2V 实测短文:

- 作者把「空场景」参考做成**一张环境参考网格图**(`contact_sheet.png`,多视角拼成一张图),一次输入代表整个场景的地点/光照/构图/风格;
- 核心经验:**参考要精简、职责单一**——角色一张、道具一张、空场景一张,而不是把上一镜头整帧拖进下一镜头(那样会锁死机位和运镜,且 Krea 参考图噪声多、给不了 H3 可靠运动);
- 每个场景还可用独立 seed 生成「空场景底板」,让图像模型把环境一次放对,而不是让一个模型同时摆多个元素。

### 3.3 合并参考板的使用注意

- 保证单格分辨率足够(H3 会下采样 ≤2048 短边),>16 格可读性明显下降;
- 明确告诉模型这张图是「场景的多个角度的参考」(在 subject_definitions 中标注),避免模型把它当作画面主体;
- 若以「角色周转」为目的(如角色卡),参考 Offer 的仍是**每格一视角的网格**,与场景参考同理。

## 四、方式 C:直接传场景旋转视频(官方支持但社区不推荐)

### 4.1 官方 `<Video N>` 语义

Ref2VA 的 `<Video N>` 用于:**编辑原视频、从原视频结尾延续、参考原视频的运镜/剪辑/节奏/时间结构**。场景细节官方明确要求抽象成 `<Subject N>`(从图像中提取),**不鼓励**把整段视频当静态场景信息源。

### 4.2 社区实测的两个硬伤

1. **连续旋转运镜的生成本身是 H3 高危操作**:
   - H3 官方指南的安全环绕速率 ≈ **24°/s**;完整 360° 需要 **9 秒 + 220 帧以上**(`MiniMaxH3ImageToVideo.length = 17k+5`,`124 帧=5.17s / 260=10.8s`);
   - 124 帧(5 秒)里硬做 360° = **72°/s**,远超安全速率 → 模型翻滚、倾斜,「幅度与角度是同一指令」,不得在太阳下重复声明并被 clamp(上限 40°/s);
   - implication:0031 里「镜头飞到中间旋转一圈」若帧数不足,生成的旋转本身就可能不稳,拆帧也拆不到干净正交视角。
2. **旋转视频作参考的信息质量差**:连续运镜每帧都在变化,模型难从中抽象「静态的房间长什么样」;等间隔取帧会拿到模糊帧和重复墙,正如 OrbitSheets 所言——那不是一张合格的场景参考板。

### 4.3 例外

**只有当你要参考「旋转运镜本身」**——行为/镜头结构复用(如「第二幕的环绕镜头与参考视频同步」)——才是 `<Video N>` 的正经用途,与静态场景参考无关。

## 五、针对本项目管线(0031 环绕 → 0032 参考场景)的建议

1. **首选**:0031 环绕视频 → 拆帧 → 人工或视觉模型选 4 张正交清晰帧(前/右/后/左)→ 0032 Ref2VA **分传**,`subject_definitions` 统一定义为一个 `<Subject N>`(场景);
2. **次选**:同样选帧,拼成一张 **2×2 场景参考板**合并传(对标 OrbitSheets/Skythread,一致性最强,保证单格分辨率);
3. **不推荐**:整段环绕视频直传 0032(除非复用的是运镜本身)。

> 若纠结,可跑一轮对比测试(4 图分传 vs 一张合并板)看 0032 输出再定;拆帧/分析脚本可复用现有工具链(或按需现场重建)。
