# 世界模型改版 · 输入改为 360° 视频（2026-09-28）

**目标**：`0034_世界模型` 的输入从「md 表里 8 张各自独立生成的多视角图」改成「**一条 360° 环绕视频**」，
经若干节点处理后仍然只产出**一个最高质量的 3DGS PLY**。没有新建工作流（0035/0036 不动），只改 0034
与自有插件 `ComfyUI-FallingTS`（新增 `world-panorama` 两节点 + 扩展 `world-refine`）。

> ⚠️ 根 `scripts\` 临时目录已于 2026-10-11 移除，下文的 `scripts\_out-0034-*` 产物与探针脚本仅作历史记录。

---

## 1. 为什么改：重影的根因不是"图太像"，是"位姿各猜各的"

先量化否掉原假设（`custom_nodes\ComfyUI-FallingTS\dev\_check-0034-8views.py`，8 张进前馈的图，832×480）：

| 指标 | 相邻面实测 | 判读 |
|---|---|---|
| MAE（0~255） | 平均 **24.1**（≈9.4% 满量程） | 差异很大，不是同一张图 |
| 去均值相关 corr | 平均 **+0.094** | 基本不相关 |
| 缩略图最近邻"重复率" | 55.3% | **指标不可信**：量的是"室内场景共性"（大量相似的墙/地板灰度），不是图像重复 |

真凶（读上游源码确认）：WorldMirror 2.0 的**推理路径不做跨视图融合** ——
`rasterization.py:240-242` 在 `is_inference` 直接 `return`，把体素合并（`prune_gs`）与置信度过滤
（`apply_confidence_filter`）全部短路；随后 `position_from="gsdepth+predcamera"`（`:522-528`）让**每个视角
按自己预测的位姿与深度**反投影 ⇒ 同一可见表面被铺两层壳。只修外观（`mode=appearance`）冻结几何去不掉，
所以过去只能靠 `mode=all` + 几何信任域 `reg` 事后把壳"收拢"。

**改版思路**：让所有视角出自同一段画面，并且**位姿由解析解给出**，从源头少一层壳。

## 3. 新增/改动的节点

### 3.1 `WorldSurroundPanorama`（新，`world-panorama`）

视频 → **等距圆柱全景长图**。两种来源：

- `mode=equirect`：真 360 相机导出的 equirect 视频（2:1）**本来就是长图**，抽一帧即可；
- `mode=unfold`（`auto` 在非 2:1 时自动选它）：普通镜头**原地旋转**拍的视频：

1. 均匀抽 ≤`max_frames` 帧，**每帧只算一次 ORB 描述子**，相邻帧互匹配取水平位移中位数；
   ⚠️ 位移必须从**关键点坐标** `k.pt[0]` 算（拿描述子字节当坐标会得到一堆 0..255 的垃圾值，
   闭环解不出焦距 —— 第一版就这么错过）；
2. 偏航角累加 `yaw_i = -Σatan(dx/f)`（内容右移 = 相机左转）；
3. **焦距由「整段正好 360°」闭环约束二分法解出**：纯旋转的转角可加 ⇒ `Σatan(|dx|/f) = 2π`。
   解不出、或解得 h_fov ∉ [20°,170°] 时回退 90° 并在 `report` 里告警"这不是完整一圈"；
4. 按等距圆柱反投影重采样：`u = cx + f·tan(θ-yaw_i)`（只跟列有关）、
   `v = cy + f·tanφ/cos(θ-yaw_i)`（行列外积），**每列只用角距离最近的两帧线性混合**
   —— 第一版用 ±60° 余弦窗口等于把 27 帧平均，糊成一片。

输出 `panorama` / `valid_band`（度，本视频真正能还原的竖向跨度）/ `report`。

**实测**（`media\七纹刻印\0031_首帧场景\00001_书房旋镜视频.mp4`，832×480/24fps/243 帧）：
120 帧全匹配，`f=330.2px → h_fov≈103.1°`，`v_fov≈72.0°`，长图 **2078×1040**，空白列 **0**，耗时 **3.0s**。

### 3.2 `WorldPanoramaViews`（新，`world-panorama`）

全景 → 一网格透视视角 + **每视角精确 w2c 外参 / 内参**（相机全在球心，纯旋转 ⇒ 平移恒 0）。

- 参数口径与上游 `HYWM2SamplePanorama` **逐像素一致**（`yaw=π(2x/(W-1)-1)`、`pitch=π(0.5-y/(H-1))`、
  `f_px=(size/2)/tan(fov/2)`、`cx=cy=(size-1)/2`、外参取 `R.T`）；
- 对拍验收：`custom_nodes\ComfyUI-FallingTS\dev\_verify-panorama-views.py` 与上游单视角采样原语逐像素/逐元素比对，
  **图像/外参/内参最大差 0.000e+00**（5 组 yaw·pitch × 2 组 fov·size）；
- 与上游的差别只有 **`v_range` 竖向范围**：`step=fov·(1-重叠%)`、`num_h=ceil(360/step)`；
  **`v_range ≤ fov` 时只切一行**（旋转视频的 `valid_band` 正好是这个量级），否则 `num_v=ceil(v_range/step)`
  （150/180 时 3 行，供真全景用）；竖向档位以 `v_center` 为中心**对称**摆放（上游是 -75 起推进、略偏）。

**为什么要这条规则**：按 `ceil(v_range/step)` 会切出 2 行、每行一半是黑边 —— 实测 12 视角时前馈 token
预算只够 **406**；改单行 **6** 视角后涨到 **574**，细节明显更多（同一段视频、同一参数下的 A/B）。

### 3.3 `WorldRefinePLY`（改，`world-refine`）

新增 **2 个可选先验输入** `extrinsics`([N,4,4] w2c) / `intrinsics`([3,3] 或 [N,3,3])：

- 节点把 w2c 逐视角取逆落成 `prior_camera.json`（口径同 HYWM2 `_dump_camera_priors_json`：JSON 里是 **c2w**）；
- 脚本带 `--prior-camera` → `pipe._run_inference(prior_cam_path=...)` → 上游
  `load_prior_camera()` → `cond_flags=[cam,0,intr]` 注入 WorldMirror（位姿不再由模型预测）；
- **先验内容也进缓存哈希**（换位姿必然重跑前馈，不会静默复用旧 `preds.pt`）；
- 视图数不再死钉 8：`>= 2` 即可（接全景视角批时是 6/12/21…），无先验且 ≠8 时告警；
- `gt` 跟进（全景路径 = 视角边长 952）。

### 3.4 `custom_nodes\ComfyUI-FallingTS\world-refine\refine_0034_gs.py`（改）

- 新增 `--prior-camera PATH`，把先验传给 `_run_inference`；
- `views_key()` 把**先验内容**一起哈希；
- 新增**先验生效度打点**：与 pipeline 同口径（`P' = inv(P[0]) @ P`，第一台相机为世界原点）比较
  模型预测位姿与注入先验，打印旋转/平移偏差。

## 6. 边界与已知限制（别承诺做不到的）

1. **旋转视频只能还原一条带**：普通镜头 v_fov≈72°（±36°），所以 `valid_band≈72`；
   天/地极区没有数据。真 equirect 视频没这个问题（`valid_band=180`，3 行 × N 列）。
2. 展开质量取决于**帧间位姿估计精度**：本机 0031 视频长图肉眼可读，但局部仍有轻微拖影（H3 视频本身帧间
   内容在漂移）；要更干净得做 per-column 局部对齐。
3. 视频**不是完整一圈**时闭环解会失败并回退 90° + 告警 —— 这是刻意的，不硬凑。
4. **平移拍摄的视频**缝不出干净长图（单应只在纯旋转时成立）。
5. 先验只约束"位姿"，**不自动去重重叠区高斯**；上游 `MergeGaussians` 官方也明确不做 ICP/混合/去重 ——
   重复壳仍要靠 `mode=all` + `reg` 收拢（本改版让它从源头少一层）。
6. `HYWM2SamplePanorama` 与本节点都只处理**单张**全景（批处理未验证）。
7. 验收口径：**必须查 `/history` 的 `status.status_str`**，只看产物文件会误判（这条是上次踩过的坑）。

## 7. 本次踩到并修掉的坑（都已落到代码注释/AGENTS.md）

1. **`_match_dx` 读错量**：位移必须从关键点坐标算，拿 ORB 描述子字节当坐标 → 闭环解不出焦距
   （表现为"该视频凑不满 360°"，长图 2614×1308、空白列 1962）。
2. **`math.arctan` 不存在**（应为 `math.atan`）——`py_compile` 过不代表运行过；且**改完必须重启
   ComfyUI**，进程内已缓存的旧模块不会自动更新（第一次跑就是被这个挡住）。
3. **别用 PowerShell 改写含中文的源码**：`Get-Content -Raw | Set-Content` 会按系统 GBK 解码再以
   UTF-8 写回，把中文注释/字符串全变成乱码并加 BOM。本次因此整个文件重写了一遍 —— 中文文件一律用
   `write`/`edit` 工具。
4. **竖向网格多切一行**：`ceil(v_range/step)` 让 12 视角里一半是黑边，前馈 token 预算被摊薄到 406；
   改成"一行的 FOV 够盖住整条带就只切一行"后 6 视角拿到 574。
5. **`Path` 未定义**：`prior_deviation()` 里用了只在 `dump_ply` 内局部导入的 `Path` → 打点失败
   （不影响重建，但白丢一个关键指标）；改用 `os.path.splitext`。
6. **Tee-Object 写出的日志是 UTF-16LE**：Python 按 UTF-8 读会全部匹配失败（验收脚本曾因此误报 FAIL）；
   改为按 BOM 判定编码。
7. **ComfyUI 节点缓存**：字节相同的 API prompt 会在 5s 内直接返回缓存结果，**PLY mtime 不变**会被
   验收判成 FAIL；正确做法是冷启动或改动输入后再验收（本次用冷启动 + `refresh=true`）。
