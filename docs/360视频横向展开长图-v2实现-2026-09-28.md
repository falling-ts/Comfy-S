## 1. 先把 v1 的三条硬伤测出来（不是猜）

| 缺陷 | 量测方法 | 实测 |
|------|----------|------|
| **长图倒立** | 把视频第 0 帧缩放到长图同角度区（±51.6°）再求相关 | 正放 NCC **0.16** / 上下翻转 NCC **0.52** ⇒ 倒立 |
| **60% 是黑边** | 逐行统计长图非黑像素 | 2074×1038，有内容的只有第 312..725 行 = **39.9%**（上下各 312 行纯黑）；原因：旋转视频只有 ±36° 有数据，却硬输出 2:1 画布 |
| **帧间平均糊掉细节** | 同一块内容与源帧的相关 + 拉普拉斯方差 | v1 NCC **0.55**、锐度 **2.9**；v2 NCC **0.74**、锐度 **12.3** ⇒ **4.3 倍** |

倒立的根因是行映射写反了：v1 用 `v = cy + f·tanφ/cos a`、`φ = π(0.5 - y/(H-1))`，于是长图第 0 行
取到的是源图的**下方**；重影的根因是每列把角距离最近的两帧**线性混合**，位姿/内容只要有 0.5°
及以上误差就会双重曝光。

另外量到一个关键事实：**这段旋镜视频转速不均匀**。位移法独立测出的旋转曲线是
`0:0° 24:8° 48:46° 72:88° 96:122° 120:153° 144:181° 168:217° 192:253° 216:321° 240:360°`
—— 前 24 帧只转 8°，末 24 帧转 39°。任何「按固定帧距切图」或「假设匀速」的做法都会错位。

## 2. v2 算法（`WorldSurroundPanorama`）

顺序执行，全部报告进 `report`：

1. **自动适配转速定抽帧步长**：先用 48 帧粗采样（ORB + 水平位移中位数）估出「每帧画面位移 px」，
   再按 `target_shift_percent`（默认 12% 画面宽）算步长 —— 转得快少抽、转得慢多抽；末帧必采到。
   0031 视频实测 `8.4px/帧` ⇒ 步长 12 ⇒ 抽 21 帧（而不是无脑抽 120 帧）。
1b. **自适应补密（2026-09-28 追加，专治不均匀转速）**：单一全局步长追不上"静止段 + 甩镜段"——
   长静止段会把每帧位移的**中位数**拉到 0 ⇒ 步长爆掉；甩镜段每帧位移又远超目标。做法：反复找出
   **几何模型解不出**（匹配不足 / RANSAC 失败）或**位移超上限**（3× 目标）的相邻采样对，一次给所有
   这样的对插中间帧，直到全部回到上限内（或撞 `max_frames` / 帧间隔已到 1）；随后对静止段保守抽稀
   （只丢与上一保留帧位移 <0.5px 的帧、且至少留 8 帧）。判据的取舍见 §8。
2. **一圈闭环检测**：首末采样帧**确实重合**才判定「整整转了一圈」并把总转角**吸附成 360°**，
   重合判据 = 匹配数 ≥40 **且** 单应内点比例 ≥0.3 **且** 内点中位位移 <0.35×典型帧间位移
   **且** 在解出的 f 下对应点转角 <5°（只用位移中位数会被误匹配骗过，见 §8）。实测 0031 逐帧位移
   累加只有 311°（−14% 系统偏差），吸附后与独立位移曲线在整圈 9 个位置都对上（≤5°）。
3. **位姿**：相邻帧 ORB 匹配 → `findHomography` + RANSAC 拟合纯偏航单应，位移取**画面中心**的
   亚像素值（不再是关键点中位数的整数像素）。吸附后重合一圈的尾帧会被剔除，否则两帧得分相同会在
   换帧处来回翻转（接缝从 20 处暴涨到 100+ 处）。
4. **焦距（四种估计联立 + 交叉校验）**：
   - `_f_from_correspondences`：纯旋转下同一对应点的 `atan((u1-cx)/f) - atan((u2-cx)/f)` 必须等于
     两帧转角 Δ，代价取 **Δ 的相对鲁棒离散度 + 竖直残差**（必须无量纲，否则 `ΣΔ→0`（f→∞）
     会让它单调下降、退化成「f 越大越好」—— 踩过）；转角信号 <1° 时直接交回上层（近静止时
     这个比值是噪声）；
   - `_f_from_overlap`：**相邻帧重叠区的稠密光度一致性**（两帧按 `u=cx+f·tan a` 采到同一组世界
     方向上逐像素比结构差），这是最硬、也最不受平移污染的判据（默认采用）；**一对有效重叠都没有
     时必须判为"无解"而不是"完美"**（原实现 `cnt=0 ⇒ cost=0/max(0,1)=0` 会让搜索落到区间下界、
     把 h_fov 假解成 143.2°，见 §8）；
   - 360° 闭环 `Σatan(|dx|/f)=2π`、单对单应闭式解 `f²=-H02/H20-cx²` 只作交叉校验 —— 实测
     单对单应受平移污染会高估 22%（380.1px vs 311.8px）。
   0031 视频结果：**f=311.8px → h_fov≈106.3°**（闭环 290.7 / 对应点 295.8 / 单对 380.1）。
5. **逐像素 winner-take-all**：每个输出像素只取光学轴夹角最小的那一帧的值，**从不做帧间平均**
   ⇒ 结构上不可能有重影。帧间亮度差用「相邻帧曝光链」（按匹配点局部中值拟合 `b≈s·a+t` 再链式
   累积；链式偏差不在 2%~12% 区间就自动关闭，免得把噪声当曝光漂移）。
6. **接缝只羽化低频**：换帧处把两帧的高斯低频做过渡、高频仍来自唯一那一帧（`seam_feather` 默认
   7px）⇒ 看不到亮度台阶，也不会出现第二条边。
7. **自动裁黑边**：没被完全覆盖的行自动裁掉（覆盖率的阈值 99.5%），于是输出**紧贴有效带的横条**
   `H = W·band/2π`；真 360 素材 band=180° 时自动退化成标准 2:1 等距圆柱。
8. **竖直朝向 = 世界地图口径**：第 0 行 = 仰角 `+band/2`（上=天、下=地）；`WorldPanoramaViews`
   同步改成同一套反变换（`elev=asin(-ry)`、`eq_y=(elev_top-elev)/v_range·(H-1)`，并按 8% 容差
   判断「一条带只需切一行」）。
9. **分辨率吃满源素材**：默认 `supersample=1.5` ⇒ 8.16px/度（v1 只有 5.76；源帧中心
   `f=311.8px/rad` ≈ 5.44px/度、边缘更高）。

输出：`panorama` / `valid_band`(度) / `v_center`(度) / `report`。

## 6. 边界与已知限制（别承诺做不到的）

1. **旋转视频只还原一条带**：普通镜头 v_fov≈72.6°，天/地极区没有数据；真 equirect 视频没这个问题
   （band=180°，竖向 3 行）。
2. **平移拍摄的视频**：纯偏航模型只在原地旋转时成立；有平移时焦距/位姿会被污染（这正是单对单应
   高估 22% 的原因），v2 用稠密光度一致性把影响压到最小，但平移大的素材仍会出接缝错位。
3. **长图内部的接缝**是「唯一帧」的硬切换 + 7px 低频羽化：内容是帧间真实差异时（H3 漂移），
   接缝处可能有轻微结构不连续；这是**刻意**的选择 —— 宁可一条缝，也不要重影。
4. **曝光匹配默认可能关闭**（链式偏差不在 2%~12% 时），此时帧间亮度差靠接缝羽化吸收。
5. 前馈分辨率仍受 8GB 显存限制（`_auto_target_size` 实测 574）；视角边长 952 已经比长图的
   8.16px/度更密，再加大只是插值，不会凭空多出细节。
6. 训练视角 PSNR 不能跨「不同锐度的输入」比较（见 §4 的警示）。
7. **转速适配范围（含不均匀转速）与四个已修的静默缺陷见 §8**：现在"近静止 / 完全静止"素材会**明确
   报错**而不是出一张假图；不闭环的部分弧**不做吸附**、report 里明说缺方位。

## 7. 0034 的布局修正（2026-09-28 追加）

**问题**：画布上节点互相压住。根因不是坐标算错，而是**声明尺寸（`size`）小于真实渲染尺寸** ——
ComfyUI 前端载入时会按内容把节点撑大，存盘的 `size` 只是提示。实测本工作流里
`PreviewImageSave` 声明 300×300，而同仓其它工作流里它的真实尺寸是 510×540 ~ 760×690，
于是它顺着同列往下长，直接盖住下面的 `WorldPanoramaViews`。

**修法**：
1. 每类节点的声明尺寸改成「真实下界」的上界，行数口径来自 `/object_info`（2026-09-28）：
   `WorldSurroundPanorama` 10 输入/4 输出、`WorldPanoramaViews` 6/5、`WorldRefinePLY` 12/1、
   `FallingTSMarkDownTable` 1/**42**（所以它真实高度约 1010 且随内容继续长）、
   `PreviewImageSave` 6/1（另有图像预览区，实测 510×540~760×690）、视口 3290×2130（前端实测）。
2. 布局改成：说明(0,40 340×980) | 表(420,40 480×1010) | 全景(980,40 360×340) |
   预览(1420,40 620×600)／视角(1420,700 400×280) | 精修(1910,700 420×400) |
   视口(2410,700 3290×2130)；净间距 80/80/90/80/60 px 全在 (50,100) 内。
3. **说明节点压缩**：文本 3086 字 → **700 字**（只留输入来源、链路一行、必接端口、四个坑 + 文档指针），
   框 340×3200 → **340×980**；详细内容全部留在本文档。
4. 生成脚本 `custom_nodes\ComfyUI-FallingTS\dev\_build-0034-world360.py` 的自检加了 **全局两两不重叠** 与
   **声明尺寸 ≥ 真实下界** 两条；另有一份**独立**校验脚本 `custom_nodes\ComfyUI-FallingTS\dev\_check-0034-layout.py`
   （不共用生成脚本的代码），它同时输出布局示意图 `scripts\_out-pano\0034-layout.png`：

```

```

5. 说明节点是纯前端节点、不参与执行：改完后重出的 API prompt 与改前 **sha256 完全相同**
   （`D7B1801C…`），所以这次改版**不需要重跑重建**，上一个 PASS 的验收结论仍然有效。

## 8. 转速适配谱系 + 四个静默缺陷（2026-09-28 追加）

**问题**：这套展开能吃**任意转速、含不平滑转速**的 360° 视频吗？

**做法**：`custom_nodes\ComfyUI-FallingTS\dev\_verify-unfold-rate.py` —— 用已知真值 GT 按**给定的逐帧转角曲线**渲染针孔帧序列，
交给节点展开，再与 GT 比。17 个用例，同一把尺子跑 before/after（before = 修复前代码的冻结副本）。

**指标先说清楚两个坑**：
1. **全局 NCC 会把「整体滚动偏移」和「局部漂移」混在一起**：长图的 yaw 原点本就任意，整幅滚几度
   无害。改用 **FFT 全列滚动**取真正最优对齐得 `NCC正放`，再用**分块局部对齐**得 `漂移`（各块最优
   列移的极差）—— 漂移才是"有没有漏方位/错位"。
2. **窄弧段的结构 NCC 天然低**：长图把远场（|a|→62°）抻长 4~5 倍，而源帧在离轴处的角分辨率本就低，
   长图远场必然比参考图糊。这类用例判 **漂移 + 内容列占比**（误判成"整圈"会把 200° 拉成 360°，
   内容占比冲到 ~100% 且漂移几十度，这条能抓住）。

### 8.2 四个修掉的静默缺陷（都拿实测数字定的）

1. **闭环吸附被误匹配骗过（最严重：静默把 200° 拉成 360°）**
   原判据只比首末帧的水平位移中位数。低纹理素材上相隔 200° 的首末帧只剩十几个随机匹配，其中位数
   可能**恰好很小** ⇒ 判定"整整一圈" ⇒ 200° 弧被强行缩放成 360°，长图整幅错位（内容列 100%、
   漂移 **31.8°**）且**一声不响**。改成几何一致性四连：匹配 ≥40、单应内点比例 ≥0.3、内点中位位移
   <0.35×典型帧间位移、在解出的 f 下对应点转角 <5°。
2. **吸附窗口过松（尺度错 2.15%）**
   原判据是 `closed or |span−2π|<10°`：48 帧素材的采样弧 352.4° 落在 10° 内被强行拉成 360° ⇒
   全局尺度错 2.15% ⇒ 长图中段漂移 **3.1°**、NCC 0.572（24 帧素材误差只有 0.3%，所以一直没暴露）。
   现在**只有首末帧确实重合才吸附**；并且**末帧一定采到** —— 原来 `total−1−idxs[-1] > stride//2`
   会把只有 1 帧远的尾巴丢掉，正好丢掉那 7.7°。
3. **近乎静止时的假焦距（143.2°）**
   `_f_from_overlap` 里"一对可用重叠都没有"时 `cnt=0 ⇒ cost=0/1=0`，每个候选 f 都成了"完美"⇒
   搜索落到区间下界，h_fov 假解成 **143.2°**；`_f_from_correspondences` 同理会把噪声比值当信号。
   现在两者在"无有效对 / 转角信号 <1°"时明确交回上层；另外整段画面累计横向位移 <6% 画面宽时
   **直接报错**「这不是环绕/旋转镜头」（近静止 2° 和完全静止都变成明确报错，不再出垃圾图）。
4. **单一全局步长追不上不均匀转速**
   见 §2 的 1b（自适应补密 + 保守抽稀）。实测：阶跃 +8 帧/−10 帧、中段突发 +6 帧后空白 79°→0%。

**补密触发判据踩的两个坑（留给以后）**：
- 只用 `_match_dx` 的位移中位数 ⇒ 88° 的错配对也会给出 13.7px 的"正常"值 ⇒ 补密永不触发，
  甩镜段整段几何失真（漂移 21.4°）；
- 改成"单应内点比例 <0.40" ⇒ **真实素材被误伤**：0031 视频有 8 对比例只有 0.24~0.37，但几何
  完全解得出（帧间内容漂移 + 运动模糊所致），平白补 11 帧把 f 从 311.8px 带到 332.4px、
  与源帧 NCC 0.74→0.51。**内点比例依赖内容漂移，不能当补密判据**；
- 最终判据 =「几何模型解不出 / 位移超上限」：在 0031 上补密 **0 帧**（与修复前行为一致），
  在合成突发段上**精确命中**那两对 RANSAC 失败的帧。

### 8.4 结论：适配范围（一句话版）

- **抽帧速率是"按画面位移"自适应的**（目标 = 相邻采样帧位移 12% 画面宽）⇒ fps、分辨率、镜头 FOV
  变化都不用改参数；**匀速 0.75°/帧 ~ 45°/帧 全部 PASS**，60°/帧 起（6 帧转一圈，帧间重叠不足）
  明确报错。
- **不平滑转速可用**：两段式 3°→9°、五倍落差、静止 30 帧后猛转 30°/帧、中段 4 帧 40° 突发——全部
  PASS（靠 1b 自适应补密；补密不能解决的"原生帧率不足"会在 report 里写
  `⚠ N 处帧间隔内位移仍超目标`）。
- **边界**：整段累计横向位移 <6% 画面宽 ⇒ 直接报错；不闭环的部分弧能正常展开，但长图**会缺方位**
  （report 明说「整段只转了 X° < 360°」且**不做吸附**）。
- **仍不适配**：平移/变焦镜头（纯偏航模型的前提；粗采样匹配失败过半会报错让你改 equirect）；
  真实**低纹理**素材的 ORB 匹配会比合成更脆（本轮只做了无噪声合成验证，没有真机低纹理素材）。
- 真 equirect（2:1）素材走直通，不参与上面这套判定。
