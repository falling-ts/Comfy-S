## 0. 先把问题拆对：三种"参考图"在管线里的位置完全不同

原问题把三个选项并列，但它们在管线里根本不是同一个东西：

| 用法 | 图在管线里的角色 | 图被"看见"的方式 | 出错表现 |
| :--- | :--- | :--- | :--- |
| **I2V（首帧）** | 就是画面第 0 帧 | 像素级：构图、姿态、光线、背景、版式全部继承 | 拼版被整张画进画面；动作被首帧姿态锁死 |
| **Ref2V（身份锚点）** | 身份 / 造型 / 场景的条件源 | 语义级：抽特征，不复制构图 | 身份漂移；多图互相冲突；多主体串脸 |
| **设定图本身（character sheet）** | 中间资产，不直接进视频 | 由人挑图后，再按上面两种之一投喂 | 它好不好，取决于下一步怎么用 |

**这是本次调研最关键的一条结论**：问题里的 ①②③ 描述的是"设定图长什么样"，但正确答案取决于"这张设定图接下来怎么用"。同一张三视图，当 Ref2V 锚点可能有用，当 I2V 首帧则几乎必然出错。

## 1. 结论摘要

### 1.1 I2V（一张图当首帧）

1. **首帧必须是单张、单一视角、构图与该镜一致的图。** 三视图 / 拼版 / 九宫格当首帧是**用法错误**，不是风格偏好。
   - 依据：Seedance 官方把"首尾帧"与"参考图"设为**互斥任务类型**；中文技能包据此写明"严禁直接把参考图当作首帧"（§2.E-4、§2.B-7）。
   - 依据：本机实测到 **reference leakage** —— 只要提示词里描述了参考图的版式（"一张 2×2 拼合的图片""每格左上角印有方位标注"），模型就把**分格线与标注文字直接画进画面**（§2.D-6）。
2. **用全身还是半身 / 特写，取决于该镜要演什么动作**，不是"哪个更像本人"。特写首帧装不下全身动作（§2.C-5）。
3. 脸部特写对五官一致性的作用在 I2V 里是**间接**的：更适合当 Ref2V 的身份补充，或用来单独修首帧的脸，而不是当首帧本身（§2.C-1、§2.C-4）。

### 1.2 Ref2V（参考图当身份锚点）

1. **中文教程层面**主流推荐"多张、多角度"：三视图、4 View 资产板、"正面/侧面/全身/半身各一张"、7 格 turnaround。这是**规范做法**层面的共识，**多数没有量化依据**（§2.A）。
2. **但有实测数据的来源一致指向"不要用拼成一张的 character sheet，要用分开的多张单视角图"**：
   - 主因一：拼版每格分辨率被压到约 1/3（一张 3×3 网格每格约 680px，而单张专用图是 2048px）；
   - 主因二：拼版的版式结构（分格、边框、重复人物、无缝背景）本身是"可见内容"，会与目标场景竞争。
   - 本机实测补充：一张"大特写 + 三视图"的建模图里，大特写脸是 315×441px，而三视图格里的脸只有 **54×70px / 48×63px**（§2.B-1、§2.B-2）。
3. **参考图数量上有明确分歧**：教程派说"越多角度越好（3~7 张）"，实测派说"**1~2 张最好，3 张以上急剧衰减**"（§2.D、§3）。
4. **多主体混在同一张参考图里会串脸** —— 这条有实测（§2.B-4）。
5. **特写（脸部大特写）在 Ref2V 里的价值有间接实测支持**：它是"语言层之外唯一能加身份"的手段之一（§2.C-1）。

### 1.3 对原问题三选项的直接判定

| 选项 | I2V（首帧） | Ref2V（身份锚点） |
| :--- | :--- | :--- |
| **① 单张纯全身立绘** | **对**。需满足：单一视角 + 构图匹配该镜 + 景别够用 | 可用，是最低配置；多数实测派认为"1~2 张分开的单视角图"最优 |
| **② 特写 + 三视图（拼成一张）** | **错**（拼版会被当画面内容） | **实测反对**（分辨率损失 + 版式泄漏）。"三视图"这个概念本身可以，但**必须拆成分开的多张** |
| **③ 更详细的多张特写 + 三视图** | 仍错（I2V 只吃一张首帧） | **方向正确**，是多数来源的实际推荐形态；数量建议 **2~4 张**，不要堆到 7 张以上 |

**一句话**：三视图的争议不在"要不要多角度"，而在"要不要拼成一张"。**实测证据支持多角度，反对拼版。**

## 3. 争议点

### 3.1 「三视图」这个词在两派里指的不是同一个东西（最大的假冲突）

- **支持派**（uisdc Vidu Q1、zjcp、manju-laoli 4 View、ai-cinematic-pipeline 7 格、seedance2.0-prompt-skill 四张）说的是"**多角度、多张图**"，很多其实是**分开上传的多张**。
- **反对派**（minimax-h3-skill、OnlyShot、本机）反对的是"**把多个视角拼成一张图**"（character sheet / grid / 4-grid）。
- 两者并不真冲突。**真正的一致结论是：要多角度，但不要拼版。**

### 3.2 参考图数量：1~2 张 vs 4~7 张

- 主张多：Vidu 官方接口支持 1~7 张；HappyHorse 攻略说"一个角色五到六张"（存疑）；aliyun 角色设计给 12 项资产；manju-laoli 的 4 View；lanshu 的 3×3 网格。
- 主张少：OnlyShot（1→95% / 2→80% / 3+→<50%，36 grid 实测）；pconline（"通常一张就够了"）；tudingai（3 张 > 5 张）；seedance.tv / Pippit（"两张互补胜过许多相似"）。
- **可能的分界**：OnlyShot 自己澄清了这一点——"ref 5-8 最优"**只对 multimodal2video（多帧合成）适用**，而"分镜图 / image2video 都是 1-2 ref 上限"。也就是说**数量上限取决于任务类型，不是模型能力**。

### 3.3 特写 vs 全身

- 主张特写（脸部占比大）：C-1（本机实测点名"加一张脸部大特写参考图"）、C-2（"裁成 1:1 让脸占满核心区域"）、C-3（MiniMax 官方"需要可识别的面部信息"）、Pippit（"三分之四视角比严格正面携带更多面部与身体信息"）。
- 主张全身：A-12（腾讯云："**必须是全身图**"，否则下半身服饰推断错误、武器缺失、鞋子无法还原、披风长度变化）；本机工作区规范（人物取"**正面全身立绘**，从头到脚完整入画"）。
- **可能的分界**：**当 Ref2V 身份锚点 → 脸部信息密度优先（特写/半身有用）；当 I2V 首帧 → 必须与该镜景别匹配（全身动作必须全身首帧）**。两者不矛盾，是用途不同。

### 3.4 「三视图会不会被模型当成三个人」

- **没有找到任何中文一手实测直接证实**"三视图参考 → 画面里出现多个人/分屏"。
- 找到的相邻证据只有三条，且都不是同一件事：
  1. 多主体（两个角色）混在一张参考图 → "奇怪的混搭"（uisdc Vidu Q1 实测）；
  2. 3 张以上 ref → 一致性 <50%（OnlyShot 实测）；
  3. 提示词描述参考图版式 → 分格线与文字被画进画面（本机 reference leakage 实测）。
- 因此这条目前只能作为**合理推断**（拼版结构是可见内容 → 可能被渲染），不能作为"已被实测证实"的结论。

## 附：一句话总结（可直接引用）

> 中文互联网上，**教程派**（阿里云角色设计 12 项资产、塔猴三视图公式、即梦三视图白底教程、4 View 资产板）普遍推荐"多角度 + 三视图"；**实测派**（MiniMax H3 技能包的负面报告、OnlyShot 的 36 grid 生产日志、本机受控标定）一致指出**问题出在"拼成一张"而不是"多角度"**——拼版会把每格分辨率压到约 1/3，并且拼版自身的分格线与标注会被模型画进画面。因此 Ref2V 的正确形态是"**2~4 张分开的全分辨率单视角图**"，不是"一张三视图"；而 I2V 首帧只能用**单张、单一视角、构图与该镜匹配**的图，三视图当首帧是用法错误。
