## 职责边界（重要，违反即整轮失败）

**只改 md 数据，不跑工作流，不改工作流。** 本会话 agent 的职责仅限于读写 `stories\` 下的资源表与正文等 **md 数据文件**：

- **不运行工作流**：工作流的实际运行（ComfyUI 提交、采样、出图/出视频/出音频）一律由**用户自己**去跑，agent 当前不需要、也不得代为执行工作流；不要把改完 md 后的「跑一次验证」当成自己的任务。
- **不改工作流文件**：仅修改 md 里的提示词/参数等数据时，**不要去改 `workflows\` 下的工作流 JSON**（包括其中的数据表选中行、节点参数、快照等）——用户会自己在 ComfyUI 里**选择数据并点「刷新」加载**最新 md 内容。
- **只有用户明确要求调整工作流时**，才允许改工作流；否则一律只动 md。

## 提示相关

`prompt.md` 是**辅助提示词文件**，位于**故事库目录**内（如 `stories\七纹刻印\prompt.md`，模板是 `stories\template\prompt.md`）：当需要撰写复杂提示内容（如场景/视频/图像/音频提示词）时，先 `read` 读取它，按其中的文件编号定位到对应资源表；不需要写复杂提示时无需加载。

## 提示词句式规则（强制）

**所有提示词必须全部使用肯定句式，严禁使用否定句式。**

适用于**全部资源表**的**全部提示词字段**（图片、视频、音频一律包含），不区分字段、不区分模型：

- **严禁**出现「不 / 没 / 无 / 别 / 非 / 未 / 禁止 / 切勿 / 避免 / 不得 / 不会 / 不要」等否定表述，也不得用「没有、不再、不变、不动、无字、无衬线」这类含否定字的词组。
- **必须**改为**反向意思的肯定陈述**：只正面描述画面里**有**什么、**是**什么、**呈现**什么、**保持**什么。
- 改写要**语义等价**、不是删句：先明确原句要锁定的效果，再用肯定式说清同一效果。

改法示例：

| 否定句式（禁用） | 肯定句式（正确） |
|------------------|------------------|
| 画面里没有开灯 | 整间房浸在昏暗夜色中，光源锁定为窗缝霓虹与窗外月光这两处 |
| 不出现任何文字 | 画面中的文字只有 Shot 1 与 Shot 4 这两处字幕卡 |
| 不转头、不伸手 | 头、颈、肩保持静卧姿态，双臂收在被内 |
| 机位不动、不得移位 | 机位全程固定，稳定锁定在开场那一帧 |
| 看不到他的脸 | 他的脸藏在被面之下与枕头的暗影里，画面呈现的是完整的隆起被面 |
| 不得并排出现多个视角 | 画面中始终只有一个完整的他、一个身影 |
| 没有台词、没有人声、没有音乐 | 声轨里只有环境声与呼吸声，台词与人声、配乐留给之后的正片段落 |

**唯一例外**：`non_diegetic_music` 一栏的固定值 `N/A`（协议保留字，不属提示词正文）。除此之外，写完提示词必须逐字自查一遍否定字是否清零。

## 资源 ID 规则

ID 为「编号_简短名」两段：编号是 **5 位十进制**，**每个资源表文件各自独立编号、一律从 `00001` 起连续递增**（编号只在**本文件内**唯一，不跨文件连号；最高暂定 99999），后接下划线 `_` 与一个简短中文名。例：`0011_万物建模.md` 内为 `00001_陈落`、`00002_电子钟`；`0020_场景首帧.md` 内为 `00001_书房`、`00002_卧室`——不同文件出现同号互不影响。

**每个文件的第一条永远是 `00001_`**；新增条目取**本文件当前最大编号 +1**，不参考其它文件的编号。

**中间插入**：在编号末尾追加一位数字，由 5 位升为 6 位（`0000x` → `0000xx`）。例：在本文件的 `00001` 与 `00002` 之间插入得 `000011`、`000012`，逐字排序仍恰好落在两者之间，不破坏既有顺序。

**引用格式**：IMAGE, VIDEO, AUDIO 类型的数据必须通过 **@{工作流文件名/ID}** 的形式进行数据记录，其中「工作流文件名」为该资源表 md 的文件名去掉 `.md`（文件名即编号空间，故不同文件的同号 ID 不冲突）。例：`@{0011_万物建模/00001_陈落}`、`@{0020_场景首帧/00001_书房}`、`@{0021_场景拉镜/00001_书房}`。

> **⚠️ 别和文件名编号搞混**：本节这套编号是**表内行 ID**（数据行第一列）。资源表**文件名**（`0011_万物建模.md`）与**工作流文件名**（`00110_万物建模_QI2.1`）走另一套编号，**不随本节规则改动**；`@{...}` 里的斜杠前那段永远是**表文件名（= 产物目录名）**，斜杠后那段才是本节的 5 位行 ID。

## 世界模型资源表（0034）· 写入要点

`0034_世界模型.md` 是「**一条 360° 环绕视频 → 一个最高质量 3DGS PLY**」的入口表：两列 `场景描述(TEXT)` + `360环绕视频(VIDEO)`，**每行 = 一个可重建的封闭场景**（房间、院子、车厢这类边界清楚的紧凑空间）。工作流 `0034_世界模型`：md 表 → `WorldSurroundPanorama`（视频 → 等距圆柱长图）→ `WorldPanoramaViews`（长图 → 带精确位姿的视角批）→ `WorldRefinePLY`（504 前馈 + 3DGS 全参数精修）→ PLY 视口；产物 `media\<项目>\0034_世界模型\0034_世界模型_世界3DGS.ply`。**写入时机：需要我明确说明时才写**，分析正文时不自动写入。

| # | 硬性要求 | 为什么 |
|---|----------|--------|
| 1 | `360环绕视频` 列一律引用 `0031_首帧场景` 里那条**旋镜视频**：写作 `@{0031_首帧场景/<该行ID>}`（例：`@{0031_首帧场景/00001_书房旋镜}`），不另拍、不另生成第二条 | 0034 是 0031 的**下游复用**：同一段视频既当 360° 环绕镜头，又是世界重建的输入 |
| 2 | 引用前先抽帧核对这段视频确实是「**单次连续拍摄、视线保持水平、顺时针、完整一整圈、时长 ≥9 秒**」；有翻滚、猛冲、明显回不到起点的，先回 0031 改提示词重生成再来建 | 展开算法靠「整圈闭环」把总转角吸附成 360°；不合格的视频要么展开失败、要么重建出倾斜世界 |
| 3 | `场景描述(TEXT)` 写**整间房**：四面墙（前/右/后/左）各自的门窗、墙面、墙角、踢脚线，加地面、天花，以及每件家具**贴在哪面墙的哪一段、朝向如何**，全部交代；**不能只写单面视角** | 重建要把它拼成一个**闭合世界**，只写一面就会得到半间空房 |
| 4 | `场景描述` 末尾**必须写明拍摄口径**：以场景中央为圆心、视线保持水平不俯仰、**顺时针**转满一整圈、**单次连续拍摄**（无剪辑、无多段拼接、无多张图） | 展开算法据此判定「整整一圈」并吸附 360°；缺这句就没有闭环依据 |
| 5 | 时长与转速：一圈 **≥9 秒**（H3 侧完整 360° 要 220+ 帧，>40°/s 必翻滚）；**匀速最佳，允许变速**（工作流按画面位移自适应抽帧并补密），但**不许长时间完全静止的停顿**（整段累计横向位移 <6% 画面宽会直接报错），也不许 4~6 帧就转完一圈（>60°/帧 报错） | 展开算法实测包线：匀速 **0.75°~45°/帧** 稳定可用、60°/帧 起报错；24fps 下 H3 的 40°/s 上限 ≈1.7°/帧，远在包线内 —— 转速真正卡在 H3 侧，不是展开侧 |
| 6 | 画面**要有纹理**：每面墙都留实体锚点（门、柜、书架、绿植、挂钟等），避免纯色墙 + 空房间 | 低纹理素材特征匹配不稳、展开不准；沿用技能 `stories` 的「每块空白墙面 1 件简单家具」定稿口径 |

**一行一个场景**：换房间、改布局就等于换一行，不要在一个 ID 里塞两个场景的长描述。各面墙锚点写法、件数克制、正面清点句见技能 `stories` 的「世界模型（0034）」；展开算法的能力边界与实测数据见 `docs\360视频横向展开长图-v2实现-2026-09-28.md`。
